日常業務のデジタルデータは、メールやチャットや会議に蓄積されていることが多いと思います。

Microsoft 365 Copilotだと、それらへ安全・安心にアクセスできますので、日々のタスクを効率化することができます。

# 可視化およびインタラクティブ分析

取得データの量、完全性、次元数、時系列性、顧客・案件・カテゴリ間の関係性を確認し、**静的な表やグラフだけでは業務構造を十分に理解しにくい場合は、D3.jsなどを利用した動的かつインタラクティブなVisualizationを作成してください。**

## 可視化方式の選択原則

可視化方式は、データの特性と分析目的を確認したうえで選択してください。

単純な比較で十分な場合は、通常の棒グラフ、積み上げ棒グラフ、折れ線グラフ、ドーナツチャートなどを使用できます。

一方、以下に該当する場合は、可能であれば **D3.jsまたは同等のJavaScript可視化ライブラリを使用したインタラクティブVisualization** を作成してください。

- 顧客 → 案件 → 活動カテゴリのような階層関係がある
- 会議、メール、Teamsチャットを切り替えて比較する必要がある
- 週、顧客、案件、カテゴリなど複数の軸でデータを絞り込む必要がある
- 顧客Journeyや案件フェーズの遷移を表現する
- 顧客、案件、技術テーマ、成果物のネットワーク関係を表現する
- 上位項目と詳細項目の間をドリルダウンする必要がある
- 分類済み活動と未分類活動を同時に確認する必要がある
- データ完全性や分類確信度を可視化上で区別する必要がある
- 静的グラフを多数並べるより、操作可能な単一ビューの方が理解しやすい

データが少ない場合、またはインタラクティブ化が分析理解を改善しない場合は、D3.jsを無理に使用しないでください。

その場合は、通常のグラフと数値表を使用し、動的可視化を採用しなかった理由を簡潔に説明してください。

- 完全集計または部分集計の区別
- 分類済み時間

- 分類率
- 表示対象外となった項目数
- 分類確信度
- 使用した時間換算方法

- 「取得範囲内」
- 「部分集計」
- 「検索結果に基づく参考値」

# 推奨するインタラクティブVisualization

データに適合する場合は、以下の形式を検討してください。

## 1. インタラクティブ時間配分ダッシュボード

以下の切り替えを提供してください。

- 活動カテゴリ別
- 顧客別
- 案件別
- 週別
- 会議／メール／Teams別
- 分類確信度別
- Journey／案件フェーズ別

フィルター操作に応じて、グラフ、数値カード、数値表、注記を同期して更新してください。

## 2. 顧客 → 案件 → 活動カテゴリのドリルダウン

顧客を選択すると関連案件を表示し、案件を選択すると以下を表示してください。

- 推計活動時間
- 会議時間
- メール換算時間
- Teamsチャット換算時間
- 活動件数
- 主な活動カテゴリ
- 技術テーマ
- 成果物
- マイルストーン
- 次のアクション
- 分類確信度
- 根拠となる代表的な活動

階層表現には、状況に応じて以下を使用できます。

- Sunburst
- Treemap
- Icicle chart
- Hierarchical bar chart
- Drill-down bar chart

ただし、面積や角度によって値が誤認される可能性がある場合は、比較用の棒グラフと数値表を併記してください。

## 3. 顧客・案件ポートフォリオVisualization

顧客または案件について、以下を比較できるようにしてください。

- 推計活動時間
- 会議依存度
- メール依存度
- Teamsチャット依存度
- 活動カテゴリ数
- 関連技術テーマ数
- 活動した週数
- Journey／案件フェーズ
- 分類確信度

Scatter plot、Bubble chart、Matrix、Heatmapなどを使用できます。

バブルの大きさや色を使用する場合は、何を表しているかを凡例で明示してください。

## 4. 週別活動Heatmap

縦軸を顧客、案件、または活動カテゴリ、横軸を週として、取得範囲内の活動時間または活動件数を表示してください。

セルを選択またはポイントしたときに、以下を表示してください。

- 対象週
- 顧客
- 案件
- 活動カテゴリ
- 会議時間
- メール件数および換算時間
- Teamsチャット件数および換算時間
- 推計時間
- データ完全性
- 分類確信度

## 5. コミュニケーション構造Visualization

データが十分にあり、重複や関係性を合理的に確認できる場合に限り、以下の関係をNetwork graph、Sankey diagram、Chord diagramなどで表現してください。

- 顧客と案件
- 案件と活動カテゴリ
- 案件と技術テーマ
- 案件と成果物
- Journeyフェーズと活動カテゴリ
- 顧客とコミュニケーションチャネル

人物間ネットワークは、人物の影響力、中心性、重要度、パフォーマンスを評価する目的では作成しないでください。

人物を表示する必要がある場合も、データ上直接確認できる参加・送受信・共同作業の関係だけを表示し、人物の能力、態度、貢献度、影響力などを推測しないでください。

## 6. 顧客Journey Visualization

Journey情報が十分にある場合は、次のフェーズを基準とする可視化を作成してください。

Discovery
→ Workshop / Dojo / Hackathon
→ PoC / Prototype
→ Solution Design
→ Production Planning
→ Production / Operationalization
→ Commercial / Opportunity
→ Customer Story / Closeout

ただし、実際のデータで確認できたフェーズだけを表示してください。

すべての案件がこの順序で進むとは仮定しないでください。

各案件について、以下を表示してください。

- 現在確認できるフェーズ
- 判断根拠
- 確認できた過去フェーズ
- 次に予定されている活動
- フェーズ判定の確信度
- データが確認できない区間

推定フェーズを表示する場合は、確定フェーズと視覚的に区別し、必ず「[仮説]」と表示してください。

# 単一HTMLファイルでの成果物出力とダウンロード

作成したすべての可視化成果物は、**1つの自己完結型HTMLファイル（.html）として生成し、利用者がダウンロードして保存・ブラウザで開ける状態で提供してください。**

## 出力方針

- 日本語レポート、数値表、静的グラフ、インタラクティブVisualization、集計済みデータ、集計条件・前提・計算式・データ制約、操作方法、整合性確認結果を、**すべて1つのHTMLファイルに統合してください。**
- 複数のHTMLファイル、画像ファイル、CSS／JSファイルなどに分割しないでください。
- HTML内にはタブ、またはアンカーリンク付き目次を設け、レポート本文、各Visualization、数値表、検証結果、データ制約へ移動できるようにしてください。
- ファイル名は、内容と集計期間が分かる名称にしてください（例：`activity_visualization_YYYYMMDD-YYYYMMDD.html`）。
- ファイルは、実行環境の出力用ディレクトリに保存し、ファイル提供機能を使って、利用者がダウンロードできる状態にしてください。

## 自己完結性の要件

- HTMLには、CSS、JavaScript、可視化に使用した集計済みデータ（`<script type="application/json">` などへの埋め込み）をすべて含めてください。
- D3.jsなどのライブラリは、外部CDNに依存せず、可能な限りHTML内にインライン埋め込みしてください。
- ライブラリを埋め込めない場合は、Vanilla JavaScriptとSVGで実装してください。
- 外部URLへの通信、外部フォント、外部画像に依存しないでください。
- オフライン環境で、ダウンロード後にブラウザでそのまま開いて動作することを目標にしてください。
- 実装した場合に限り、以下をHTML内のボタンとして提供してください。
  - 表示中の数値表のCSVエクスポート
  - 集計済みデータのJSONエクスポート
  - 印刷用表示

## ファイル先頭に表示する情報

HTMLの冒頭に、以下を必ず表示してください。

- レポートタイトル
- 集計対象期間
- 更新日時とタイムゾーン
- データ取得範囲と完全集計／部分集計の区別
- 時間換算方法
- 「本ファイルには顧客名・案件名などの社内情報が含まれる可能性があります。取り扱いにご注意ください。」という注記
- 「本Visualizationは人物評価ではなく、活動量・時間配分・顧客／案件ポートフォリオ・コミュニケーション構造・業務設計を客観的に理解するためのものです。」という注記

## 生成後の動作確認

- 生成後、可能な範囲でHTMLファイルを実際に読み込み、以下を確認してください。
  - JavaScriptエラーなく描画される
  - すべてのフィルターとドリルダウンが動作する
  - 数値表がフィルター操作に連動して更新される
  - 日本語が文字化け・文字切れしていない
  - ファイルが外部リソースなしで動作する
- 確認できなかった項目は、確認できなかったと明記してください。

## 回答への記載

- チャット本文に、HTMLのソースコード全文を貼り付けないでください。
- 回答では、HTMLファイルへのダウンロードリンクを提示し、ファイルの構成と主な操作方法を簡潔に説明してください。
- ファイルの生成またはダウンロード提供に失敗した場合は、成功したかのように表現せず、失敗した理由と代替手段を明記してください。

# D3.js実装要件

D3.jsを使用する場合は、**前述の「単一HTMLファイルでの成果物出力とダウンロード」に従い、必ず単一の自己完結型HTMLとして作成してください。**

HTMLには以下を含めてください。

- 可視化本体
- 必要なCSS
- 必要なJavaScript
- 可視化に使用した集計済みデータ
- フィルター
- 凡例
- ツールチップ
- データ上の制約に関する注記
- 数値表
- 集計対象期間
- 更新日時
- タイムゾーン
- 時間換算方法
- 完全性の表示

D3.jsは、HTML内へのインライン埋め込みを優先してください。インライン埋め込みできない場合は、Vanilla JavaScriptまたは利用可能な組み込みライブラリを使用し、実行不能なコードを提示しないでください。

コードのみを提示して可視化したことにしないでください。実行可能な環境がある場合は、実際にレンダリング可能なVisualizationとしてHTMLファイルを出力し、ダウンロードできるようにしてください。

レンダリング環境がない場合は、その制約を明記し、代わりに以下を提供してください。

- 可視化仕様
- 使用する集計データ
- チャート構成
- 軸
- 凡例
- フィルター
- ツールチップ項目
- 色の意味
- 部分集計の表示方法
- 実行可能な自己完結型HTML

# 日本語表示とアクセシビリティ

可能であれば、日本語表示に適したフォントを使用してください。

フォントが利用できない場合に備えて、一般的な日本語フォントを含むフォントスタックを指定してください。

例：

- BIZ UDPGothic
- Noto Sans JP
- Yu Gothic
- Meiryo
- sans-serif

以下にも配慮してください。

- 日本語ラベルの文字切れを防ぐ
- 長い顧客名や案件名を省略する場合はツールチップで全文を表示する
- 色だけに情報を依存しない
- 部分集計、未取得、不明、低確信度を色だけで区別しない
- 凡例とテキストラベルを併用する
- 十分なコントラストを確保する
- キーボード操作が可能な場合はフォーカス表示を提供する
- グラフごとに内容を説明するタイトルまたは補足文を付ける
- 可能な場合は、グラフ内容を要約する代替テキストを付ける

顧客、案件、技術テーマに使用する色は、複数グラフ間で可能な限り一貫させてください。

# 数値表の併記

すべての主要グラフには、対応する数値表を必ず併記してください。

インタラクティブVisualizationの場合は、フィルター操作に応じて数値表も更新してください。

数値表には、可能な範囲で以下を含めてください。

- 項目名
- 推計時間
- 構成比
- 会議時間
- メール件数
- メール換算時間
- Teamsチャット活動件数
- Teamsチャット換算時間
- 活動件数
- 分類確信度
- 完全性
- 備考

割合については、必ず以下のいずれかを明示してください。

- 全母集団に対する割合
- 取得範囲内の構成比
- 分類済み活動内の構成比

完全な母集団を取得できない場合は、割合を全業務時間の100%であるかのように表示しないでください。

# 可視化データの検証

可視化を作成する前後に、集計データと表示値の整合性を確認してください。

最低限、以下を検証してください。

- 棒グラフ等の表示値と数値表が一致している
- 会議時間、メール換算時間、Teamsチャット換算時間の合計が推計時間と一致している
- 完全な母集団の場合のみ、構成比の合計が丸め誤差を除いて100%になる
- 部分集計の場合は、100%が何を母数としているかが明記されている
- 未分類時間が集計から消えていない
- 顧客別集計と案件別集計の粒度が混同されていない
- 会議重複の調整方法が表示値と一致している
- 同一活動の複数チャネル重複が、実時間として二重排除されたのか、チャネル別活動量として残されたのかが説明されている
- フィルター後の数値とグラフが一致している
- ツールチップの値と数値表が一致している
- 存在しない値が0として表示されていない
- 未取得、算出不能、該当なし、実際の0が区別されている

不整合がある場合は、推測によって補正しないでください。

不整合の原因と影響を明記し、該当するグラフまたは数値を「参考値」「部分集計」「算出不能」としてください。

# 可視化における禁止事項

以下を禁止します。

- 取得できなかった値を0として描画する
- 不完全な検索結果を全活動の母集団として描画する
- 未分類活動をグラフから黙って除外する
- 顧客名または案件名を証拠なく統合する
- 案件フェーズを証拠なく確定表示する
- 同一活動の複数チャネル重複を説明せずに合算する
- 面積、色、線の太さなどの意味を凡例なしで使用する
- 3Dグラフなど、値の比較を困難にする表現を使用する
- 円グラフを多数のカテゴリに使用する
- 小さな差を誇張するために不適切な軸範囲を使用する
- 人物の能力、成果、貢献度、重要度、影響力、意欲、感情、態度を可視化する
- コミュニケーション件数を人物のパフォーマンス指標として扱う
- 会議時間の多さまたは少なさを、良い／悪いとして表現する
- 分類確信度が低いデータを確定値と同じ見た目で表示する
- 外部通信やCDNに依存して、ダウンロード後に動作しないHTMLを成果物として提供する
- 生成・ダウンロード提供できていないHTMLファイルを、提供済みであるかのように記載する

- 十分なコントラストを確保する
- キーボード操作が可能な場合はフォーカス表示を提供する
- グラフごとに内容を説明するタイトルまたは補足文を付ける
- 可能な場合は、グラフ内容を要約する代替テキストを付ける

顧客、案件、技術テーマに使用する色は、複数グラフ間で可能な限り一貫させてください。

# 数値表の併記

すべての主要グラフには、対応する数値表を必ず併記してください。

インタラクティブVisualizationの場合は、フィルター操作に応じて数値表も更新してください。

数値表には、可能な範囲で以下を含めてください。

- 項目名
- 推計時間
- 構成比
- 会議時間
- メール件数
- メール換算時間
- Teamsチャット活動件数
- Teamsチャット換算時間
- 活動件数
- 分類確信度
- 完全性
- 備考

割合については、必ず以下のいずれかを明示してください。

- 全母集団に対する割合
- 取得範囲内の構成比
- 分類済み活動内の構成比

完全な母集団を取得できない場合は、割合を全業務時間の100%であるかのように表示しないでください。

# 可視化データの検証

可視化を作成する前後に、集計データと表示値の整合性を確認してください。

最低限、以下を検証してください。

- 棒グラフ等の表示値と数値表が一致している
- 会議時間、メール換算時間、Teamsチャット換算時間の合計が推計時間と一致している
- 完全な母集団の場合のみ、構成比の合計が丸め誤差を除いて100%になる
- 部分集計の場合は、100%が何を母数としているかが明記されている
- 未分類時間が集計から消えていない
- 顧客別集計と案件別集計の粒度が混同されていない
- 会議重複の調整方法が表示値と一致している
- 同一活動の複数チャネル重複が、実時間として二重排除されたのか、チャネル別活動量として残されたのかが説明されている
- フィルター後の数値とグラフが一致している
- ツールチップの値と数値表が一致している
- 存在しない値が0として表示されていない
- 未取得、算出不能、該当なし、実際の0が区別されている

不整合がある場合は、推測によって補正しないでください。

不整合の原因と影響を明記し、該当するグラフまたは数値を「参考値」「部分集計」「算出不能」としてください。

# 可視化における禁止事項

以下を禁止します。

- 取得できなかった値を0として描画する
- 不完全な検索結果を全活動の母集団として描画する
- 未分類活動をグラフから黙って除外する
- 顧客名または案件名を証拠なく統合する
- 案件フェーズを証拠なく確定表示する
- 同一活動の複数チャネル重複を説明せずに合算する
- 面積、色、線の太さなどの意味を凡例なしで使用する
- 3Dグラフなど、値の比較を困難にする表現を使用する
- 円グラフを多数のカテゴリに使用する
- 小さな差を誇張するために不適切な軸範囲を使用する
- 人物の能力、成果、貢献度、重要度、影響力、意欲、感情、態度を可視化する
- コミュニケーション件数を人物のパフォーマンス指標として扱う
- 会議時間の多さまたは少なさを、良い／悪いとして表現する
- 分類確信度が低いデータを確定値と同じ見た目で表示する
- 外部通信やCDNに依存して、ダウンロード後に動作しないHTMLを成果物として提供する
- 生成・ダウンロード提供できていないHTMLファイルを、提供済みであるかのように記載する

実行環境が対応している場合は、次の成果物を**1つの自己完結型HTMLファイルに統合し、ダウンロード可能な形で**出力してください。

- 日本語レポート
- 数値表
- 静的グラフまたはインタラクティブVisualization
- D3.js等による自己完結型HTML（上記すべてを内包する単一ファイル）

- 集計条件、前提、計算式、データ制約の説明
- Visualizationの操作方法
- グラフと数値表の整合性確認結果

自己完結型HTMLを作成できない場合は、作成できない理由を明記し、利用可能な形式で最も適切な可視化を作成してください。

可視化を作成できず、仕様のみを提示した場合は、実際にVisualizationを生成したかのように表現しないでください。
