# 業務フローからAgent作成 — サンプルデータ

> 注意: このファイルに記載する会社名、病院名、製品名、ロット番号、部署名、日付、SLA、規制条件はすべて架空です。実在の個人・団体・制度とは関係ありません。

## 共通シナリオ

- 会社名: 東雲メディカルデバイス株式会社
- 事業: 在宅医療機器（吸入ポンプ・携帯型モニター）の製造販売
- 対象業務: 顧客苦情の受付から、重大度判定、一次報告、CAPA起案まで
- 背景: 2026年9月から販売店・病院・コールセンターの苦情受付チャネルを統合予定
- 強い制約:
  - 患者氏名や診療情報は極力マスキング
  - 重大事故疑いは72時間以内に一次報告草案
  - 営業部だけで対外回答を確定してはいけない
  - 旧Excel台帳と新QMSが3か月並行運用

## 1. 手順のリストアップに渡す入力

```text
あなたはコーチングに長けた私の上司として振舞ってください。

私は東雲メディカルデバイス株式会社で、以下の事業に携わっており、以下の業務をしています。
この業務の実行に必要しますので、手伝ってください。
- 事業: 在宅医療機器の製造販売および保守
- 業務: 顧客苦情の受付から重大度判定、一次報告、暫定対策、CAPA起案まで

ワークフローは以下です。
顧客苦情対応
  ├── 状況確認
  │     ├── 販売店・病院・コールセンターから一次情報を受領
  │     ├── 製品名、ロット、シリアル、発生日、症状、患者影響の有無を確認
  │     └── 個人情報をマスキングして受付番号を採番
  ├── 重大度判定
  │     ├── 健康被害の有無を一次判定
  │     ├── 使用停止・回収要否の仮判断
  │     └── 規制報告要否の一次エスカレーション
  ├── 調査依頼
  │     ├── 品質保証へ調査依頼
  │     ├── 製造記録・出荷記録・保守履歴を回収
  │     └── 不足情報を販売店へ照会
  ├── 初動対応
  │     ├── 72時間以内の一次報告草案を作成
  │     ├── 営業・品質・薬事でレビュー
  │     └── 顧客向け暫定回答案を作成
  └── 是正処置
        ├── CAPA起票
        ├── 原因分類（設計・製造・物流・使用方法）
        └── 再発防止策の承認依頼
```

## 2. マニュアルが無い場合の手順整理に渡す入力

```text
あなたはコーチングに長けた私の上司として振舞ってください。

私はこの仕事をするのが初めてで何をしたらいいのかが分かっていません。
私が仕事で各タスクをする際の手順をリストアップしてください。
それぞれの手順の詳細な内容も教えてください。手順の中で、以下を特に説明してください。
- なぜ
- 何を
- どの様に

# 仕事
- 医療機器メーカーで、販売店や病院から入る苦情・不具合連絡を受け、重大度を見極め、必要な関係者へつなぎ、72時間以内の一次報告草案まで作る仕事です。旧Excel台帳と新QMSが併用中で、患者個人情報は原則マスキング、営業だけで顧客回答を確定してはいけません。重大事故かどうかは受付時点では曖昧なことが多く、製品名やロット番号が欠けているケースもあります。
```

# ワークフロー

## 4. 専門家の抽出に渡す入力

```text
ワークフローの各ステップで発生する解決策を実行するために、どんなスキルのエキスパートが役に立ちますか?
その専門性・認定資格・能力・人間性・学術分野など、そのエキスパートの特徴あるいは特性について、可能な限り丁寧かつ詳細かつ具体的に説明してください。

それぞれのステップに必要なものをリストアップしてください。

# 対象ステップ
- 状況確認
- 重大度判定
- 調査依頼
- 初動対応
- 是正処置

# 追加条件
- 机上の一般論ではなく、医療機器・品質保証・薬事・顧客対応の実務が分かる人材像にする
- 社内に存在しないほど高いレベルの専門家像でもよい
- 深呼吸をして、一歩ずつ進めてください。
```

## 5. 業務遂行に役に立つデータ抽出に渡す入力

```text
ワークフローの各ステップで発生する解決策を実行するために、役に立つ詳細なデータをリストアップして、表形式で作成してください。
データはエンティティ名だけでなく、そのアトリビュートつまり属性についてもリストアップしてください。
定性データと定量データがあります。定性データについては以下も参考にして、必要であれば追加してください。

### 定性データの例
- 販売店とのメールのやり取り
- コールセンター受付メモ
- 病院技師の自由記述コメント

# 特に含めたい観点
- 製品ロット、シリアル、保守履歴、出荷先、発生日、再現条件
- 重大度判定の根拠となる症状情報
- QMS と旧Excel台帳の突合キー
- 個人情報の有無とマスキング状態
- 72時間報告の期限管理

省略をせず、可能な限り全ての詳細な情報を作成してください。
```

## 6. 業務遂行に役に立つ機能抽出に渡す入力

```text
ワークフローの各ステップで発生する課題を解決するために、役に立つ詳細なソフトウェアに求められる機能やAPIやサービスをリストアップしてください。
既存のソフトウェアだけではなく、今存在していないが、あれば役に立つ機能やAPIやサービスがあれば、私が作成しますので、それも含めてください。

# 前提システム
- 新QMS
- 旧Excel苦情台帳
- 販売店ポータル
- メール
- Teams

# 特に困っていること
- ロット番号未記入の自動検知
- 患者個人情報のマスキング漏れ
- 同一事象の重複受付
- 期限超過しそうな案件の早期警告
- 一次報告文案のレビュー差分整理
```

## 7. System Prompt作成に渡す入力

```text
リストアップした各エキスパートを、AI Agentとして作成します。

これまで作成した全ての情報から適切なものを選択して、AI Agent作成に必要な項目を作成してください。
System Promptは、役割と目的、具体的な指示、制約条件、背景情報、例示、簡潔さ、フィードバックループ、専門性を含めてください。
System Promptの「専門性」には、これまで作成したエキスパートの専門性、認定資格、能力、人間性、学術分野を記載してください。

各AI Agentとは別に追加で、全ての業務が出来る「顧客苦情対応統括」AI Agent も作成してください。

### AI Agent作成に必要な項目
- Agent:
- Agentの説明:
- System Prompt:
- ソフトウェアの機能やAPIやサービス:
- データ:

# 補足
- 個人情報と規制報告情報を扱うため、推測による断定は禁止
- 顧客向け回答はドラフト止まり
- 重大事故疑いは必ず人間承認へ回す
```
