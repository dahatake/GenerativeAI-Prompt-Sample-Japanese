# サンプルデータ監査レポート

> すべて架空の研修用データです。対象は各フォルダの `sample/*サンプルデータ.md`（約75ファイル）です。

## 監査観点

1. 対応Promptへのリンク・架空データ注意書きがあるか
2. プレースホルダー（`○○` / `TODO` など）が残っていないか
3. シナリオに対して分量が妥当か（分析・学習・検証が成立するか）
4. 「貼り付け用の抜粋」と「実ファイル」の役割が分かれているか

## 結果サマリー

| 観点 | 結果 |
|---|---|
| 架空データ注意書き | 全ファイルにあり |
| 対応Promptリンク | 一部は `対応Prompt: ..\xxx.md` のプレーンテキスト表記（リンク切れではない） |
| プレースホルダー残り | なし（検出語は説明文・「質問例」見出し・`○○さん` を含むPrompt例のみ） |
| 世界観の一貫性 | 会社名・数値・日付は2026年の北辰/各社設定で概ね揃っている |
| 分量の不足 | **データ分析系、SQL、会議の文字起こし、巡回セールスマンで不足 → 本対応で改善** |

### 問題なしと判断したもの

- 行政フォルダ：PDF／xlsx／xlsm の実ファイルが既にあり、シナリオ規模に見合う。
- Code Interpreter：`data/` に実Excel/CSV、`factory-copilot-demo-2026-09.zip` がある。
- Agent・Security・Workshop・教育・人事・営業・日々のタスク・管理職・ビジネス戦略：テキスト入力が主で、2〜10KBの分量はプロンプトの1回入力として妥当。

## 生成データの設計

- 生成スクリプト: [generate_sample_data.py](../データ分析/sample/generate_sample_data.py)（シード固定。再実行で同一結果）
- 各CSVには、md側の「品質メモ」と同種の欠損・重複・表記ゆれ・外れ値を意図的に混ぜてある（例: PedalGoのマスター未登録ID、競合名の表記ゆれ、2026-02の春節スパイク）。
- 数値は架空であり、実在の統計・顧客・金融取引ではない。

## 残課題（今回未対応）

- `対応Prompt:` 行をリンク形式に統一する（約30ファイル）。
- `訪日外客数のデータ加工` は既存の実Excel（`Code Interpreter/data/`）を使う前提のため、本対応では変更していない。

## 追補: 全ファイル精読後の主な修正

全サンプルを対応Promptと突き合わせて読み、次を修正した（詳細はgit差分を参照）。

- 日付・曜日の誤り（土曜日の会議等）、金額の食い違い（投資上限7,000万円→6,000万円）、期間の矛盾（半年導入計画）、時代の矛盾（2026年の辰年イベント）を是正。
- 実在名に見える固有名（ミルクボックスカフェ/Northgate等）を架空名へ置換。
- 本文と実ファイルが食い違っていた箇所（行政の出納PDF、データ分析CSV、訪日外客数の加工レイアウト）を実ファイルに合わせて修正。
- 分量不足を補う実ファイルを追加（メール75件、見積200件、小テスト回答、OrderFlowのコード一式、Azureアラート/コストCSV、Security試験ケース14件、Excel(xlsx)等）。
- 全 `対応Prompt:` 行をリンク形式に統一（前回の残課題を解消）。
- 既知の注意: 分類モデルの `collection_note` は目的変数をほぼ予測するリーク列（mdに明記）。
