# 行政関連

このPromptは、行政の業務改善や政策評価に関する情報を提供するために作成されました。行政職員や政策立案者が、より効果的な施策を実施し、住民の満足度を向上させるための参考資料として活用してください。

# 謝辞
このシナリオは、現在「総務省自治体DXアクセラレータ」として活躍されている桃井誠さんのご協力により作成されました。桃井さんの専門知識と経験に基づくアドバイスは、行政の業務改善や政策評価において非常に貴重なものです。ここに深く感謝申し上げます。

## 共通の前提

- 個人情報、マイナンバー、口座番号、健康情報、職員番号などは入力せず、必ずダミー化またはマスキングします。
- RAGやナレッジ機能を使う場合は、公開資料または庁内で利用許可された資料だけを登録します。
- AIの出力は最終成果物ではなく、担当者が確認・修正して使う下書きとして扱います。

## 1. Excelマクロの保守・理解支援

### ビジネス上のシナリオ

税務、福祉、会計、統計などの部署で、前任者が作成したExcelマクロが業務の一部として使われ続けているものの、現担当者にはVBAの知識が十分になく、処理内容や修正時の影響範囲が分からない状態です。

このテーマでは、既存のVBAコードを自治体専用AIに読み込ませ、後任者向けの「引継ぎマニュアル」「処理フロー」「注意点一覧」を作成します。目的は、マクロをすぐに改修することではなく、まず「何を、どの順番で、なぜ行っているか」を業務担当者が理解できる状態にすることです。

### 入力に有効なデータの例

- VBAのマクロコード
- マクロを実行するExcelファイルの用途説明
- シート名、列名、入力項目、出力項目の説明
- 実行前後で何が変わるかの説明
- エラーが起きやすい操作や過去の引継ぎメモ

入力例：

```text
業務名：月次集計表の作成
利用者：会計課の担当職員
目的：各課から提出された支出データを取りまとめ、会計区分ごとの集計表を作成する。

シート構成：
- 入力データ：各課から提出された支出一覧
- マスタ：会計区分コードと名称
- 集計結果：マクロ実行後に作成される表

VBAコード：
Sub CreateSummary()
    Dim lastRow As Long
    lastRow = Sheets("入力データ").Cells(Rows.Count, 1).End(xlUp).Row
    Sheets("集計結果").Range("A2:D1000").ClearContents
    ' 以下、会計区分ごとに集計する処理
End Sub
```

### Prompt

```text
あなたは、自治体業務に詳しいベテランのExcel VBA担当者です。
以下のExcelマクロについて、VBAに詳しくない後任職員でも理解できるように、処理内容を業務引継ぎマニュアルとして整理してください。

# 目的
- マクロが「何のために」「どの順番で」「どのデータを使って」動いているかを理解したいです。
- コードの専門的な説明ではなく、業務担当者が運用・確認できる説明にしてください。
- 不明点や推測が必要な点は、断定せず「要確認」として明示してください。

# 入力情報
## 業務の概要
{このExcelファイルを使う業務の説明を貼り付ける}

## シート・列・項目の説明
{分かる範囲でシート名、列名、入力項目、出力項目を貼り付ける}

## VBAコード
{VBAコードを貼り付ける}

# 出力形式
次の構成で出力してください。

1. このマクロの目的
   - 3行以内で要約してください。

2. 処理の全体像
   - 業務担当者向けに、処理の流れを箇条書きで説明してください。

3. 処理フロー表
   - 「順番」「処理内容」「対象シート・列」「確認ポイント」「要注意事項」の表にしてください。

4. 入力データと出力データ
   - マクロ実行前に必要なデータ
   - マクロ実行後に作成・更新されるデータ
   - 入力漏れがあると問題になりそうな項目

5. エラーや事故を防ぐための確認事項
   - 実行前に確認すべきこと
   - 実行後に確認すべきこと
   - 触らない方がよい箇所

6. 後任者向けの一言マニュアル
   - 「このマクロは、要するに何をしているのか」をIT知識がない職員向けに説明してください。

7. 要確認事項
   - コードだけでは判断できない点
   - 担当課に確認すべき点

# 制約
- コードを実行したかのように断定しないでください。
- 分からない仕様は推測で補完せず、「要確認」としてください。
- 個人情報が含まれている場合は、内容を引用せず「個人情報と思われる値」として扱ってください。
```

## 2. 会話ログからのマニュアル自動作成

### ビジネス上のシナリオ

ベテラン職員から若手職員への引継ぎでは、実際の手順が口頭説明、チャット、会議メモ、音声認識テキストなどに散在しがちです。口頭説明には、主語の省略、順序の前後、略称、暗黙知が含まれるため、そのままでは業務マニュアルとして使いにくい状態です。

このテーマでは、会話ログを自治体専用AIに貼り付け、行政文書として読みやすい「手順書」「チェックリスト」「FAQ」に変換します。目的は、属人化した知識を整理し、誰でも同じ手順で作業できる状態にすることです。

### 入力に有効なデータの例

- 前任者との会話ログ
- 音声認識で文字起こしした説明文
- Teamsやチャットのやり取りをマスキングしたテキスト
- 業務で使うシステム名、画面名、帳票名
- 期限、承認者、関係部署、例外対応のメモ

入力例：

```text
業務名：補助金申請受付後の確認作業
対象者：新しく担当になった職員

会話ログ：
前任者：まず申請書が届いたら、受付簿に日付を入れてください。添付資料が足りないことが多いので、チェック表を見ます。
後任者：どのチェック表ですか？
前任者：共有フォルダにある最新版です。年度が変わると様式が変わるので注意してください。
前任者：金額が上限を超えていたら、すぐ差し戻しではなく、担当係長に確認します。
後任者：申請者への連絡はメールですか？
前任者：原則メールですが、期限が近い場合は電話もします。記録は必ず対応履歴に残します。
```

### Prompt

```text
あなたは、自治体の業務引継ぎ資料を作成する業務改善アドバイザーです。
以下の会話ログから、初めて担当する職員でも作業できる業務マニュアルを作成してください。

# 目的
- 口頭説明や会話ログに含まれる暗黙知を、再利用できる手順書に変換したいです。
- 主語が省略されている箇所や順番が前後している箇所を整理してください。
- ただし、会話ログにない制度・ルールは勝手に追加しないでください。

# 入力情報
## 業務名
{業務名を入力}

## 想定読者
{例：初めてこの業務を担当する一般職員}

## 会話ログ・文字起こし
{会話ログまたは音声認識テキストを貼り付ける}

## 補足情報
{システム名、帳票名、締切、関係部署など、分かる範囲で入力}

# 出力形式
次の構成で出力してください。

1. 業務の目的
   - この業務が何のために行われるかを簡潔に説明してください。

2. 業務の全体像
   - 「事前準備」「受付・確認」「システム入力」「承認・連絡」「記録・保管」のように、自然な流れに整理してください。

3. 詳細手順
   - 「手順番号」「作業内容」「使用する資料・システム」「判断基準」「注意点」の表で作成してください。

4. チェックリスト
   - 作業漏れを防ぐため、実施前・実施中・実施後に分けてチェック項目を作成してください。

5. よくある例外対応
   - 会話ログに含まれる例外や注意点を抽出してください。
   - 根拠が不明なものは「要確認」としてください。

6. FAQ
   - 新任担当者が質問しそうな内容をQ&A形式で整理してください。

7. 確認すべき不足情報
   - マニュアル完成前に前任者や上司へ確認すべき点を列挙してください。

# 制約
- 会話ログにない情報を、事実のように書かないでください。
- 不明点は「要確認」と明記してください。
- 個人名、電話番号、メールアドレス、申請者情報が含まれる場合はマスキングしてください。
- 行政文書として読みやすい、丁寧で簡潔な表現にしてください。
```

## 3. 年末調整の申請作成支援（チャットボット）

### ビジネス上のシナリオ

年末調整の時期になると、職員から人事・給与担当へ「どの欄に書くのか」「どの証明書が必要か」「配偶者や扶養親族の扱いはどうなるか」といった問い合わせが集中します。担当者は国税庁などの公開資料を確認しながら回答しますが、同じ質問が繰り返され、業務負荷が高くなります。

このテーマでは、国税庁の書き方マニュアルなど公開情報を自治体専用AIのナレッジ機能に登録し、根拠ページを示しながら案内するFAQボットを作成します。職員の個別情報は入力させず、質問は必ず匿名化・一般化した条件で扱います。

### 入力に有効なデータの例

- 国税庁が公開している年末調整関係の記載例、手引き、FAQ
- 自治体内で配布している一般的な案内文（個人情報を含まないもの）
- 申告書の種類名、欄名、提出期限などの一般情報
- 匿名化した質問例

入力例：

```text
登録資料：
- 令和○年分 給与所得者の扶養控除等申告書の記載例
- 令和○年分 基礎控除申告書・配偶者控除等申告書・所得金額調整控除申告書の記載例
- 年末調整に関する一般FAQ

質問例：
- 配偶者の給与収入が年間○○万円程度の場合、配偶者控除等申告書のどの欄を確認すればよいですか。
- 生命保険料控除証明書がある場合、どの申告書に記入しますか。
- 扶養親族が大学生の場合、確認すべき欄はどこですか。
```

### Prompt

```text
あなたは、自治体職員向けに年末調整書類の書き方を案内するFAQ担当者です。
登録済みのナレッジ資料だけを根拠に、質問者が確認すべき申告書、欄、ページ、注意点を分かりやすく案内してください。

# 重要な前提
- 回答には、登録済み資料に書かれている内容だけを使ってください。
- 根拠資料が見つからない場合は、推測で回答せず「登録資料からは確認できません」と伝えてください。
- 個人情報、マイナンバー、住所、氏名、具体的な給与額、家族の詳細情報は入力しないよう案内してください。
- 税務上の最終判断が必要な場合は、人事・給与担当または税務署等の公式窓口に確認するよう促してください。

# 質問
{年末調整に関する質問を、個人情報を除いて入力する}

# 出力形式
次の構成で回答してください。

1. 結論
   - どの申告書・どの欄を確認すべきかを簡潔に答えてください。

2. 確認する資料・ページ
   - 資料名、ページ番号、見出し、該当箇所を示してください。
   - ページ番号が分からない場合は、資料名と見出しを示してください。

3. 書き方の確認ポイント
   - 質問者が確認すべき項目を箇条書きにしてください。
   - 個人情報そのものは書かせず、確認観点だけを示してください。

4. 注意事項
   - 判断が分かれそうな点、証明書が必要になりそうな点、担当者確認が必要な点を示してください。

5. 次に行うこと
   - 質問者が次に確認・準備すべき行動を、1〜3個で示してください。

# 回答ルール
- 根拠資料にない内容は回答しないでください。
- 断定できない場合は「資料上は確認できません」「担当部署に確認してください」と書いてください。
- 専門用語は、一般職員にも分かる言葉で補足してください。
- 回答の最後に「個人情報は入力しないでください」と注意喚起してください。
```

## 4. 出納担当の審査業務（PDF検算の自動化）

### ビジネス上のシナリオ

出納担当は、支出伝票、請求書、検収書、決裁文書などを確認し、支出金額、債権者名、会計区分、摘要、日付などに不整合がないかを審査します。PDFを目視で確認して転記・照合する作業は時間がかかり、金額の読み間違いや確認漏れが発生しやすい業務です。

このテーマでは、ダミーの支出伝票PDFを自治体専用AIに読み込ませ、必要項目をMarkdown表として抽出し、金額や項目の不一致を確認しやすい形に整えます。目的は、会計システムへの自動登録ではなく、人間が審査しやすい確認リストを短時間で作ることです。

### 入力に有効なデータの例

- ダミー化した支出伝票PDF
- ダミー化した請求書PDF
- 抽出したい項目一覧
- 会計区分や支出科目のコード表
- システム集計値、伝票番号、審査観点のメモ

入力例：

```text
添付資料：支出伝票PDF（ダミーデータ）

抽出したい項目：
- 伝票番号
- 支出日
- 債権者名
- 支出金額
- 消費税額
- 会計区分
- 支出科目
- 摘要

照合したいシステム集計値：
- 伝票番号：D-2026-001
- 支出金額：125,400円
- 会計区分：一般会計
```

### Prompt

```text
あなたは、自治体の出納審査を支援する確認リスト作成担当者です。
添付されたPDFから、支出審査に必要な項目を抽出し、人間が確認しやすいMarkdown表に整理してください。

# 目的
- PDFを目視確認する前に、主要項目を一覧化したいです。
- システム集計値と突き合わせやすい形にしてください。
- OCRで読み取りが不確かな箇所は、断定せず「要目視確認」としてください。

# 入力情報
## 添付PDF
{支出伝票、請求書などのPDFを添付する}

## 抽出したい項目
{例：伝票番号、支出日、債権者名、支出金額、会計区分、支出科目、摘要}

## 照合したい値
{会計システム等の集計値があれば貼り付ける。なければ「なし」と入力}

# 出力形式
次の構成で出力してください。

1. 抽出結果一覧
   - 「項目」「抽出値」「記載箇所」「信頼度」「確認メモ」の表にしてください。
   - 記載箇所は、ページ番号や見出しなど分かる範囲で示してください。

2. 金額確認
   - PDF上の金額、内訳、合計額を表にしてください。
   - 合計が計算できる場合は、計算結果を示してください。
   - 計算できない場合は、その理由を示してください。

3. システム集計値との照合
   - 入力された照合値とPDF抽出値を比較してください。
   - 「一致」「不一致」「要目視確認」のいずれかで判定してください。

4. 審査時の注意点
   - 不鮮明な文字、金額の不一致、日付の不整合、会計区分の確認漏れなどを列挙してください。

5. 人間が次に確認すべきこと
   - 優先度の高い順に、確認作業を箇条書きにしてください。

# 制約
- PDFに書かれていない情報を補完しないでください。
- 読み取りが不確かな場合は「要目視確認」としてください。
- 個人情報や口座番号が含まれる場合は、そのまま出力せずマスキングしてください。
- 出力は会計処理の最終判断ではなく、担当者の確認用リストとして作成してください。
```

## 5. 教育委員会の連絡調整（転送・起案文自動作成）

### ビジネス上のシナリオ

教育委員会には、県や国から学校向けの通知、調査依頼、研修案内、提出依頼などが日々届きます。担当者は、原文を読み、各学校に分かりやすい形で転送し、必要に応じて課内決裁用の起案文も作成します。同じ通知から「学校向けの依頼文」と「庁内向けの起案文」というトーンの異なる文書を作るため、時間がかかりやすい業務です。

このテーマでは、通知メール本文を自治体専用AIに貼り付け、学校向けの転送文と課内決裁用の起案伺い文を同時に作成します。目的は、担当者がゼロから文面を作る負担を減らし、依頼事項・期限・添付資料・対応要否を漏れなく整理することです。

### 入力に有効なデータの例

- 県や国から届いた通知メール本文
- 添付資料名、提出期限、回答方法
- 送付先の種別（小学校、中学校、義務教育学校など）
- 自治体の文体・トーンに関する指定
- 課内決裁で必要な項目

入力例：

```text
通知メール本文：
県教育委員会より、令和○年度情報モラル教育研修の実施について通知します。
各市町村教育委員会におかれましては、管内学校へ周知いただき、参加希望者を取りまとめのうえ、令和○年○月○日までに別添様式で回答してください。

添付資料：
- 実施要項.pdf
- 参加申込様式.xlsx

作成したい文書：
1. 各学校宛ての転送文
2. 課内決裁用の起案伺い文

文体：
- 学校向け：分かりやすく、依頼事項を明確にする
- 起案文：公文書調で簡潔にする
```

### Prompt

```text
あなたは、自治体の教育委員会で通知文・起案文を作成する文書作成担当者です。
以下の通知メール本文をもとに、各学校宛ての転送文と、課内決裁用の起案伺い文を同時に作成してください。

# 目的
- 原文の内容を正確に読み取り、学校が取るべき行動を分かりやすく伝えたいです。
- 課内決裁用には、通知の趣旨、対応方針、依頼事項、期限を簡潔に整理したいです。
- 原文にない依頼や期限を勝手に追加しないでください。

# 入力情報
## 通知メール本文
{県・国などから届いた通知メール本文を貼り付ける}

## 添付資料
{添付資料名、様式名、参考資料名などを入力する}

## 送付先

## 自治体内の補足ルール

# 出力形式
次の構成で出力してください。

1. 原文の要点整理
   - 通知の目的
   - 学校または教育委員会が対応すべきこと
   - 期限
   - 添付資料
   - 注意点

2. 各学校宛ての転送文
   - 件名
   - 宛名
   - 本文
   - 依頼事項
   - 提出期限・提出方法
   - 問い合わせ先欄
   - 学校が迷わないよう、平易で丁寧な表現にしてください。

3. 課内決裁用の起案伺い文
   - 件名
   - 起案理由
   - 概要
   - 対応方針
   - 学校への依頼内容
   - 期限
   - 添付資料
   - 公文書として簡潔で過不足のない表現にしてください。

4. 担当者向けチェックリスト
   - 送信前に確認すべきこと
   - 決裁前に確認すべきこと
   - 添付漏れや期限誤りを防ぐ確認項目

5. 要確認事項
   - 原文だけでは判断できない点
   - 上司または発信元に確認すべき点

# 制約
- 原文にない事実、期限、提出方法を追加しないでください。
- 不明点は「要確認」として出力してください。
- 個人情報や非公開情報が含まれる場合はマスキングしてください。
- 学校向け文書は分かりやすく、起案文は簡潔な公文書調にしてください。
```
