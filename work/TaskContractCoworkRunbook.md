# Copilot Cowork 実行手順書（CW1）: Task Contract Prompt と従来型のプロンプトを、Cowork で比べる

- 対象: 課題 T1（月次売上の集計）。従来型のプロンプト（B）と Task Contract Prompt（TC+）を、Cowork で各3回（計6回）実行する。
- あなたがすること: Cowork での操作（本人確認、貼り付け、回答、承認の判断）と、結果の保存、返送。
- 私がすること: 返送されたファイルを、隠し要件のテストで採点し、白書に反映する（あなたは採点の基準を知らなくてよい）。
- 所要時間の目安: 90〜120分（1回あたり10〜20分）。
- 実験の手順と採点の基準は、実行前に固定して記録した: [preregistration_cowork_cw1.md](./experiments/data/preregistration_cowork_cw1.md)。この手順書は、その手順を実行する形にしたものである。

---

## 0. 全体の流れ

1. 準備（5分）: PowerShell で作業フォルダーを作る。
2. 6回の実行（run-01〜run-06）: **B、TC+、B、TC+、B、TC+ の順**。毎回、**新しい Cowork のタスク**で行う。
3. 各回の記録: 会話の全文、Cowork が示した結果の dict、観察の記録を、フォルダーに保存する。
4. 返送（5分）: 1つのコマンドで zip を作り、その場所と SHA-256 を、次のメッセージで私に送る。

```
run-01  B     従来型のプロンプトを貼る
run-02  TC+   Phase 1（契約案と質問）→ 固定回答 → Phase 2（実装）
run-03  B
run-04  TC+
run-05  B
run-06  TC+
```

PowerShell で、次を実行する。

```powershell

powershell -NoProfile -ExecutionPolicy Bypass -File .\cowork.ps1 init
```

- `C:\CoworkRuns\CW1\run-01` 〜 `run-06` のフォルダーが作られ、各フォルダーに記録用の `meta.txt` ができる。
- 以降のコマンドは、**`cowork` というスクリプトを同じ形で呼ぶ**（`.\cowork.ps1 ...`）。実行できないときは、先頭に `powershell -NoProfile -ExecutionPolicy Bypass -File` を付ける。

## 3. 共通のルール（6回すべてで守る）

1. **回ごとに、新しい Cowork のタスク（新しい会話）を始める。** 前の回の内容を引き継がない。
2. **プロンプトは変更しない。** 後述のコマンドでクリップボードにコピーして、そのまま貼る（ファイルは E12 と同じプロンプト。コマンドが SHA-256 を表示するので、下の値と一致することを確かめる）。
   - B: `1CA4667C…834B`
   - TC+ の Phase 1: `614CE0F9…6295`
3. **Cowork が質問してきたら、回答の表（6章）の文だけで答える。** 質問されていない話題は、自分から言わない。ヒントも出さない。B のときも同じ。
4. **承認の判断**:
   - 計画の承認、この課題のデータの処理、新しい作業用の場所へのファイルの保存 → 承認してよい。
   - **メールの送信、予定の作成、共有、他のファイルや他人のデータの読み取り → 承認しない（拒否する）。** 求められた内容を `meta.txt` に書く。
5. **途中で自分の判断で助言しない。** 結果が間違っていても、直すよう頼まない（B のとき、Cowork が示した結果が最終）。
6. 想定外のこと（エラー、Cowork の停止、規則に従えなかったこと）があったら、`meta.txt` の `deviations` に書く。**やり直してよいのは、(a) Cowork の障害や停止で最終回答が得られなかったとき、(b) この手順書と違うことをしてしまったとき、の2つだけで、1回まで。** やり直す前の記録は、`run-0N\try1\` というフォルダーを作って、**ファイルをすべてそこに移す**（`meta.txt` を含む）。やり直した後の記録を、`run-0N\` に新しく作る（私は、やり直した後を主な結果にして、やり直す前も併記する）。

## 4. B の回（run-01、run-03、run-05）

1. 新しい Cowork のタスクを始める。開始時刻をメモする。
2. プロンプトをコピーする。

   ```powershell
   .\cowork.ps1 copy B
   ```

3. Cowork の入力欄に、**貼り付けて送信する**。
4. Cowork が質問したら、6章の表で答える。承認を求められたら、3章の規則で判断する。
5. Cowork が最終回答を示したら、終了時刻をメモする。**次の3つを保存する**（7章）。
   - `conversation.txt`: 会話の全文
   - `final_dict.json`: Cowork が最終結果として示した dict だけ
   - `meta.txt`: 観察の記録
   - Cowork が作ったファイルがあれば、そのフォルダーに保存する（名前を変えない）

## 5. TC+ の回（run-02、run-04、run-06）

TC+ は、**2段階**（Phase 1: 契約案と質問 → あなたの回答 → Phase 2: 実装）で行う。

### 5-1. Phase 1

1. 新しい Cowork のタスクを始める。開始時刻をメモする。
2. プロンプトをコピーして、貼って送信する。

   ```powershell
   .\cowork.ps1 copy P1
   ```

3. Cowork は、データを調べ、質問と Task Contract 案を示して、**止まるはず**である。
   - 質問と契約案の**全文**（画面に出たすべて）を、`C:\CoworkRuns\CW1\run-02\phase1_output.txt`（run 番号に合わせる）に保存する（メモ帳に貼り付けて、UTF-8 で保存する）。
   - Cowork が止まらずに実装まで進んだ場合は、**回答を送らず**、その時点の結果を記録して、7章に進む（`stopped_after_phase1: no`）。

### 5-2. あなたの回答（固定の表で答える）

1. Cowork の質問と「この仮定で進めます」が、6章の表の話題（`cancelled`、`tz`、`tax`、`months`）の**扱い方を尋ねている、または述べているか**を、1つずつ判断する（データの事実を述べているだけのときは当たらない）。
2. 含まれている話題だけを指定して、回答のファイルを作る。例: 質問が「タイムゾーン」と「取消の扱い」だったとき

   ```powershell
   .\cowork.ps1 answers run-02 tz cancelled
   ```

   - 話題が1つもなければ、`.\cowork.ps1 answers run-02`（話題なし）とする。
   - 表にない質問（丸め、負の金額など）には、スクリプトが自動で「特に指定はありません。推奨案で進めてください。」を付ける。
3. `meta.txt` の `topics_answered` に、答えた話題を書く。

### 5-3. Phase 2

1. 次のコマンドで、Phase 2 のプロンプト（契約案と回答を埋め込んだもの）を作る。クリップボードにもコピーされる。

   ```powershell
   .\cowork.ps1 phase2 run-02
   ```

2. 同じ Cowork のタスクで、**貼り付けて送信する**。
   - 同じタスクで続けられないときだけ、**新しいタスク**を始めて、次のコマンドで作ったプロンプトを貼る（元のデータが先頭に付く）。`meta.txt` の `phase2_same_task` に no と書く。

     ```powershell
     .\cowork.ps1 phase2 run-02 -NewTask
     ```
3. Cowork が最終回答を示したら、終了時刻をメモして、7章の3つを保存する。値の聞き返しや承認が出たら、3章と6章の規則で答える。

## 6. 回答の表（固定。そのまま貼る）

| 話題（キー） | 当たるとき（Cowork の質問や仮定が、その話題の**扱い方**を尋ねている、または述べているとき） | 回答の文 |
|---|---|---|
| `cancelled` | status が cancelled の注文を、集計に含めるか除くか（取消、キャンセルの扱い） | cancelled の注文は集計から除外してください。 |
| `tz` | 月をどのタイムゾーンで決めるか（UTC か JST かなど、月の境界の基準） | 月の判定は日本時間(JST, UTC+9)で行ってください。ordered_at は UTC で記録されています。 |
| `tax` | amount_incl_tax をそのまま集計するか、税抜に直すか（税込、税抜、消費税の扱い） | 金額は税込(10%)で記録されています。レポートは税抜金額(税込 ÷ 1.1、整数)で返してください。 |
| `months` | 注文のない月を、結果に含めるか飛ばすか（欠損月、月の連続性、0 の扱い） | 最初の月から最後の月まで、注文がない月も 0 として必ず含めてください（欠損月を飛ばさない）。 |
| 上記以外 | 丸め、負の金額、出力形式、エラー処理など | 特に指定はありません。推奨案で進めてください。 |

- **Cowork が質問した点、または「この仮定で進めます」と明示した点についてだけ**答える。
- 1つの質問が複数の話題にまたがるなら、該当する行をすべて使う。
- Cowork が**データの事実を述べているだけ**（例: 「status は completed と cancelled の2種類です」）で、扱い方を尋ねても述べてもいないときは、当たらない。
- **迷ったら、当たらない（「上記以外」）にして、迷ったことを `meta.txt` の `deviations` に書く。**
- あなたはこの表を見るため、隠し要件を知った状態で操作する。質問されていない話題を答えない規則が、実験の漏れを防ぐ唯一の仕組みである。
- この表の文は、B のときにも同じように使う（B の回で、Cowork が質問してきたときだけ。B では 5-2 のコマンドは使わず、表の文を直接送る）。

## 7. 各回で保存するもの

フォルダー: `C:\CoworkRuns\CW1\run-0N\`（`init` が作成済み）

| ファイル | 内容 | 作り方 |
|---|---|---|
| `conversation.txt` | Cowork との会話の**全文**（あなたの送信、Cowork の応答、計画、承認の表示、コードと出力を含む） | 画面のやり取りを全選択（Ctrl+A）してコピーし、メモ帳に貼って UTF-8 で保存する。長くて選択できないときは、画面を上から順にコピーして追記する。 |
| `final_dict.json` | Cowork が**最終結果として示した dict だけ**をそのまま貼る（例: `{"2026-01": 12345, ...}`）。途中の例や、直す前の結果は貼らない。結果がファイル（CSV、JSON、画面の表など）にだけあるときは、そのファイルを開いて中身を貼り、`meta.txt` の `deviations` に形式を書く。示されなかったときは `null` と書く | 前後に説明の文があってもよい。**自分で計算し直したり、直したりしない。** 複数の dict があるときは、私が手作業で確認する。 |
| `meta.txt` | 観察の記録（`init` が項目を作成済み） | 各項目の `:` の後に書く。分からない項目は `unknown`。 |
| Cowork が作ったファイル | 生成されたコード（`.py`）、レポート、結果のファイル | **すべて同じフォルダーにダウンロードして、名前を変えずに保存する。** コードのファイルは、私が保留データでも実行する。 |

`meta.txt` の項目:

| 項目 | 書くこと |
|---|---|
| start_time / end_time | 送信から最終回答までの時刻（時:分:秒） |
| cowork_executed_code | Cowork がコードを**実行した**表示（実行結果の出力など）があったか: yes / no / unknown |
| cowork_asked_questions | Cowork があなたに質問した数（なければ 0） |
| topics_answered | 答えた話題（cancelled / tz / tax / months / none） |
| stopped_after_phase1 | TC+ のとき、Phase 1 で止まったか（yes / no）。B は NA |
| phase2_same_task | TC+ のとき、Phase 2 を同じタスクで続けられたか（yes / no）。B は NA |
| approval_prompts_shown | 承認を求める表示があれば、その内容（なければ none） |
| external_effect_requested | メール送信や共有などを求められたら、その内容と、拒否したこと（なければ none） |
| files_created_by_cowork | Cowork が作ったファイル名（なければ none） |
| deviations | この手順書と違うこと（なければ none） |

進み具合は、次のコマンドで確認できる。

```powershell
.\cowork.ps1 status
```

## 8. 返送（全6回が終わったら）

1. すべての記録がそろったら（`status` で `conversation.txt`、`final_dict.json`、`meta.txt` が各回にある）、次を実行する。

   ```powershell
   .\cowork.ps1 pack
   ```

   - `C:\CoworkRuns\CW1\manifest.sha256.txt`（各ファイルの SHA-256）と、`C:\CoworkRuns\CW1_results.zip` ができ、zip の SHA-256 が表示される。

2. 次のメッセージで、私に**次の形で**送る（この PC 上のファイルは、私が直接読める）。

   ```
   CW1 の結果です。
   zip: C:\CoworkRuns\CW1_results.zip
   zip の SHA-256: （pack が表示した値）
   気づいたこと: （任意。Cowork の画面で気づいたこと、使いにくかった点、想定外の表示など）
   ```

3. 6回が終わらなかった場合も、**終わった分だけで返送してよい**（欠けた回は「未実施」として報告する）。

## 9. 返送の後に私がすること

1. zip の SHA-256 と、manifest の各ファイルのハッシュを確認する。
2. `python cowork/score_cowork.py <展開したフォルダー>` で、各回を採点する（Cowork が示した dict、生成されたコードや会話中のコードを元データと保留データで実行した結果。コードは安全性を検査して実行する）。未実施、判定不能、複数の候補は区別して、返送された回のすべてを報告する。
3. 事前に固定した予想（H33〜H35）を判定し、E12（Copilot Chat）と並べる。
4. 白書の「Cowork での Contract の実行」を、未実施から、この結果に更新する（付録、8章、限界）。逸脱があれば、記録する。

## 10. うまくいかないとき

| 状況 | 対応 |
|---|---|
| Cowork にサインインできない | Edge で通常どおりサインインし、Windows Hello の確認を完了する。完了できなければ、その旨を返送のメッセージに書く（結果は「未実施」） |
| コピーしたプロンプトが貼れない | `copy` コマンドをもう一度実行する。メモ帳に貼って確認してから Cowork に貼ってもよい（内容は変えない） |
| Cowork が TC+ で止まらずに実装した | 回答を送らず、その時点の結果を記録する。`stopped_after_phase1: no` |
| Cowork が計画の承認だけを求めて止まった | 3章4の規則で承認する（外部への作用が含まれなければ） |
| Cowork がコードを実行しない、dict を示さない | `final_dict.json` に `null` を書く。直すよう頼まない。`cowork_executed_code` は、**dict が示されたかとは別に**、画面の実行の表示で判断する（実行したが dict を示さなかった、のときは yes）。分からなければ unknown |
| どの話題に当たるか迷う | 6章の「迷ったら」の規則。`deviations` に書く |
| コマンドの実行でエラーが出る | エラーの文を、そのまま返送のメッセージに貼る |
