# Task Contract (案) — monthly_work_hours(path)

## 確認できた事実（shifts.csv を調査）
- 列: `employee,date,type,start,end`（ヘッダあり、UTF-8/LF、6 行のデータ）
- `type` は `work` と `paid_leave` を確認。`paid_leave` は start/end が空。
- 日付は 2026-10-01〜10-03 のみ（単一月 = 2026-10）。従業員は E001〜E003。
- 時刻は `HH:MM`（分単位）。`14:50` のように端数が出る（= 5.8333… 時間）。
- 夜勤の行がある: `E002,2026-10-01,work,22:00,06:00`（end < start → 日跨ぎ）。
- **休憩時間の列は存在しない**。start〜end は拘束時間であり、休憩が含まれているか不明。
- 作業ディレクトリには shifts.csv と timing.txt のみ。既存の solution.py・テスト・仕様書はない。

## 仮定（この仮定で進めます）
- A1. end < start の work は翌日に終了した勤務とみなし、end に 24 時間を加算する（22:00→06:00 = 8.0h）。
- A2. 月は `date` 列で判定する。複数月が混在する場合は月別に分けず、戻り値は引数なしで全行を合算する。関数は `monthly_work_hours(path)` のシグネチャのまま、任意引数 `month="YYYY-MM"` は追加しない。
- A3. `work` 以外で未知の type（例: `absent`）は 0 時間として無視する。
- A4. start/end が空または不正な work 行は例外にせず 0 時間扱いとする。
- A5. 勤務が 1 行もない従業員も、行があれば `0.0` で戻り値に含める（paid_leave のみの人など）。
- A6. 標準ライブラリ（csv, datetime）のみ使用。CSV は UTF-8（BOM があっても可）。

## 質問（外れると手戻りが大きい点・最大3問）

**Q1. 休憩時間の控除**（CSV に休憩列がないため、控除の有無で全員の合計が変わる）
- (a) 控除しない（start〜end をそのまま労働時間とする）
- (b) 労基法準拠: 拘束 6h 超で 45 分、8h 超で 60 分を控除（例: 09:00-18:00 → 8.0h）  ← **推奨**
- (c) 一律 60 分を控除（拘束 6h 超の日のみ）
- 上記以外なら具体的な値（閾値・分数）で答えてください。

**Q2. 有給（paid_leave）の扱い**
- (a) 0 時間（労働時間に含めない）  ← **推奨**（「労働時間」の集計のため）
- (b) 1 日 8.0 時間として加算
- 上記以外なら具体的な値（1 日あたり時間数）で答えてください。

**Q3. 丸め方**（14:50 などで割り切れない値が出る）
- (a) 丸めない（分単位の正確な値を float で返す。例 5.8333…）  ← **推奨**
- (b) 合計を小数第 2 位に四捨五入
- (c) 日ごとに 15 分単位で切り捨てた後に合算
- 上記以外なら具体的な値（桁数・単位・方向）で答えてください。

## Outcome

- Out of scope: 残業・深夜・休日割増の区分集計、月別分割、CSV 以外の入力形式、出力の CLI/ファイル化、祝日・営業日の判定。
