# Task Contract 案（Spec Mode）

## 確認できた事実（sales.csv を調査）
- 列: `order_id, ordered_at, amount_incl_tax, status`。UTF-8、改行 CRLF、10 行（ヘッダ除く）。
- `ordered_at` は UTC（末尾 `Z`）の ISO 8601。例: `2026-01-31T16:20:00Z`。
- 列名は `amount_incl_tax`（税込）。金額は 1100 の倍数で、10% 税込の価格に見える（11000 = 10000×1.1）。
- `status` は `completed` / `cancelled`。cancelled は 2 件（A-1003 22000、A-1007 4400）。
- 負の金額が 1 件（A-1006 = -1100, completed）。返金・値引きと思われる。
- 月またぎで UTC と JST で月が変わる行が 2 件: A-1004（UTC 1/31 16:20 → JST 2/1 01:20）、A-1010（UTC 4/30 15:30 → JST 5/1 00:30）。
- 3 月は注文が 0 件（欠損月）。
- 作業ディレクトリには sales.csv と timing.txt しかない。既存コードやテストはない。

## 仮定
- Python 標準ライブラリ（csv, datetime）のみを使う。
- 戻り値のキーは `"YYYY-MM"`、値は int。

## 質問（外れると手戻りが大きい点のみ）

**Q1. 月の境界はどのタイムゾーンで判定しますか？**（A-1004 と A-1010 の月が変わります）
- A) UTC のまま（`ordered_at` の先頭 7 文字と同じ月。他条件が推奨案なら 1 月 = 19800、2 月 = 7700）
- **B) JST（UTC+9）に変換して判定 ← 推奨**（日本の売上集計のため）
- C) その他。具体的な UTC オフセット（例: +09:00）で答えてください。

**Q2. 金額は何を集計しますか？**
- **A) `amount_incl_tax` をそのまま合計（税込、丸めなし）← 推奨**
- B) 税抜（10%）。行ごとに `amount_incl_tax / 1.1` を切り捨てて合計
- C) 税抜（10%）。月合計を `/ 1.1` して四捨五入
- D) その他。税率・丸め方を具体的な値で答えてください。

**Q3. `cancelled` と負の金額の扱いは？**
- **A) `completed` のみ集計。負の金額（返金）は `completed` なので差し引く ← 推奨**
- B) `completed` のみ集計。負の金額は除外（0 以上の行だけ）
- C) 全 status を集計（cancelled も含める）
- D) その他。具体的な条件で答えてください。

## Task Contract 案

### Outcome
`solution.py` に `monthly_sales(path)` を実装する。`sales.csv` を読み、`{"YYYY-MM": 金額(int)}` の dict を返す。

### Scope / Out of scope
- Scope: `monthly_sales(path)` の実装（CSV 読み込み、月判定、status 絞り込み、合計）。
- Out of scope: CLI・出力ファイル・グラフ・pandas など外部依存・sales.csv の変更・テストフレームワーク導入。

### Data sources
- `sales.csv`（引数 `path` で渡す。列は上記の 4 列）。

### Constraints
- 標準ライブラリのみ。ファイルは UTF-8 で読む。
- 値は int。小数を返さない。
- 作業ディレクトリ外のファイルは読み書きしない。
- 実装フェーズで作るのは `solution.py`（と `timing.txt` への追記）のみ。

### Definition of Done（検証できる条件）
Q1〜Q3 が推奨案（B / A / A）のとき、`monthly_sales("sales.csv")` の期待値は次のとおり。
- 期待値: `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}`（JST 判定・税込・completed のみ）
  - 1 月 = 11000 + 5500 = 16500（A-1004 は JST で 2 月）。
  - 2 月 = 3300 + 8800 − 1100 = 11000。
  - 4 月 = 16500 + 2200 = 18700。A-1010（7700）は JST で 5 月。
- 戻り値のキーは月の昇順。注文のない 3 月はキーに含めない。
- 全値が `int`。
- 回答が推奨案以外の場合は、その選択に合わせて期待値を再計算して確定する。
- `python -c "from solution import monthly_sales; print(monthly_sales('sales.csv'))"` で上記と一致することを確認する。

### Evidence
- 上記コマンドの出力と、手計算の内訳（A-1001〜A-1010 の月・金額・status 対応表）を最終回答に載せる。
- timing.txt に開始時刻と終了時刻を記録する。

### Open questions（この仮定で進めます）
- 注文のない月（3 月）は 0 で補完せず、キーに含めない。
- 不正行（空の金額、非数値、日時の形式不正）は想定しない。処理を停止し、例外をそのまま送出する。
- 金額は整数として `int()` で読む。小数表記は想定しない。
- 同じ `order_id` の重複行はないものとして、重複排除しない。
- `status` の比較は完全一致 `completed`（大文字小文字・前後空白は正規化しない）。
- 空ファイル、ヘッダのみのファイルは `{}` を返す。
- Q1〜Q3 は上記のとおり回答をお願いします。無回答の場合は推奨案（B / A / A）で進めます。
