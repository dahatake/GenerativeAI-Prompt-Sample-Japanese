# Task Contract — 月次売上集計

状態: **確定・実行承認済み**。ユーザーの指示により、個別回答がなかった項目は推奨既定案で確定する。

## 確認できた事実

- 依頼は、`solution.py` の `monthly_sales(path)` で売上を集計し、`{"YYYY-MM": 金額(int)}` の `dict` を返すこと。
- 仕様策定時に確認した入力ファイルは `sales.csv`。列は `order_id,ordered_at,amount_incl_tax,status`。
- データは10行で、全日時に UTC を表す `Z` が付く。金額はすべて整数表記で、`completed` が8行、`cancelled` が2行。
- `A-1004` と `A-1010` は UTC ではそれぞれ1月・4月、JST では2月・5月になる。`A-1006` は `completed` で金額が `-1100`。3月の行はない。

## 採用した仮定

- 月境界は JST（UTC+09:00）の暦月。`completed` の金額を符号付きで合計し、`cancelled` は除外する。対象行がない月は省略する。
- `amount_incl_tax` を記載単位のまま使用し、税の再計算、単位換算、`order_id` による重複排除は行わない。
- 入力は UTF-8（BOM は任意）のヘッダー付きカンマ区切り CSV。日時は `YYYY-MM-DDTHH:MM:SSZ`、金額は半角十進数字に任意の先頭符号。ステータスは `completed` または `cancelled`。
- 必須列の不足、必須値の空欄、不正な日時・整数、未知のステータスは `ValueError`。集計対象外の行も入力として検証する。

## 不足情報

- 元の依頼で未指定だった月境界・売上計上ルール・欠月の扱いは、推奨既定案を採用した。実装を保留する未決事項はない。

## Outcome

`monthly_sales(path)` が指定された CSV を読み取り、確定した月境界・売上計上ルールに沿って、月別の税込合計を `dict[str, int]` で返す。

## Scope・Out of scope

- 対象: `solution.py` の関数ひとつと、その検証テスト・実行報告。`ordered_at` で月を判定し、`status` で対象行を選び、`amount_incl_tax` を加算する。
- 対象外: CSV の書き換え、CLI・帳票の追加、通貨換算、税計算、`order_id` による重複排除。

## Data sources

- 実行時: 引数 `path` が指す CSV。必須列は `ordered_at`、`amount_incl_tax`、`status`。
- 検証: 作業ディレクトリの `sales.csv` と、境界・異常ケース用のテスト内の CSV データ。外部データソースは使わない。

## Constraints

- Python 標準ライブラリのみとし、関数は入力ファイルを変更しない。結果のキーはゼロ埋めした `YYYY-MM`、値は `int`。辞書のキー順序は契約に含めない。
- 作業ディレクトリ内でのみ作業する。開始と終了時に `timing.txt` へタイムスタンプを1行ずつ追記する。

## Definition of Done

1. `solution.py` から `monthly_sales` をインポートでき、`sales.csv` を渡すと `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` と一致する。値は `int` で、入力 CSV は変更されない。
2. `A-1004` が2月、`A-1010` が5月に計上され、`cancelled` 2行は除外され、`A-1006` の `-1100` は2月の合計から差し引かれる。
3. 対象行のない3月は含めないが、対象行があって合計がゼロになった月は `0` を返す。必須ヘッダーだけの入力、または対象行が一件もない入力は `{}` を返す。
4. 必須列がない CSV、必須値が空欄の CSV、不正な日時・金額・ステータスを持つ CSV は `ValueError` になる。

## Evidence

- `sales.csv` 1行目: ヘッダー。4・8行目: `cancelled`。5・11行目: JST 変換で月が変わる行。7行目: 負の金額。
- 照合内訳: 1月 `11000 + 5500`、2月 `3300 + 8800 - 1100`、4月 `16500 + 2200`、5月 `7700`。
- `test_solution.py` でサンプル結果、集計ルール、ゼロ・空の入力、不正入力を検証する。実行コマンド・出力と各 DoD の結果は `report.md` に記録する。

## Open questions

なし。次の3項目は推奨既定案で確定した。

1. 月境界: JST（UTC+09:00）。
2. 売上対象: `completed` のみ。負数もそのまま加算する。
3. 対象行がない月: 省略する。
