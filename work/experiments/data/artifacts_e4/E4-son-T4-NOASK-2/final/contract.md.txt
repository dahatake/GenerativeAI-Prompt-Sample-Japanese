> 確定内容: 質問への回答が無かったため、Q1(a) 休憩控除なし / Q2(a) 有給は0h / Q3(a) 全行を従業員ごとに合算、で確定。
> Open questions の既定案も採用: 日跨ぎは開始日に帰属（月別集計をしないため実質影響なし）、不正行は `ValueError`。

## 1. 事実整理

### 確認できた事実（shifts.csv より）
- 作業ディレクトリには `shifts.csv`（6データ行）と `timing.txt` のみ。`solution.py`・テスト・仕様書は存在しない。
- 列: `employee,date,type,start,end`（ヘッダあり、時刻は `HH:MM`）。
- 従業員: E001(3行), E002(2行), E003(1行)。日付はすべて 2026-10（1か月分のみ）。
- `type` は `work` と `paid_leave` の2種類を確認。`paid_leave` 行は `start`,`end` が空。
- E002 の 2026-10-01 は `22:00`→`06:00`（日跨ぎ勤務。end < start）。
- 休憩時間を表す列は無い。例: 09:00-18:00（拘束9h）、08:30-17:45（拘束9h15m）。

### 仮定（未確認。確認が取れなければ既定案で進める）
- A1: 同一 CSV に複数月が含まれうるため、集計単位は（従業員, 年月）になりうる。関数は `path` のみを取り、月指定が無い。
- A2: 日跨ぎ勤務は end < start の場合に翌日 end として計算する（22:00→06:00 = 8h）。
- A3: 文字コードは UTF-8（BOM 有無を許容）、空行・前後空白は無視する。
- A4: 戻り値の時間は小数時間（例 9:00-14:50 → 5.8333…）で、丸めはしない。
- A5: `type` が `work` 以外（`paid_leave` 等）で start/end が空の行はエラーにせず処理する。

### 不足情報
- 休憩の控除有無と規則。
- `paid_leave` を労働時間に含めるか。
- 複数月が混在した場合の戻り値の形（キーが従業員IDのみ、という指定と整合させる方法）。
- 日跨ぎ勤務の月またぎ（例: 月末22:00→翌月06:00）の帰属。

## 2. 質問（最大3問・回答で実装が大きく変わるもの）

**Q1. 休憩時間は労働時間から控除しますか？**（データに休憩列が無い）
- (a) 控除しない。end−start をそのまま労働時間とする **【推奨既定案】**
- (b) 労基法基準で自動控除（6h超→45分、8h超→60分）
- (c) 固定で1時間控除など、別の規則（内容を指定してください）
- 外れた場合の影響: 全行の値が変わる。ただし控除規則が1か所に集約できるため修正は小さい。

**Q2. `paid_leave`（有給）は労働時間に含めますか？**
- (a) 含めない（実労働時間のみ。有給行は0h扱い）**【推奨既定案】**
- (b) 所定労働時間（例: 8h/日）として加算する
- (c) 別集計（今回の戻り値には含めない）
- 外れた場合の影響: 有給のある従業員（E001）の値が変わる。

**Q3. 複数月が混在する CSV の扱いは？**（戻り値は `{従業員ID: float}` 固定）
- (a) 全行を従業員ごとに合算する。月の絞り込みはしない **【推奨既定案】**
- (b) `monthly_work_hours(path, month="2026-10")` のように任意引数で月を指定でき、指定時はその月のみ集計（未指定は (a)）
- (c) 複数月を検出したら `ValueError`
- 外れた場合の影響: シグネチャと戻り値の意味が変わる。後方互換のため (b) なら (a) を内包できる。

## 3. Task Contract 案

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装し、勤怠CSVから従業員ごとの労働時間（時間単位の float）を返す。

### Scope / Out of scope
- Scope: CSV の読み込み、`work` 行の時間計算（日跨ぎ対応）、従業員ごとの合算、Q1〜Q3 の回答に沿った処理。
- Out of scope: 残業・深夜・休日割増の計算、給与計算、CSV 以外の入力形式、GUI/CLI、`shifts.csv` の変更、外部ライブラリの導入。

### Data sources
- `shifts.csv`（列: employee, date, type, start, end）のみ。外部データ・ネットワークは使わない。

### Constraints
- Python 標準ライブラリのみ（`csv`, `datetime`）。
- 戻り値は `{従業員ID(str): float(時間)}`。
- 不正行（時刻の形式不正など）の扱いは黙って無視せず、`ValueError` 等で明示する（案。要承認）。
- 作業ディレクトリ外のファイルは読み書きしない。

### Definition of Done（検証できる条件）
Q1(a)・Q2(a)・Q3(a) の既定案を前提とした期待値:
1. `monthly_work_hours("shifts.csv")` が E001, E002, E003 の3キーを返す。
2. E001 = 9.0 + 5 + 50/60 = 約 14.8333 h（`paid_leave` は 0h）。
3. E002 = 8.0（日跨ぎ 22:00→06:00）+ 6.0 = 14.0 h。
4. E003 = 9.25 h（08:30→17:45）。
5. 値は `float`、比較は `pytest.approx`（誤差 1e-6 以内）。
6. 日跨ぎ、`paid_leave`（空の start/end）、不正な時刻、空ファイルをカバーする小さなテストを用意し、すべて通る。
7. 回答が既定案と異なる場合は、その回答に沿って期待値を更新して再検証する。

### Evidence
- テスト実行のログ（上記 2〜5 の assert の合格）。
- `python -c "from solution import monthly_work_hours; print(monthly_work_hours('shifts.csv'))"` の出力。
- 作業開始・終了時刻を `timing.txt` に記録。

### Open questions
- Q1（休憩控除）, Q2（有給の扱い）, Q3（複数月の扱い）。回答が無い場合は各推奨既定案（a）で進める。
- 日跨ぎ勤務の月またぎの帰属（既定案: 開始日の月に帰属）。
- 不正行は例外とするか、スキップして警告とするか（既定案: 例外）。
