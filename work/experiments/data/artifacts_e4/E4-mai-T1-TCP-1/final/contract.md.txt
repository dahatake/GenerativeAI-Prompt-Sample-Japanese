# Approved Task Contract (Execution Mode)

## 確認できた事実

- 作業ディレクトリには `sales.csv`、`timing.txt`、`contract.md`、`answers.md`があります。
- `sales.csv` のヘッダーは `order_id,ordered_at,amount_incl_tax,status` です。
- データは10行あり、`completed` または `cancelled` のステータスです。
- 日時はISO 8601形式です。
- 金額は整数文字列で、負数も存在します。
- データ上の月は2026-01、2026-02、2026-04です。
- Contractフェーズ終了時には `solution.py` は存在しませんでした。

## 回答で確定した条件

- Q1: `status == "completed"` の行だけを集計し、`cancelled` 行は除外します。
- Q2: データ内の最初の月から最後の月まで連続する全月を返し、注文がない月は0です。
- Q3: 不正なヘッダー・日時・金額は推奨案に従い明確な例外で失敗させます。
- その他の状態のステータスは売上対象外とします。

## Outcome

作業ディレクトリ内の `solution.py` に、指定されたCSVパスから月次売上を集計する `monthly_sales(path)` を実装し、承認済みの仕様で検証します。戻り値は `{"YYYY-MM": int}` のdictです。

## Scope

- 標準ライブラリの `csv` と `datetime` を使用します。
- 必須ヘッダーは `order_id,ordered_at,amount_incl_tax,status` です。
- 全データ行の日時と金額を検証します。
- 最初から最後までの連続月を生成し、欠落月は0を設定します。
- `completed` 行の金額を月ごとに符号付きで合算します。
- `cancelled` およびその他のステータスは除外します。

## Out of scope

- CSV以外の入力形式。
- 請求、税計算、通貨換算、外部連携。
- CLIや他モジュールへの統合。

## Data sources

- 引数 `path` が示すCSV。
- 検証対象のサンプル: 作業ディレクトリの `sales.csv`。

## Constraints

- 作業ディレクトリ外のファイルは読まない・変更しない。
- 標準ライブラリのみ使用する。
- 月キーは `YYYY-MM` とし、金額は `int` とする。
- 不正なヘッダー、日時、金額、または欠損値は `ValueError` を発生させる。
- 空のデータ行がない場合、返り値は `{}` とする。

## Definition of Done

1. `solution.py` に呼び出し可能な `monthly_sales(path)` が存在する。
2. サンプル `sales.csv` では `{"2026-01": 19800, "2026-02": 7700, "2026-03": 0, "2026-04": 26400}` を返す。
3. 戻り値の各キーが `YYYY-MM` に一致し、各値が `int` である。
4. `cancelled` 行を除外し、`completed` 行の負数を符号付きで合算する。
5. 不正なヘッダー、日時、または金額を明確な例外で検出する。

## Evidence

- サンプル集計:
  - 2026-01: 11000 + 5500 + 3300 = 19800
  - 2026-02: 8800 + (-1100) = 7700
  - 2026-03: 0
  - 2026-04: 16500 + 2200 + 7700 = 26400
- 自己検証用テストは `test_solution.py` に作成し実行する。

## 採用した仮定

- 最初・最後の月の範囲決定には、日時が有効な全行を含めます。
- 不正なヘッダー、欠損値、日時、金額は `ValueError` とします。
- 未知のステータスは売上対象外ですが、データ範囲には含めます。
- ISO 8601のタイムゾーン付き日時はUTC換算後に月キーを決定します。タイムゾーンなし日時はそのまま月キーにします。

- 結果: 8 tests、すべて成功（OK）。
