# Task Contract — 請求書番号の検証

状態: 承認済み（Execution Mode）。依頼に従い、Spec Mode で提示した推奨既定案（Q1〜Q3 の A）で確定した。

## 確認できた事実

- 依頼は、`solution.py` に `validate_invoice_id(value)` を実装し、`bool` を返すこと。
- `samples.txt` の1行目は「最近発行された請求書番号の例:」。2〜5行目には `INV-202601-0001`、`INV-202601-0002`、`INV-202512-0347`、`INV-202603-1200` がある。不正例や判定ルールの記載はない。
- 4例とも `INV-`、ASCII 数字6桁、ハイフン、ASCII 数字4桁の形。末尾には先頭ゼロのある例とない例がある。

## 採用した仮定

- 4例はすべて有効で、形式は `INV-YYYYMM-NNNN` のみ。区切りは ASCII のハイフン、数字は ASCII の `0`〜`9`。
- `YYYYMM` は年 `0001`〜`9999`、月 `01`〜`12`。現在日付や運用開始日との比較は行わない（Q1）。
- `NNNN` は4桁の連番 `0001`〜`9999` とし、`0000` は無効（Q2）。
- 文字列を変換せず全体一致で判定する。前後の空白・末尾改行、小文字、全角数字、文字列以外の値は無効（Q3）。

## Outcome

`from solution import validate_invoice_id` で利用でき、入力が合意した請求書番号の規則に合うかを `True` または `False` で返す。

## Scope・Out of scope

- 対象: 1件の入力の形式・値域の判定、その境界ケースのテスト、および検証結果の報告。
- 対象外: 番号の発行・修正、台帳照合による実在性や一意性の確認、外部システムとの連携。

## Data sources

- 依頼文（関数名・ファイル名・戻り値）と `samples.txt`（番号例）。例にない境界条件は、承認された推奨既定案に従う。

## Constraints

- 作業ディレクトリ内で作業し、開始・終了時刻を `timing.txt` に1行ずつ追記する。
- 実装は標準ライブラリのみとし、関数はファイル・ネットワーク・現在時刻に依存しない。不正入力も例外ではなく `False` を返す。

## Definition of Done（検証できる条件）

- **D1:** `solution.py` から `validate_invoice_id` をインポートでき、呼び出し可能である。
- **D2:** `samples.txt` の4例すべてに `True` を返す。
- **D3:** 下表の代表ケースすべてで期待値どおりの結果を返す。
- **D4:** D2・D3 の有効・無効入力を例外なく処理し、戻り値は整数などではなく厳密に `bool` である。

| 入力例 | 期待値 | 検証する境界 |
| --- | --- | --- |
| `INV-000101-0001`、`INV-999912-9999` | `True` | 年・月・連番の両端 |
| `INV-000001-0001`、`INV-202600-0001`、`INV-202613-0001` | `False` | 年 `0000`、月 `00`・`13` |
| `INV-202601-0000`、`INV-202601-001`、`INV-202601-10000` | `False` | 連番ゼロ・桁数違い |
| `ABC-202601-0001`、`INV_202601-0001`、`INV-２０２６０１-0001` | `False` | 接頭辞、区切り、ASCII 数字 |
| `inv-202601-0001`、`" INV-202601-0001 "`、`"INV-202601-0001\n"` | `False` | 小文字、前後空白、末尾改行 |
| `""`、`None`、`123` | `False` | 空文字列、文字列以外の入力 |
