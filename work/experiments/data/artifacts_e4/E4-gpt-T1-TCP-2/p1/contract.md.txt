# Task Contract 案 — `monthly_sales(path)`

## Outcome

`solution.py` の `monthly_sales(path)` が、指定された CSV の税込売上額を暦月ごとに合計し、`{"YYYY-MM": 金額(int)}` を返す。以下は契約案であり、この段階では実装しない。

## Scope・Out of scope

- 対象: 指定された単一 CSV の読み込み、対象行の選定、集計タイムゾーンへの変換、月別の整数合計、欠けた月の扱い。
- 対象外: 税額の再計算、通貨換算、注文の突合・重複排除、製品別などの集計、CLI やレポート出力。

## Data sources

- `sales.csv` — ヘッダーは `order_id,ordered_at,amount_incl_tax,status`。`ordered_at` を月の判定に、`amount_incl_tax` を合計に、`status` を対象行の判定に使う。`order_id` は行の識別にのみ使う。

## Constraints

- 入力の金額と同じ単位で整数を合計し、換算・丸めはしない。入力ファイルは変更しない。
- 仕様確認段階の作成・変更は `contract.md` と `timing.txt` のみ。実装と実装後の検証は契約確定後に行う。

## Definition of Done

- `solution.py` から `monthly_sales` をインポートでき、渡したパスの CSV を読み込む。戻り値のキーはゼロ埋めされた `YYYY-MM` の文字列、値は `int`。辞書の反復順は要件に含めない。
- 推奨案（Q1-A / Q2-A / Q3-A）では、同梱の `sales.csv` に対し `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` と完全一致する。対象行がない入力では `{}` を返す。
- 推奨案での個別確認: `A-1004` は 2 月、`A-1010` は 5 月。`A-1003` と `A-1007` は除外し、`A-1006` の `-1100` は 2 月から差し引く。3 月のキーは作らない。
- 代替案が選ばれた場合は該当の期待値を更新する。ほかの条件を推奨案のままにすると、Q1-B は `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}`、Q2-B は 2 月が `12100`、Q2-C は 1 月が `38500`・2 月が `15400`、Q2-D は 1 月が `38500`・2 月が `16500`、Q3-B は `"2026-03": 0` が加わる。
- 必須列がない CSV、または集計対象行に不正な日時・金額がある CSV は、部分集計を返さず `ValueError` を送出する。

## Evidence — 確認できた事実

- 作業開始時のディレクトリ調査で、時刻追記後に確認できたのは `sales.csv` と `timing.txt` のみ。`solution.py`、テスト、追加の仕様書はなかった。
- `sales.csv` はデータ 10 行。`ordered_at` は全行で `YYYY-MM-DDTHH:MM:SSZ`（UTC）。金額は全行が整数表記。通貨名・金額の単位は記載されていない。
- `completed` は 8 行で、そのうち `A-1006` は `-1100`。`cancelled` は 2 行で、金額はいずれも正（`22000`、`4400`）。負額の理由は記載されていない。
- `A-1004` の `2026-01-31T16:20:00Z` は JST で 2 月 1 日 01:20、`A-1010` の `2026-04-30T15:30:00Z` は JST で 5 月 1 日 00:30。UTC・JST ともに 3 月の行がない。

## Open questions

### 不足情報 — 確認したい 3 点

**Q1. どのタイムゾーンの暦月で締めますか？**

- **A（推奨）:** JST（UTC+09:00 固定）に変換後の年月で集計する。日本国内向けの月次報告を想定した案。
- **B:** 変換せず UTC（UTC+00:00）の年月で集計する。
- どちらでもなければ、具体的なタイムゾーン名（例: `America/New_York`）または UTC オフセットを指定してください。

**Q2. どの行の金額を売上に算入しますか？**

- **A（推奨）:** `status == "completed"` の行のみ、負額も符号どおり合算する（`A-1006` の `-1100` は差し引く）。
- **B:** `status == "completed"` かつ `amount_incl_tax >= 0` の行のみ合算する。
- **C:** `status` によらず全行について、負額も符号どおり合算する。
- **D:** `status` によらず `amount_incl_tax >= 0` の行のみ合算する。
- いずれでもなければ、対象にする `status` の値と、負額を加算・除外・その他のどの方法で処理するかを具体的に指定してください。

**Q3. 集計対象行が 0 件の月をどう返しますか？**

- **A（推奨）:** 集計対象行が 1 件以上ある月だけを返す。行があって合計が 0 の月は残す。
- **B:** 集計対象行の最初の月から最後の月まで（両端を含む）の全暦月を返し、行がない月は整数 `0`。対象行がまったくなければ `{}`。
- いずれでもなければ、含める期間の開始月・終了月（`YYYY-MM` または決め方）と、行がない月の値を具体的に指定してください。

### 仮定 — 質問にしない点

- この仮定で進めます: カンマ区切り・ヘッダー付きの UTF-8 CSV（BOM は許容）とし、日時はサンプルと同じ UTC の `YYYY-MM-DDTHH:MM:SSZ` を受け付ける。`ordered_at`、`amount_incl_tax`、`status` は必須列とし、列順は問わない。
- この仮定で進めます: 行単位で計上し、`order_id` が同じでも重複排除しない。`completed` 指定時は文字列の完全一致とする。
- この仮定で進めます: 必須列の欠落や対象行の不正日時・非整数の金額は `ValueError`、ファイルが開けない場合は元の I/O 例外を送出する。ヘッダーはあるが対象行がない場合は `{}`。
