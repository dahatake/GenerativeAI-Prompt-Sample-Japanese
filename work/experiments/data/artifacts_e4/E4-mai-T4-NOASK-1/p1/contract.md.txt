# Task Contract（Spec Mode）

## 確認できた事実
- 作業ディレクトリには `shifts.csv` と `timing.txt` がある。
- `shifts.csv` は 224 bytes で、ヘッダーは `employee,date,type,start,end`。
- サンプル行は合計 6 行で、従業員は E001・E002・E003。
- `type=work` の行は開始時刻と終了時刻を持つ。
- `type=paid_leave` の行は開始時刻・終了時刻が空欄で、実働行ではない。
- E002 は `22:00`〜`06:00` の夜間勤務行を含む。
- データはすべて 2026-10 の日付。
- 現時点で `solution.py` はまだ存在しない。

## 仮定
- `monthly_work_hours(path)` は、指定 CSV 全体を対象に従業員ごとの実働時間を合計する。月キーや期間引数を返す API はないため、戻り値は `{従業員ID: 合計時間}` とする。
- CSV は標準のヘッダー名を持つ。
- `work` は実働時間の対象行、他の `type` は原則として実働時間に含めない。
- 終了時刻が開始時刻以前なら、翌日終了とみなす（例: 22:00〜06:00 は 8 時間）。
- 不正な時刻や必須値欠落は、暗黙に推測せず検証時に問題として扱う。

## 不足情報
- CSV が複数月をまたぐ場合、署名に月指定がないので「何月分を集計するか」は不明。
- 夜間勤務を跨ぎ日の扱いと、開始・終了が等しい場合の扱いが未確定。
- `work`以外の勤務種別や不正行をどのように処理するかが未確定。
- 文字コード、区切り記号、時刻形式（例: 24時間超）、小数丸め仕様はサンプルだけでは不明。

## Open questions（実装前に回答が必要な点）
1. 複数月を含む CSV を渡された場合の集計範囲は？
   - 選択肢 A: CSV 全行を合計する（推奨の既定案）。
   - 選択肢 B: 日付ごとに従業員を月別集計するが、戻り値の型を変える。
   - 選択肢 C: 月を引数で指定できる拡張シグネチャにする。
   - 推奨理由: 現在の `monthly_work_hours(path)` という単一引数仕様には A が最も整合する。

2. 夜間勤務で終了時刻が開始時刻より前の場合は？
   - 選択肢 A: 結果が翌日になるため次の日から開始時刻を引く（推奨の既定案）。
   - 選択肢 B: 同日の経過時間として負数になる可能性を許容する。
   - 選択肢 C: 不正行としてエラーまたはスキップする。
   - 推奨理由: サンプルの E002 22:00〜06:00 を 8 時間として計算できる。

3. `type=work` 以外の行はどう扱うか？
   - 選択肢 A: `work` のみ集計し、それ以外はスキップする（推奨の既定案）。
   - 選択肢 B: 有効な開始・終了時刻を持つ全行を集計する。
   - 選択肢 C: `paid_leave` などの有休種別を所定労働時間で換算する。
   - 推奨理由: サンプルの `paid_leave` は時刻がなく実劈働時間ではないため、実労働時間の集計では A が適切。

## Outcome
- 作業ディレクトリ内の `solution.py` に、`monthly_work_hours(path)` を実装するための仕様境界を固定する。

## Scope
- `shifts.csv` 相当の CSV を読み込む。
- 従業員 ID ごとに実働時間を合計し、float の dict を返す。
- 推奨の既定案に従い、`work` 行のみ集計し、夜間跨ぎを補正する。
- 月が混在していても、現仕様ではファイル全体を単一集計対象とする。

## Out of scope
- 月別の戻り値構造への変更。
- 有給休暇や欠勤を労働時間として換算する処理。
- 外部ライブラリの導入。
- `solution.py` と検証用テスト以外の実装変更（この Spec Mode 段階では作成しない）。

## Data sources
- 主データ: 作業ディレクトリ内の `shifts.csv`。
- 入力スキーマ: `employee,date,type,start,end`。
- 時刻は `%H:%M` 相当の 24 時間表記を想定。

## Constraints
- 作業ディレクトリ外のファイルは読まない・書き込まない。
- この Spec Mode 段階では `contract.md` と `timing.txt` 以外を作成・変更しない。
- ユーザーへの質問ツールや対話は使わない。Open questions は契約案として記録する。
- 標準ライブラリのみを使用できる形で実装する。
- 戻り値の従業員キーは文字列として保持し、時間は float とする。

## Definition of Done（検証可能な条件）
- `contract.md` が作成され、確認事実・仮定・不足情報・Open questions・契約項目を含む。
- `timing.txt` の最初と最後に各 1 行ずつ、実行時刻が追記される。
- 次段階で以下を検証できること:
  - サンプルから E001 は 9:00〜18:00 が 9 時間、9:00〜14:50 が 5 時間50分なので合計 14.833333333333334 時間程度。
  - E002 は 22:00〜06:00 が 8 時間、13:00〜19:00 が 6 時間なので合計 14 時間。
  - E003 は 8:30〜17:45 が 9.25 時間。
  - `paid_leave` 行は出力に時間を加算しない。
- 想定外の欠落値や不正時刻については、実装仕様確定後のテストでエラー方針を一貫させる。

## Evidence
- CSV 内容とヘッダー、行数、時刻の記録は本ディレクトリの `shifts.csv` のみ。
- `timing.txt` の初回タイムスタンプは作業開始時刻として記録済み。
- 作業ディレクトリ外のファイル、隠し仕様、参照解答は参照していない。
