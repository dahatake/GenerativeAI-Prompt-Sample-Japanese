# Task Contract（承認済み・Execution Mode）

## Outcome
`solution.py` に `validate_invoice_id(value) -> bool` を実装し、承認された請求書番号仕様に従う判定関数を提供する。

## Scope・Scope内
- `samples.txt` を根拠として番号形式を検証する
- `solution.py` 内に `validate_invoice_id(value)` を実装する
- 戻り値を厳密に Python の `bool` とする
- 入力が文字列でない場合は `False` を返す

## Out of scope
- 請求書番号の重複確認、発行履歴照合、外部API連携
- 番号の採番・正規化・文字列変換
- 日付としての実在性確認
- 作業ディレクトリ外のファイル参照・変更

## Data sources
- `samples.txt`
- 回答：`answers.md`
- サンプル：`INV-202601-0001`、`INV-202601-0002`、`INV-202512-0347`、`INV-202603-1200`

## 確認できた事実
- サンプルはすべて `INV-` で始まり、次に年月、ハイフン、4桁連番の形式
- 年月は西暦4桁と月2桁を連結する
- 連番は4桁

## 承認済み仕様
- 完全一致のみ許可
- 形式：`INV-` + 西暦年4桁 + 月2桁 + `-` + 連番4桁
- 大文字 `INV-` のみ許可、前後空白・小文字・区切り違いは不正
- 年：2020～2099
- 月：01～12
- 連番：0001～9999
- 年・月・連番はASCII数字のみ
- 文字列以外の入力は `False`

## 仮定
- `INV-202603-1200` を含む全ての範囲内サンプルを有効とする
- 日付の実在性（うるう日等）は検証対象外で、年・月の範囲のみ検証する
- 正規表現は完全一致し、Unicode数字ではなくASCII数字 `[0-9]` を使用する

## Constraints
- 依存ライブラリを追加しない
- 標準ライブラリまたは組込み機能のみ使用する
- 作業ディレクトリ外のファイルを読まない・書かない

## Definition of Done（検証できる条件）
- `solution.py` をインポートできる
- モジュール内に `validate_invoice_id(value)` が存在する
- 戻り値が常に `bool` 型である
- `samples.txt` の番号例4件すべてが `True` になる
- 有効範囲内の形式 `INV-202603-1200` は `True` になる
- 小文字、前後空白、桁不足・桁超過、ハイフン欠落、月00または13、連番0000、年2019または2100、非数値文字を含む値は `False` になる
- `None`、整数、リストなど文字列以外の入力は `False` になる

## Evidence
- 実行する自己検証テスト：`test_validate_invoice_id.py`
- テスト結果と実行コマンドは `report.md` に記録する

## Open questions
- なし。回答の具体的な仕様が揃っているため、追加確認は不要。
