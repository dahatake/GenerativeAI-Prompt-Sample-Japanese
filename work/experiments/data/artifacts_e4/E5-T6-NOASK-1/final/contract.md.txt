# Task Contract（確定版）: 月次請求書生成 `make_invoices(data_dir, month)`

ステータス: **確定・承認済み（Execution Mode, 2026-11-25）**。質問 Q1〜Q3 への回答は得られなかったため、指示に従い**すべて推奨既定案で確定**しました。

### 確定ルール（Q1〜Q3 の採用結果）
- Q1 → (a) `ordered_at` を JST（Asia/Tokyo）に変換し、月の判定と価格適用日の判定を行う。
- Q2 → (a) `completed` と `shipped` を請求対象とする。`cancelled` と `returned` は除外する。
- Q3 → 推奨既定案:
  - 値引き: gold は `floor(subtotal × 5 / 100)`、standard は 0。
  - 税率: food 8%、general 10%（それ以外の category は `ValueError`）。
  - 値引きの按分: 8% 対象分 = `floor(discount × 8%対象小計 / subtotal)`、残りは 10% 対象分（10% 対象がなければ全額 8% 対象。式から自動的にそうなる）。
  - 税: 請求書ごと・税率ごとに `floor((税率別小計 − 按分値引き) × 税率)` を計算し、tax はその合計。
  - `total = subtotal − discount + tax`。
- 仮定 A1〜A9 もそのまま採用する。

## 1. 調査結果

作業ディレクトリにあるもの: `data/` 配下の CSV 4 ファイルと `timing.txt` だけです。`solution.py`、既存コード、テスト、仕様書はありません。

### 確認できた事実（data/ の中身から）

| ファイル | 列 | 内容 |
|---|---|---|
| customers.csv | customer_id, name, tier | 5件（C001〜C005）。並びはID順ではない。tier は `gold`（C001, C003）と `standard`（C002, C004, C005） |
| products.csv | sku, name, category | 4件。category は `general`（A100, A200）と `food`（F100, F200） |
| prices.csv | sku, effective_from, unit_price | 6件。SKU ごとの価格履歴。A100 は 1200 → **1300（2026-10-16 から）**、F100 は 1580 → **1680（2026-10-10 から）**。A200=2980、F200=540 は変更なし。すべて整数（円） |
| orders.csv | order_id, customer_id, ordered_at, sku, qty, status | 24件。並びは順不同。1注文 = 1 SKU。`ordered_at` は **UTC（末尾 `Z`）の ISO 8601**。status は `completed` / `shipped` / `returned` / `cancelled` の4種類 |

- 文字コードは UTF-8（BOM なし）、改行は CRLF。顧客名と商品名に日本語が入っています。
- 注文日は 2026-09-28〜2026-11-03 にまたがっています。データ上の中心は 2026-10 です。
- **基準のタイムゾーンで結果が変わる注文**（UTC → JST +9h）:
  - O1002 `2026-09-30T15:30Z`: JST では **10/01**。9月か10月かが変わる。
  - O1021 `2026-10-31T16:00Z`: JST では **11/01**。10月か11月かが変わる。
  - O1008 `2026-10-09T15:10Z`: JST では **10/10**。F100 の単価が 1580 か 1680 かが変わる。
  - O1012 `2026-10-15T15:20Z`: JST では **10/16**。A100 の単価が 1200 か 1300 かが変わる。
  - O1022 `2026-10-31T14:50Z`: JST でも 10/31 23:50 なので影響なし（境界ぎりぎりの確認用）。
- 値引きのルール、税率、端数処理、請求書番号の形式は、**データにも作業ディレクトリにも書かれていません**。
- 値引きと関係しそうな属性は `tier`（gold/standard）です。税率と関係しそうな属性は `category`（food/general）です。食品は軽減税率 8%、それ以外は標準税率 10% という区分に見えます。

### 仮定（質問で覆らない限り、この前提で実装します）

- A1. 単価は「注文日時点で有効な価格」とします。具体的には、その SKU の価格のうち `effective_from <= 注文日` を満たす最新のものです。注文日は Q1 で決めるタイムゾーンで数えます。
- A2. 請求書は「顧客 × 月」につき1枚です。対象月に請求対象の注文がない顧客には請求書を作りません（0円の請求書は作りません）。
- A3. `amount = unit_price × qty` とします。`subtotal` は lines の amount の合計です（税抜、値引き前）。
- A4. `total = subtotal - discount + tax` とします。
- A5. `invoice_id` は `INV-YYYYMM-<customer_id>`（例: `INV-202610-C001`）とします。同じ入力からは常に同じ ID になります。
- A6. 請求書は customer_id の昇順に返します。lines は ordered_at の昇順、同時刻なら order_id の昇順に並べます。
- A7. CSV 出力は UTF-8（BOM なし）でヘッダー行を付けます。列は `invoice_id,customer_id,subtotal,discount,tax,total`、行の順番は A6 と同じです。
- A8. 次の場合は黙って読み飛ばさず、例外（`ValueError`）にします。存在しない customer_id や sku を参照している注文、注文日時点で有効な価格がない SKU、`month` の形式が `YYYY-MM` でない場合です。
- A9. 外部ライブラリは使わず、Python 標準ライブラリ（csv, datetime, zoneinfo など）だけで実装します。

### 不足している情報

- F1. 月の区切りと価格適用日をどのタイムゾーンで判定するか → **Q1**
- F2. どの status を請求対象にするか（特に `returned` の扱い） → **Q2**
- F3. 値引きのルール（対象、率、計算の基準）、税率、端数処理、値引きと税の計算順 → **Q3**
- F4. invoice_id の正式な形式、CSV の文字コードや改行コード → 影響が小さいので A5 と A7 で仮置きします（後から変更しやすい部分です）

## 2. 質問（最大3問。外れると手戻りが大きいものだけ）

### Q1. 「月」と「価格の適用日」はどのタイムゾーンで判定しますか？
対象月に入る注文と単価が変わるので、全請求書の金額に影響します（上の4注文）。
- (a) **JST（Asia/Tokyo）に変換してから日付を判定する** ← **推奨既定案**（国内の円建て請求で、取引日は日本時間で数えるのが自然なため）
- (b) UTC の日付をそのまま使う
- (c) その他（指定してください）

### Q2. どの status の注文を請求に含めますか？
- (a) **`completed` と `shipped` を請求し、`cancelled` と `returned` は除外する** ← **推奨既定案**
- (b) `completed` だけを請求する（出荷済みでも未完了は翌月以降に回す）
- (c) `returned` はマイナス行（返金）として計上する。返品の発生月も指定してください

### Q3. 値引き・消費税・端数処理のルールを教えてください。
値引きのルールはデータからは推測できません。推奨案のとおり進めた場合、外れると金額がすべて変わります。
- **推奨既定案**:
  - 値引き: `tier = gold` の顧客は subtotal の **5%**、`standard` は 0。1円未満は切り捨て
  - 消費税: `food` は **8%**（軽減税率）、`general` は **10%**。**請求書ごと・税率ごと**に、値引き後の金額に対して計算し、1円未満は切り捨て（インボイス制度の「1請求書・税率ごとに1回端数処理」に合わせる）
  - 値引きは税率ごとの小計に按分します（按分の端数は切り捨て、余りは 10% 対象に寄せる）。tax には税率ごとの税額の合計を入れます
- 代替案: (b) 値引きなし（discount=0 固定） / (c) 値引きは税込み額から引く / (d) 率・しきい値・端数処理（四捨五入など）を別途指定する

## 3. Task Contract（確定）

### Outcome
`solution.py` に `make_invoices(data_dir: str, month: str) -> list[dict]` を実装します。指定月（`"YYYY-MM"`）の顧客別請求書を、確定したルールどおりに整数円で返します。あわせて CLI `python solution.py <data_dir> <YYYY-MM> <out.csv>` で請求書一覧を CSV に書き出します。

### Scope
- CSV 4 ファイルの読み込みと、参照の整合性チェック（A8）
- 対象月の注文の抽出（Q1 のタイムゾーン、Q2 の status）
- 注文日時点の単価の決定（A1）
- lines（order_id, sku, qty, unit_price, amount）の生成
- subtotal / discount / tax / total の計算（Q3）
- 請求書 dict のリストを返す（キー: invoice_id, customer_id, lines, subtotal, discount, tax, total）
- CLI と CSV 出力（A7）

### Out of scope
- PDF や帳票レイアウトの生成、顧客名と住所の印字
- 複数月をまとめた処理、前月繰越、入金消込
- データの修正や正規化（不正データはエラーにするだけ）
- 外部ライブラリの導入、`data/` 内ファイルの変更

### Data sources
- `<data_dir>/customers.csv`, `products.csv`, `prices.csv`, `orders.csv`（UTF-8、ヘッダー付き。列構成は上の表のとおり）
- 上記以外のデータソースはありません

### Constraints
- 金額はすべて `int`（float を経由しない整数演算で計算する）
- Python 標準ライブラリのみ使用
- 作業ディレクトリ外のファイルは読み書きしない
- 同じ入力からは常に同じ出力（ID と並び順を含む）

### Definition of Done（検証できる条件）
1. `make_invoices("data", "2026-10")` が例外なく終わり、各要素が必要なキーをすべて持ち、金額がすべて `int` である。
2. すべての請求書で `subtotal == sum(line.amount)`、`amount == unit_price * qty`、`total == subtotal - discount + tax` が成り立つ。
3. 境界ケースが確定したルールどおりに処理される: O1002 / O1021 の月の判定（Q1）、O1008 / O1012 の単価（Q1 + A1）、cancelled / returned の扱い（Q2）。
4. 2026-10 の全請求書の金額が、確定ルールで手計算した期待値と完全に一致する。gold と standard の両方、food と general の混在を含めて確認する。
5. 2026-09 と 2026-11 を指定した場合も正しく動く（境界の注文が漏れたり重複したりしない）。対象の注文がない月は空リストを返す。
6. 不正入力（`2026-13`、`202610`、存在しない sku など）で `ValueError` が発生する。
7. `python solution.py data 2026-10 out.csv` で、ヘッダーと請求書数ぶんの行を持つ CSV ができ、値が関数の戻り値と一致する。
8. 上の 1〜7 を確認する自動テスト（標準の `unittest`）がすべて通る。
