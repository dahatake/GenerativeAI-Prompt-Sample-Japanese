# Task Contract：請求書番号の判定（承認済み・Execution Mode）

ユーザーの指示により、個別の回答に代えて Q1〜Q3 の推奨既定案を採用する。

## 確認できた事実

- 依頼は `solution.py` に `validate_invoice_id(value)` を実装し、`bool` を返すこと。
- `samples.txt` は最近の発行例として `INV-202601-0001`、`INV-202601-0002`、`INV-202512-0347`、`INV-202603-1200` を挙げている。4件とも `INV-`、ASCII 数字6桁、ハイフン、ASCII 数字4桁の並びで、不正例は示されていない。

## 採用した仮定

- 4件はすべて有効例として扱う。文字列を変換せずに `INV-YYYYMM-NNNN` と完全一致することを要求する。`INV-` は大文字、区切りは ASCII のハイフン、数字は ASCII の固定桁とし、前後空白・末尾改行を補正しない。文字列以外（`None`、数値、`bytes` など）は変換せず `False` を返す。
- `YYYYMM` は暦上の年月（年 `0001`〜`9999`、月 `01`〜`12`）、`NNNN` は4桁にゼロ埋めした連番（`0001`〜`9999`）とする。現在日付による制限は設けない。
- 番号そのものの妥当性を判定する。発行済みかどうかは確認せず、サンプルにない番号もルールに合えば受け付ける。

## Outcome

合意したルールに従い、渡された値が有効な請求書番号なら `True`、そうでなければ `False` を返す Python 関数を提供する。

## Scope・Out of scope

- **対象:** `solution.py` に実装し、`test_solution.py` で検証する。結果は `report.md` に記録する。
- **対象外:** 番号の発行、入力の補正、旧形式のサポート、台帳照合、重複確認、他のシステムとの連携。

## Data sources

- 依頼文、推奨既定案で進めるという承認、および `samples.txt`。サンプルは形式の証拠であり、発行済み番号の全件リストではない。
- 不正例と境界値の期待結果は、承認されたルールに基づく。

## Constraints

- 指定ディレクトリの外にある作業ファイルは読み書きしない。開始・終了時刻を `timing.txt` に各1行追記する。
- API は `validate_invoice_id(value)`、戻り値は厳密に `bool` とする。判定は外部依存・ファイル参照・現在時刻に依存しない。

## Definition of Done（検証できる条件）

| ID | 条件 |
| --- | --- |
| D1 | `from solution import validate_invoice_id` が成功し、全検証ケースで例外を出さず、`type(result) is bool` を満たす。 |
| D2 | `samples.txt` の4件がすべて `True`。 |
| D3 | サンプル外の境界例 `INV-000101-0001` と `INV-999912-9999` がともに `True`。 |
| D4 | 月 `00`・`13`、年 `0000`、連番 `0000` は `False`。 |
| D5 | 桁不足・桁超過、区切り違い、小文字、全角数字、前後の空白や末尾改行、空文字は `False`。 |
| D6 | 文字列以外の入力は変換せず `False`。 |

## Evidence

`test_solution.py` を実行し、各入力の期待値と実測値、実行コマンド、出力、および各 DoD の状態を `report.md` に記録する。

## Open questions

未決事項なし。Q1 は ASCII の固定形式への厳密一致、Q2 は年月と連番の範囲検査（現在日付による制限なし）、Q3 は台帳照合なしで確定した。
