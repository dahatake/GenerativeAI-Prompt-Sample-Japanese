# Task Contract 案：売上の月次集計

## Outcome
合意後、`solution.py` に `monthly_sales(path)` を実装する。指定されたCSVの集計対象行を暦月ごとに合計し、`{"YYYY-MM": 金額(int)}` の `dict` を返す。この段階では実装しない。

## Scope・Out of scope
- 対象：ヘッダー付きCSVから `ordered_at`、`amount_incl_tax`、`status` を読み取り、合意した月境界・対象ステータス・欠けた月の扱いで税込金額を集計する。
- 対象外：税額の再計算、通貨換算、注文IDによる重複排除、CLIやファイルへの集計結果の出力。

## Data sources
### 確認できた事実
- 作業開始時に確認した入力は `sales.csv` のみ。既存の `solution.py`、テスト、業務仕様書はない。
- `sales.csv` はカンマ区切りで、ヘッダーは `order_id,ordered_at,amount_incl_tax,status`。データは10行で、全バイトがASCIIの範囲にある。
- `ordered_at` は全行 `Z` 付き（UTC）。`amount_incl_tax` は全行で整数表記。`completed` が8行、`cancelled` が2行で、`completed` の `A-1006` に `-1100` がある。通貨名は記載されていない。
- `A-1004` は UTC の1月末から JST の2月初めに、`A-1010` は UTC の4月末から JST の5月初めに移る。UTC・JSTのどちらで見ても、3月の行がない。

## Constraints
- 今回の読み書きは指定作業ディレクトリ内に限る。今回変更するのは `contract.md` と `timing.txt` のみ。実装と実装テストは合意後に行う。
- 集計値は入力と同じ単位で、丸め・税計算・通貨換算なしの Python `int`。外部ライブラリ不要。出力キーの並び順は契約に含めない。

## Definition of Done
- `from solution import monthly_sales` で読み込め、渡されたパスのCSVを読み取る。戻り値は `dict`、キーは4桁年・2桁月の `YYYY-MM`、値は `int`。
- `sales.csv` に推奨3案を適用した場合、戻り値は厳密に `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}`。回答で別案が選ばれた場合は、下記 Evidence の対応する期待値と欠けた月の規則で検証する。
- 月境界の2件、取消2件、負額1件、3月欠落の扱いが、選択と仮定どおりである。対象行がある月に金額 `100` と `-100` だけがあれば、その月は `0` で残る。
- ヘッダーのみ、またはフィルター適用後に対象が0行なら `{}`。必須列の欠落、不正な日付や金額、未定義のステータスは `ValueError`。検証では少なくともヘッダーのみの入力と非整数金額の入力も確認する。

## Evidence
- `sales.csv` をPython標準ライブラリで読み取り、列名・件数と、タイムゾーンおよびステータス条件ごとの合計を確認した。以下は3月を補完しない場合の値。Q3で補完を選ぶ場合は各行の結果に `"2026-03": 0` を加える。

| 月境界 | 対象ステータス | `sales.csv` の期待値 |
| --- | --- | --- |
| JST | `completed` のみ | `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` |
| UTC | `completed` のみ | `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}` |
| JST | `completed` と `cancelled` | `{"2026-01": 38500, "2026-02": 15400, "2026-04": 18700, "2026-05": 7700}` |
| UTC | `completed` と `cancelled` | `{"2026-01": 41800, "2026-02": 12100, "2026-04": 26400}` |

## Open questions
### 不足情報（要回答）
次の各問について A/B を選んでください。どの選択肢にも当てはまらない場合は、タイムゾーン、対象ステータスの値、補完の開始月・終了月と補完値など、実装できる具体的な値で回答してください。

1. **月の境界はどのタイムゾーンですか？** A（推奨）：UTC+09:00（JST）に変換してから現地暦月で集計。`A-1004` は `2026-02`、`A-1010` は `2026-05`。B：UTC+00:00の暦月で集計。それぞれ `2026-01`、`2026-04`。
2. **どのステータスを集計しますか？** A（推奨）：`completed` のみを加算し、`cancelled` は除外。B：`completed` と `cancelled` の両方を記載額のまま加算し、取消額の符号は反転しない。
3. **集計対象行がない月のキーは必要ですか？** A（推奨）：対象行が存在する月のキーだけ返し、`2026-03` は省略。B：対象行の最初の月から最後の月まで両端を含めて連続したキーを返し、対象行がない月は `0`（実データでは `2026-03`）。その範囲外は補完せず、対象行0件なら `{}`。

### 仮定（質問しない点）
- この仮定で進めます：各対象行の金額を符号付き整数としてそのまま足し、負額は差し引く。`order_id` で行を統合しない。対象行がある月の合計がゼロになってもキーは残す。
- この仮定で進めます：入力はUTF-8のカンマ区切りヘッダー付きCSV（UTF-8 BOMは許容）。集計に必要な3列は列名で特定し、その他の列は集計に使わない。日時は `YYYY-MM-DDTHH:MM:SSZ` の実在するUTC日時、金額は `-?[0-9]+`、ステータスは大文字・小文字を区別して `completed` または `cancelled`。
- この仮定で進めます：必須列の不足や必須値の不正を黙って無視せず、集計対象外の行も含めて `ValueError` とする。有効なヘッダーだけなら `{}` とし、ファイルが開けない場合は通常のI/O例外をそのまま送出する。
