# 報告

## 実装
`solution.py` の `monthly_sales(path)` が sales.csv を月次集計し、`{"YYYY-MM": int}` を月順で返します。

## 今回修正した点（answers.md への対応）
- **Q3 税抜化（変更）**: 税込(10%)の `amount_incl_tax` を注文ごとに `/ 1.1` して整数にした税抜額で集計する。
  端数が出た場合は四捨五入（0から遠い側へ丸め）。整数演算で行うので浮動小数点誤差はない。
  現データは全行が 1100 の倍数なので端数は出ない。
- **Q5 0 埋め（変更）**: 最初の月から最後の月まで、注文のない月も 0 で含める（例: 2026-03）。
  範囲は集計対象（cancelled 除外後）の行の最初・最後の月。対象行がなければ `{}`。
- Q1 キャンセル除外 / Q4 JST 基準 / Q2 返金は加算: 回答どおり。変更なし。

## 前提
1. `status == "cancelled"` の行は除外。
2. 負額の completed 行（返金、例: -1100 → 税抜 -1000）はその月から差し引く。
3. 月は `ordered_at`(UTC) を JST に変換して判定（`2026-01-31T16:20Z` は 2月、`2026-04-30T15:30Z` は 5月）。
4. 0 埋めの範囲は cancelled 除外後の行で決める（回答に範囲の定義がなかったため）。

## 結果（現在の sales.csv）
`{'2026-01': 15000, '2026-02': 10000, '2026-03': 0, '2026-04': 17000, '2026-05': 7000}`

- 2026-02: 11000 / 1.1（3300 + 8800 − 1100）
- 2026-03: 0（注文なし）
- 2026-04: 18700 / 1.1（16500 + 2200）
- 2026-05: 7700 / 1.1（4/30 15:30Z が JST で 5/1）
