## 2. 仮定（既定値で埋める点）

- A1 `unit_price` は**税抜**価格。
- A2 消費税率は category で決める: `general` = 10%、`food` = 8%（軽減税率）。
- A3 税額は**請求書ごと・税率ごとに1回だけ端数処理し、切り捨て**て合計する（インボイス制度に合わせる）。行ごとには端数処理しない。
- A4 値引きは**税抜金額に対して税計算の前**に適用する。値引きは税率グループごとに計算し、グループごとに切り捨てる。`discount` は各グループの値引きの合計。
- A5 `amount = qty × unit_price`。`subtotal = Σ amount`。`total = subtotal − discount + tax`。
- A6 適用する単価は、`effective_from ≤ 注文日` を満たす行のうち最新のもの（`effective_from` 当日から有効）。注文日は Q1 で決めるタイムゾーンで日付に変換する。
- A7 請求書は顧客ごと・月ごとに1通。請求対象の明細がない顧客には請求書を作らない（金額0の請求書も作らない）。
- A8 （回答により変更）`invoice_id` = `INV-{YYYYMM}-{NNNN}`。その月の請求書に customer_id の昇順で 0001 から連番を振る（例: `INV-202610-0001`）。
- A9 並び順: 請求書は customer_id の昇順。lines は注文日時の昇順、同時刻なら order_id の昇順。
- A10 出力 CSV: UTF-8（BOM なし）、ヘッダー行 `invoice_id,customer_id,subtotal,discount,tax,total`、行の並びは A9 と同じ。請求書が0件ならヘッダーだけを出力する。
- A11 異常な入力ではエラーにして止める（黙って飛ばさない）: month が `YYYY-MM` 形式でない、存在しない customer_id / sku を参照している、注文日時点で有効な価格がない。
- A12 標準ライブラリだけで実装する（Python 3.x、追加パッケージなし）。

## 3. 不足情報 → 質問（外れると手戻りが大きいもの、3問）

> どの選択肢にも当てはまらない場合は、**具体的な値**（例: 「UTC+9、価格は UTC 日付で判定」「gold かつ税抜1万円以上で3%、四捨五入」）で回答してください。

### Q1. 月の判定と価格の適用日に使うタイムゾーンは？
影響: 10月分では O1002 と O1021 がどちらの月に入るか、O1008 と O1012 の単価が変わります。C001 の subtotal は 27,180（JST）と 28,780（UTC）、C003 は 20,960（JST）と 16,220（UTC）になります。
- **(A) 推奨: JST（UTC+9）**。`ordered_at` を JST に変換し、その日付で月と価格の両方を判定する。
- (B) UTC。`ordered_at` の日付をそのまま使い、月と価格の両方を判定する。
- (C) 月の判定は JST、価格の適用日は UTC（またはその逆）。どちらをどちらにするかを指定してください。

### Q2. 請求対象にする status は？
- **(A) 推奨: `completed` と `shipped` を請求する**。`returned` と `cancelled` は除外する。
- (B) `completed` だけを請求する（`shipped` は除外する。完了月にも請求しない）。
- (C) `completed` と `shipped` を請求し、`returned` はマイナス明細（qty を負にする）として同じ月に計上する。`cancelled` は除外する。

### Q3. 値引き（discount）のルールは？（データに定義がないので、値で指定してください）
- **(A) 推奨: `gold` の顧客は税抜 subtotal の 5% を値引きする**（A4 のとおり税率グループごとに切り捨て）。`standard` は 0。
- (B) `gold` の顧客は 10% を値引きする（端数処理は A と同じ）。`standard` は 0。
- (C) `gold` の顧客で、税抜 subtotal が 10,000円以上のときだけ 5% を値引きする（端数処理は A と同じ）。それ以外は 0。
- (D) 値引きはしない（全員 `discount = 0`）。

## 4. Task Contract 案

### Outcome
`solution.py` に `make_invoices(data_dir, month)` を実装する。指定した月（`"YYYY-MM"`）の請求書を、顧客ごとに dict のリストとして返す。あわせて、`python solution.py <data_dir> <YYYY-MM> <out.csv>` で請求書一覧の CSV を書き出せるようにする。

### Scope / Out of scope
- Scope:
  - CSV 4種類の読み込み
  - 月の判定（Q1）と、請求対象の注文の抽出（Q2）
  - 価格履歴からの単価決定（A6）
  - 明細・小計・値引き（Q3）・消費税（A2〜A4）・請求額の計算
  - 返り値の構造: 請求書は `invoice_id, customer_id, lines, subtotal, discount, tax, total` を持つ。lines の各行は `order_id, sku, qty, unit_price, amount` を持つ
  - CLI と CSV の出力
- Out of scope:
  - PDF・帳票のレイアウト
  - 顧客名・品名の出力（返り値の構造に含めない）
  - 通貨換算
  - 前月の調整や繰越
  - データベースや外部サービスとの連携
  - 入力 CSV の修正

### Data sources
`<data_dir>/customers.csv`, `products.csv`, `prices.csv`, `orders.csv`（列は §1 のとおり）。これ以外の入力は使わない。

### Constraints
- 金額はすべて `int`（円）。浮動小数点は使わず、整数演算で端数を処理する（例: `x * 8 // 100`）。
- Python 標準ライブラリだけを使う。入力ファイルは変更しない。
- 結果は決定的にする（同じ入力からは同じ順序・同じ値を返す）。
- 作業ディレクトリの外のファイルは読み書きしない。

### Definition of Done（検証できる条件）
1. `make_invoices("data", "2026-10")` が list を返す。各要素は上記7つのキーを持ち、金額はすべて `int`。
2. どの請求書でも次が成り立つ: `amount == qty*unit_price`、`subtotal == Σamount`、`total == subtotal − discount + tax`。
3. 2026-10 の結果は次と一致する（回答した値で再計算済み）:

   | invoice_id | customer_id | subtotal | discount | tax | total |
   |---|---|---|---|---|---|
   | INV-202610-0001 | C001 | 27180 | 1359 | 2351 | 28172 |
   | INV-202610-0002 | C002 | 12560 | 0 | 1124 | 13684 |
   | INV-202610-0003 | C003 | 20960 | 1048 | 1717 | 21629 |
   | INV-202610-0004 | C004 | 10280 | 0 | 994 | 11274 |

   - C005 の請求書は作らない。
   - O1012 の単価は 1300、O1008 の単価は 1680。
   - O1002 は 10月に入り、O1021 は11月に入る。
4. 注文のない月（例: `2026-12`）では空リストを返す。CLI では、ヘッダーだけの CSV を出力する。
5. `python solution.py data 2026-10 out.csv` が終了コード0で終わる。出力される CSV のヘッダーと各行は、DoD 3 の表と一致する。
6. 不正な month（例: `2026-13`、`202610`）を渡すと `ValueError` になる。CLI では引数が足りないとき、使い方を表示して0以外の終了コードで終わる。
