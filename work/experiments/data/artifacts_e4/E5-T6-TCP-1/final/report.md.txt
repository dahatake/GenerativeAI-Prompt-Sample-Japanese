## 採用した仮定・決定の一覧

| ID | 内容 | 出典 |
|---|---|---|
| Q1 | `ordered_at`（UTC）を JST（UTC+9）に変換し、その日付で計上月と価格の適用日の両方を判定する | 回答 |
| Q2 | `completed` と `shipped` を請求する。`returned` と `cancelled` は除外する | 回答 |
| Q3 | gold は税率区分ごとの小計から 5% を値引きし、区分ごとに切り捨てる。standard は 0 | 回答 |
| A1 | `unit_price` は税抜 | 推奨案（回答は「指定なし」） |
| A2 | 税率は general 10%、food 8% | 回答で確定 |
| A3 | 税額は区分ごとに「(区分小計 − 区分値引き) × 税率」を計算して切り捨て、合計する | 回答で確定 |
| A4 | 値引きは税計算の前に、区分ごとに切り捨てる | 回答で確定 |
| A5 | `amount=qty×unit_price`、`total=subtotal−discount+tax`。計算はすべて整数演算 | 契約 |
| A6 | 単価は、`effective_from ≤ 注文日（JST）` を満たす行のうち最新のもの（`effective_from` 当日から有効） | 契約 |
| A7 | 請求対象の明細がない顧客には請求書を作らない | 回答で確定 |
| A8 | `invoice_id = INV-YYYYMM-NNNN`。customer_id の昇順で 0001 から連番を振る | 回答（変更） |
| A9 | 請求書は customer_id の昇順。lines は ordered_at の昇順で、同時刻なら order_id の昇順 | 回答で確定（同時刻の扱いは推奨案） |
| A10 | CSV は UTF-8（BOM なし）でヘッダー付き。0件ならヘッダーだけを出力する | 推奨案（回答は「指定なし」） |
| A11 | 次の場合は `ValueError` にする（CLI では終了コード1）: 不正な month、存在しない customer_id / sku の参照、有効な価格がない。返品・キャンセルの注文はこの検証の対象外（先に除外する） | 推奨案（回答は「指定なし」） |
| A12 | Python 標準ライブラリだけで実装する | 契約 |
