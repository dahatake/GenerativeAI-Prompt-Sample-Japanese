## 2. 確認できた事実 / 仮定 / 不足情報

### 確認できた事実
- F1: 入力は上記 4 CSV（UTF-8、ヘッダー付き、カンマ区切り）。
- F2: 単価は SKU ごとの履歴で、`effective_from` により期間ごとに変わる。
- F3: 注文日時は UTC 表記。月境界・単価切替日付近に UTC/JST で結果が変わる注文が 4 件ある。
- F4: 顧客には `tier`（gold/standard）、商品には `category`（general/food）があり、値引き・税率区分に使う意図が推測される。
- F5: 依頼上の戻り値の形（invoice_id, customer_id, lines[order_id, sku, qty, unit_price, amount], subtotal, discount, tax, total）、金額は整数円、CLI `python solution.py <data_dir> <YYYY-MM> <out.csv>`。

### 仮定（回答がなければこの既定で進める）
- A1: 適用単価 = 注文日（Q1 で決めたタイムゾーンの日付）以前で `effective_from` が最大の行の単価。
- A2: `amount = unit_price × qty`。`subtotal = Σ amount`（税抜）。`total = subtotal − discount + tax`。
- A3: 請求書は「その月に請求対象明細が 1 件以上ある顧客」ごとに 1 枚。対象 0 件の顧客（例: 2026-10 の C005）は請求書を作らない。
- A4: `invoice_id = "INV-{YYYYMM}-{customer_id}"`（例: `INV-202610-C001`）。
- A5: 並び順: 請求書は customer_id 昇順、lines は ordered_at 昇順→order_id 昇順。
- A6: CSV 出力は UTF-8（BOM なし）、ヘッダー `invoice_id,customer_id,subtotal,discount,tax,total`、行順は A5 と同じ。対象 0 件ならヘッダーのみ。
- A7: 標準ライブラリのみ使用（Python 3.x）。
- A8: 不正入力はエラー: `month` が `YYYY-MM` でない → `ValueError`。注文の customer_id/sku がマスタにない、注文日時点の単価がない、未知の status → `ValueError`（黙って捨てない）。
- A9: 戻り値の各金額は Python `int`。

### 不足情報
- N1: 月の判定・単価適用日のタイムゾーン（→ Q1）
- N2: 値引きルール（対象 tier、率、計算基準）、税率、端数処理、計算順序（→ Q2）

## 3. 質問（最大 3 問・手戻りが大きいもののみ）

### Q1. 月の判定と単価の適用日は、どのタイムゾーンの日付で行いますか？
- **(A) JST（Asia/Tokyo, UTC+9）で判定 ← 推奨既定**（円建て・日本企業の請求のため。月判定と単価適用日の両方に適用）
- (B) UTC のまま（`ordered_at` の日付部分）で判定
- (C) 月判定と単価適用日で別々のタイムゾーン（要指定）

影響: O1002・O1021 の帰属月、O1008・O1012 の単価が変わる（上表）。

### Q2. 値引き・消費税の計算ルールはどれですか？
- **(A) 推奨既定:**
  - 値引き: `tier=gold` の顧客は税抜小計の **10%**、standard は 0。
  - 税率: `category=food` は **8%（軽減税率）**、`general` は **10%**。
  - 計算順序と端数: 税率区分ごとに `区分小計 → 区分値引き = floor(区分小計 × 値引率) → 課税標準 = 区分小計 − 区分値引き → 区分税額 = floor(課税標準 × 税率)`。請求書単位・税率ごとに 1 回だけ切り捨て（インボイス制度の端数処理に準拠）。`discount = Σ区分値引き`、`tax = Σ区分税額`。
- (B) 値引き率・税率は (A) と同じだが、値引きは請求書全体で `floor(subtotal × 率)` を計算し、税額は区分ごとに値引き前の小計で計算（値引きは税計算に影響させない）
- (C) 別のルール（値引き率・対象・閾値・税率・端数処理〔切り捨て/四捨五入/切り上げ〕を指定してください）

影響: discount・tax・total の全値。データに根拠がないため、最も手戻りが大きい論点です。

### Q3. どの status の注文を請求対象にしますか？
- **(A) `completed` と `shipped` を請求、`returned` と `cancelled` は除外（明細にも出さない） ← 推奨既定**
- (B) `completed` のみ請求
- (C) `completed`・`shipped` を請求し、`returned` はマイナス明細（返品控除）として計上、`cancelled` は除外

影響: 請求対象の明細・顧客と全金額。

## 4. Task Contract 案

### Outcome
`solution.py` に `make_invoices(data_dir, month)` を実装し、指定月（`"YYYY-MM"`）の顧客別請求書を dict のリストで返す。同ファイルを CLI として実行すると請求書一覧を CSV に出力できる。

### Scope
- `make_invoices(data_dir: str, month: str) -> list[dict]`
  - 請求書 dict: `invoice_id, customer_id, lines, subtotal, discount, tax, total`
  - line dict: `order_id, sku, qty, unit_price, amount`
- 4 CSV の読み込み、月フィルタ（Q1）、status フィルタ（Q3）、履歴単価の解決（A1）、値引き・税計算（Q2）。
- CLI: `python solution.py <data_dir> <YYYY-MM> <out.csv>` → 列 `invoice_id,customer_id,subtotal,discount,tax,total` の CSV を書き出す。引数不足時は使い方を stderr に出して非 0 終了。
- 入力検証とエラー（A8）。

### Out of scope
- PDF/帳票レイアウト、顧客名・商品名の出力、明細 CSV の出力。
- 複数通貨、税率の期間変更、前月繰越・入金消込。
- `data/` の CSV の変更、外部ライブラリの追加。
- テストファイルの追加は当初対象外としていたが、Execution Mode の指示により DoD 検証用の `test_solution.py` を追加する。

### Data sources
- `data/customers.csv`（tier → 値引き判定）
- `data/products.csv`（category → 税率判定、SKU 存在確認）
- `data/prices.csv`（SKU × 有効開始日 → 単価）
- `data/orders.csv`（対象注文の抽出）
- 上記以外のデータソースは使わない。

### Constraints
- 金額はすべて `int`（円）。浮動小数点で丸め誤差を出さない（整数演算 or `Decimal`）。
- Python 標準ライブラリのみ。作業ディレクトリ外を読み書きしない。
- 入力 CSV の行順に依存しない（結果は A5 の順で決定的）。
- 同じ入力に対し常に同じ出力（決定的）。

### Definition of Done（検証可能な条件）
1. `from solution import make_invoices; make_invoices("data", "2026-10")` が例外なく list を返し、各要素が上記 7 キー、各 line が 5 キーを持つ。
2. 全請求書で `amount == unit_price * qty`、`subtotal == Σamount`、`total == subtotal - discount + tax`、全金額が `int`。
3. 各 line の `unit_price` が A1 のルール（Q1 のタイムゾーン）で `prices.csv` から引いた値と一致する（O1008・O1012 で確認）。
4. 帰属月が Q1 に従う（JST 既定なら O1002 は 2026-10 に含まれ、O1021 は 2026-10 に含まれず 2026-11 に含まれる）。
5. status フィルタが Q3 に従う（既定なら O1006・O1010・O1013・O1017 はどの請求書にも出ない。2026-10 に C005 の請求書がない）。
6. discount・tax が Q2 のルールで手計算した値と全請求書で一致する。
7. `python solution.py data 2026-10 out.csv` が終了コード 0 で、`out.csv` のヘッダーと各行が `make_invoices` の結果と一致する。
8. データのない月（例: `2026-08`）は空リスト／ヘッダーのみの CSV。不正な月（例: `2026-13`, `202610`）は `ValueError`（CLI は非 0 終了）。
9. 対象月 2026-09・2026-10・2026-11 すべてで 1〜8 が成り立つ。
