# Task Contract (案) — monthly_sales(path)

## 調べて確認できた事実
- 作業ディレクトリには `sales.csv`（10行＋ヘッダ、UTF-8、CRLF、BOMなし）と `timing.txt` のみ。`solution.py` は未作成。
- 列: `order_id, ordered_at, amount_incl_tax, status`
- `ordered_at` は ISO8601 の **UTC (末尾 Z)**。
- `amount_incl_tax` は列名から **税込** 金額。すべて整数。**負の値が1件**（A-1006: -1100、status=completed。返品/値引きの可能性）。
- `status` は `completed` / `cancelled`（cancelled は3件: A-1003 22000, A-1007 4400 ほか）。
- 月境界をまたぐ行が2件ある（UTC と JST で月が変わる）:
  - A-1004 `2026-01-31T16:20:00Z` → JST では 2026-02-01 01:20（3,300）
  - A-1010 `2026-04-30T15:30:00Z` → JST では 2026-05-01 00:30（7,700）
- 3月には注文が1件もない（月の欠番がある）。

## 仮定（質問にしない。この仮定で進めます）
- 金額は整数円。結果は int。
- 負の金額（A-1006 -1100, completed）は返金として**そのまま合算する**（除外しない）。
- 注文の無い月（2026-03）は**キーを出力しない**（0埋めしない）。
- キーはゼロ埋め `YYYY-MM`。dict の順序は月の昇順。
- 入力は UTF-8、ヘッダ行あり、関数名・引数は `monthly_sales(path)`、標準ライブラリ(csv, datetime)のみ使用。
- 空行・欠損など壊れた行は今回のデータに存在しないため特別扱いしない（想定外の行は例外のまま）。

## 不足情報 → 質問（手戻りが大きい順、最大3問）

**Q1. 月の区切りに使うタイムゾーンは？**
- A) UTC のまま（ordered_at の年月をそのまま使う）
- B) **JST (UTC+9)に変換してから月を決める（推奨）** — 日本の事業の月次締めは通常JST。この場合 A-1004 は 2月、A-1010 は 5月に入る。
- 他の場合は具体的なオフセット（例: UTC+9）で答えてください。

**Q2. 金額は税込のまま集計？税抜に換算？**
- A) **税込 (`amount_incl_tax`) をそのまま合算（推奨）**
- B) 税抜に換算（税率10%、各行 `amount / 1.1` を行ごとに四捨五入して合算）
- C) 税抜に換算（税率10%、月合計を `合計 / 1.1` で1回だけ切り捨て）
- 他の場合は税率・丸め方（行ごと/合計後、切り捨て/四捨五入/切り上げ）を具体的な値で答えてください。

**Q3. `cancelled` の注文の扱いは？**
- A) **除外する（`completed` のみ集計）（推奨）**
- B) 含める（status を見ない）
- 他の場合は、集計対象にする status を具体的に列挙してください。

## Task Contract 案

### Outcome
`solution.py` に `monthly_sales(path)` を実装し、`sales.csv` から月別売上 `{"YYYY-MM": int}` を返す。

### Scope / Out of scope
- Scope: `solution.py` の `monthly_sales` 1関数（必要なら内部ヘルパー）。
- Out of scope: CLI、ファイル出力、グラフ、日付範囲指定、通貨換算、CSV 以外の入力、大規模データ向け最適化、`sales.csv` の変更。

### Data sources
- `sales.csv`（作業ディレクトリ内のみ）。列 `order_id, ordered_at(UTC ISO8601), amount_incl_tax(int), status`。

### Constraints
- Python 標準ライブラリのみ。
- 作業ディレクトリ外のファイルは読み書きしない。
- 戻り値の値は `int`（float や Decimal にしない）。

### Definition of Done（検証できる条件。Q1〜Q3 の既定案を採用した場合の期待値）
- `monthly_sales("sales.csv")` が dict を返し、全値が `int`、キーが `YYYY-MM` 形式。
- 既定案(JST変換・税込・completedのみ・負値合算・空月なし)での期待値:
  - 2026-01: 11000 + 5500 = **16500**
  - 2026-02: 3300 (A-1004) + 8800 − 1100 = **11000**
  - 2026-04: 16500 + 2200 = **18700**
  - 2026-05: **7700** (A-1010)
  - 2026-03 のキーは存在しない
  - ※ Q1=A(UTC)の場合: 01=19800, 02=7700, 04=26400（5月なし）
- 回答が変わった場合は、同じ手順で期待値を再計算して合わせる。
- 月境界の2件(A-1004, A-1010)、cancelled、負値、空月の4点を確認する小テストを手元で実行し、全て合格すること。

### Evidence
- 実装後に `python -c "from solution import monthly_sales; print(monthly_sales('sales.csv'))"` の出力を上記期待値と照合し、結果を最終報告に記載。
- 境界行ごとの所属月と除外行の一覧（行ID→月/除外理由）を報告に添える。

- Q1〜Q3（上記）の回答待ち。未回答なら推奨既定案（JST / 税込 / completedのみ）で進める。
- この仮定で進めます: 負値は合算、空月は出力しない、キー昇順、標準ライブラリのみ、不正行は特別扱いしない。
