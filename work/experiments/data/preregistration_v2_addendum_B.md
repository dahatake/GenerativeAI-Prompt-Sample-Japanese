# 事前登録 v2 追補B: 事後修正の回帰を防ぐ指示の検証（E3-RT）

- 作成: 2026-11-25（実行前）。本ファイルの SHA-256 は、実行前に GitHub の secret gist に記録する。
- 背景: v2 の E3 で、T5-B-POST-1 が修正の過程で、Phase 1 では満たしていた R6（発注点ちょうどでも発注）を失った。ホワイトペーパー v1.1 の 6.3 節で、B-POST の修正プロンプトに回帰を防ぐ1行を追加することを提案したが、これは未検証である。

## 方法

- 出発点: E3-T5-B-POST-1 の Phase 1 の状態（Phase 1 の solution.py と report.md、元のデータ、元の answers.md）を、そのまま6つのサンドボックスに複製する。
- 条件:
  - **CTRL**（3回）: E3 の B-POST の修正プロンプト（`E3_BPOST_phase2.txt`）をそのまま使う。
  - **RT**（3回）: 同じプロンプトに、次の1行を加える。「修正の前に、今の振る舞いのうち回答と矛盾しないものをテストとして固定し、修正後もそのテストが通ることを確かめてください。」
- 被験エージェントは新しいセッションで開始する（Phase 1 の会話の文脈はない）。

## 仮説と指標

- **H14**: RT は CTRL より R6 を保持する回が多い。
- 主要指標: 最終の solution.py の T5 の R6（隠しテスト）。
- 副次指標: T5 の全要件、T5S（28日の境界）、Phase 1 との差分の行数、実働時間。
- 分析: 記述統計と Fisher の正確検定（片側）。n=3 のため、効果の確証ではなく、提案した文面が少なくとも害を与えないことと、方向を確認する。
