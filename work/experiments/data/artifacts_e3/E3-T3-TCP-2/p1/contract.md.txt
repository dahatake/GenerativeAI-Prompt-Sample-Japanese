## 1. 調査結果

### 確認できた事実
- 作業ディレクトリにあるファイルは `samples.txt` だけです（作業開始時点。`timing.txt` は今回作成）。`solution.py`、テスト、README、仕様書はありません。
- `samples.txt` は UTF-8（BOM なし）、改行は CRLF です。内容は次のとおりです。
  ```
  最近発行された請求書番号の例:
  INV-202601-0001
  INV-202601-0002
  INV-202512-0347
  INV-202603-1200
  ```
- 4 件の例は、すべて同じ形に見えます: `INV` + `-` + 6 桁の数字 + `-` + 4 桁の数字（15 文字、ASCII）。
  - 中央の 6 桁は `202601`、`202512`、`202603` で、`YYYYMM`（年 4 桁 + 月 2 桁）と読めます。例の範囲は年 2025〜2026、月 01・03・12 です。
  - 末尾の 4 桁は `0001`、`0002`、`0347`、`1200` で、ゼロ埋めの連番と読めます。年月をまたいでも番号は単調増加ではありません（202512 が 0347、202601 が 0001）。月ごとに番号を振り直している可能性があります。
  - 接頭辞はすべて大文字の `INV` です。前後に空白はありません。
- 正しい例しかありません。**不正な例は 1 件もありません。** そのため、どこまでを不正とするかはサンプルからは決まりません。
- 見出しは「最近発行された」です。過去〜現在の番号だけを想定している可能性はありますが、未来日付を拒否する根拠にはなりません。

### 仮定（質問以外は既定値で進めます）
- 形式は `INV-YYYYMM-NNNN` です。
- 関数は純粋関数で、外部 DB との照合（存在確認・重複確認）は行いません。
- チェックディジットやチェックサムはありません（例から規則を導けないため）。
- Python 3 の標準ライブラリだけを使います。

### 不足情報
- 年月の妥当性（月 01〜12、年の範囲、未来の年月）をどこまで検査するか。→ Q1
- 連番の範囲（`0000` を許すか、5 桁以上を許すか）。→ Q2
- 入力の正規化（前後の空白、大文字小文字、全角文字）と、文字列以外の入力をどう扱うか。→ Q3
- 接頭辞が `INV` 以外になることはあるか（部門別・国別など）。→ 質問しません。`INV` 固定で進めます（Open questions 参照）。

## 2. 質問（最大 3 問）

選択肢のどれにも当てはまらない場合は、**具体的な値**（例: 「年は 2020〜2030」「連番は 0001〜99999」）で答えてください。

### Q1. 年月部分（`YYYYMM`）をどこまで検査しますか？
| 選択肢 | 判定ルール | 例: `INV-202613-0001` | 例: `INV-199912-0001` | 例: `INV-209912-0001` |
|---|---|---|---|---|
| A | 6 桁の数字であることだけを確認する | True | True | True |
| **B（推奨）** | 月 `01`〜`12`、年 `2000`〜`2099` | False | False | True |
| C | B に加えて、実行日の年月より未来なら False（実行日 2026-11 なら `202612` 以降は False） | False | False | False |

- 推奨理由: 月 13 などの明らかな誤入力をはじけます。実行日に依存しないので、テストが再現できます。
- C を選ぶ場合、「今日」はローカルタイムゾーン、JST、UTC のどれで決めるかも指定してください。

### Q2. 連番部分（`NNNN`）の許容範囲はどれですか？
| 選択肢 | 判定ルール | `0000` | `0001` | `9999` | `10000` |
|---|---|---|---|---|---|
| **A（推奨）** | ちょうど 4 桁で `0001`〜`9999` | False | True | True | False |
| B | ちょうど 4 桁で `0000`〜`9999` | True | True | True | False |
| C | 4 桁以上で 1 以上（`0001`〜`9999`、`10000` 以上も許可。5 桁以上は先頭 0 を不許可） | False | True | True | True |

- 推奨理由: 例はすべて 4 桁で、`0001` から始まっています。

### Q3. 入力の正規化と、文字列以外の入力をどう扱いますか？
| 選択肢 | 判定ルール |
|---|---|
| **A（推奨）** | 厳密一致。`str` 以外（`None`、`int`、`bytes` など）は例外を出さずに `False`。前後の空白・末尾の改行・小文字の `inv`・全角文字（`ＩＮＶ－２０２６…`）はすべて `False` |
| B | `str` の前後の空白・改行を `strip()` してから厳密判定。大文字小文字は区別。`str` 以外は `False` |
| C | `strip()` と Unicode NFKC 正規化（全角→半角）をしてから、大文字小文字を区別せずに判定（`inv-202601-0001` は True）。`str` 以外は `False` |
| D | A と同じ判定だが、`str` 以外の入力には `TypeError` を送出する |

- 推奨理由: 「番号が正しいか」の判定なので、表記ゆれを黙って受け入れない方が安全です。正規化が必要なら、呼び出し側で行う方が責務を分けられます。

## 3. Task Contract 案（推奨既定案 Q1=B, Q2=A, Q3=A を前提）

### Outcome
`solution.py` に `validate_invoice_id(value) -> bool` を実装します。`value` が正しい請求書番号なら `True`、それ以外なら `False` を返します。例外は送出しません。

正しい番号の条件（すべて満たすこと）:
- `value` が `str` である。
- 文字列全体が `INV-YYYYMM-NNNN` に完全一致する（ASCII のみ、15 文字、前後の余分な文字なし）。
- `YYYY` は `2000`〜`2099`、`MM` は `01`〜`12`。
- `NNNN` は 4 桁で `0001`〜`9999`。

### Scope
- `solution.py` を新規作成し、`validate_invoice_id` を実装します（必要なら内部用の定数や正規表現も置きます）。

### Out of scope
- 請求書番号の生成や採番。
- DB や台帳との照合（存在確認・重複確認）、連番の連続性チェック。
- チェックディジットの検証。
- 入力の正規化（Q3 で B/C が選ばれた場合は範囲に入れます）。
- 不正な理由を返すこと（戻り値は bool だけです）。
- `samples.txt` の変更。

### Data sources
- `samples.txt`（正しい例 4 件。唯一の仕様根拠）
- この契約への回答（Q1〜Q3）

### Constraints
- Python 3、標準ライブラリだけを使います（`re` など）。
- 作業ディレクトリ内のファイルだけを読み書きします。
- 数字の判定には `[0-9]` を使います（`\d` は全角数字などの Unicode 数字にも一致するため使いません）。
- 文字列全体との一致は `re.fullmatch` で判定します（`$` は末尾の `\n` を許してしまうため使いません）。
- 実行日時に依存しません（Q1=C の場合を除く）。
- 外部 I/O はなく、副作用もありません。
