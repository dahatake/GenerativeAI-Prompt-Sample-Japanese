# reorder_plan 実装メモ

## 実装内容（solution.py）
`reorder_plan(inventory_path, shipments_path, today)` は発注点方式で判定し、`[{"sku", "qty"}]` を sku の昇順で返します。

1. **日販**: `today` の前日までの直近28日間（`today-28日` ≤ date < `today`）の出荷数の合計を 28 で割った値です。出荷がない日は 0 として数えます。
2. **発注点**: 日販 × `lead_time_days` + `safety_stock`。
3. **有効在庫**: `stock` + `on_order`（発注済み・未入荷分を含めます）。
4. 有効在庫が発注点**以下**のときに発注します。発注数は「発注点 − 有効在庫」を `lot` の倍数に切り上げた値で、最低 1 ロットです。
5. `discontinued=true` の品目は発注対象から除外します。

サンプルデータで today=2026-11-10 の場合、結果は `[{"sku": "A100", "qty": 50}]` です（A100 は発注点 41 に対して有効在庫 40）。

## 前提（answers.md の回答を反映済み）
- 需要を見る期間は、today の前日までの直近28日間です（today 当日は含めません）。【Q1 で確定】C400 は 10/10 以降出荷がないため、11/10 時点では需要 0 となり、発注しません。
- 発注量は「発注点 − 有効在庫」を lot の倍数に切り上げた値です。最大在庫や EOQ は使いません。【Q2 で確定】
- 判定は「有効在庫 ≤ 発注点」です（等しい場合も発注）。【Q3 で確定】
- 在庫ファイルにない SKU の出荷は無視します。lot が 0 以下または空の場合は 1 として扱います。【Q4：指定がなかったため推奨案のまま】
- `today` は `date`、`datetime`、`"YYYY-MM-DD"` 文字列のいずれでも受け付けます。CSV は UTF-8（BOM の有無は問いません）を前提にしています。【Q5：指定がなかったため推奨案のまま】
- 出荷データの最終日より後の日付を today にすると、28日の窓の中に出荷のない日が増えるため、日販が低く見積もられます。【Q6：指定がなかったため推奨案のまま】
