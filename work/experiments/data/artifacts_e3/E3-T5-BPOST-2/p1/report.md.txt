# reorder_plan 実装メモ

## 実装内容（solution.py）
`reorder_plan(inventory_path, shipments_path, today)` は発注点方式で判定し、`[{"sku", "qty"}]` を sku の昇順で返します。

1. **日販**: `today` の前日までの直近30日間（`today-30日` ≤ date < `today`）の出荷数の合計を 30 で割った値です。出荷がない日は 0 として数えます。
2. **発注点**: 日販 × `lead_time_days` + `safety_stock`。
3. **有効在庫**: `stock` + `on_order`（発注済み・未入荷分を含めます）。
4. 有効在庫が発注点**以下**のときに発注します。発注数は「発注点 − 有効在庫」を `lot` の倍数に切り上げた値で、最低 1 ロットです。
5. `discontinued=true` の品目は発注対象から除外します。

サンプルデータで today=2026-11-10 の場合、結果は `[{"sku": "A100", "qty": 50}]` です（A100 は発注点 41 に対して有効在庫 40）。

## 前提にしたこと（仕様に明記がないため判断した点）
- 需要を見る期間は直近30日で、today 当日の出荷は集計途中とみなして除外しています。C400 は 10/10 以降出荷がないため、11/10 時点では需要 0 となり、発注しません。
- 発注量は「発注点まで戻す」ための最小ロット数です。補充先を発注点より上に置く方式（最大在庫や EOQ）は採用していません。
- 判定は「有効在庫 ≤ 発注点」です（等しい場合も発注）。
- 在庫ファイルにない SKU の出荷は無視します。lot が 0 以下または空の場合は 1 として扱います。
- `today` は `date`、`datetime`、`"YYYY-MM-DD"` 文字列のいずれでも受け付けます。CSV は UTF-8（BOM の有無は問いません）を前提にしています。
- 出荷データの最終日より後の日付を today にすると、30日の窓の中に出荷のない日が増えるため、日販が低く見積もられます。

期間・判定条件・発注量の決め方に社内ルールがある場合は、それに合わせて調整が必要です。
