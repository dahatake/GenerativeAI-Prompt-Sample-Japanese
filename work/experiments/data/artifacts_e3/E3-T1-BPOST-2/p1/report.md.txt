# monthly_sales 実装レポート

## 実装
- `solution.py` の `monthly_sales(path)` は `sales.csv` を読み込み、`{"YYYY-MM": 金額(int)}` を月の昇順で返します。
- 省略可能なキーワード引数: `tz`（どのタイムゾーンで月を判定するか。既定は JST）、`counted_statuses`（集計対象にする status。既定は `("completed",)`）。
- 実行結果（sales.csv）: `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}`

## 前提（データからは決められなかった点）
1. **タイムゾーン**: `ordered_at` は UTC（`Z` 付き）ですが、月の判定は **JST（UTC+9）** で行いました。金額が円で、消費税10%込みの値なので、日本の事業と判断しました。月末の注文 A-1004・A-1010 は JST だと翌月に入ります。UTC で集計すると `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}` です（`tz=timezone.utc` を指定）。
2. **status**: `completed` の行だけを集計し、`cancelled` は除外しました。
3. **マイナス金額**: 返金・値引きとみなし、差し引いて集計しました（A-1006 の -1100）。
4. **税**: `amount_incl_tax` の税込金額をそのまま使い、税抜きへの換算はしていません。
5. **売上ゼロの月**: 対象の行がない月（例: 2026-03）は結果に含めていません（0 も入れません）。
6. タイムゾーンのない日時は UTC とみなします。金額の桁区切りカンマは取り除きます。

## 確認したいこと
上の 1〜5（特にタイムゾーン、税込か税抜か、売上ゼロの月を 0 として入れるか）が想定と違う場合は教えてください。
