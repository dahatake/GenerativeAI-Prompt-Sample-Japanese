# monthly_sales 実装レポート

## 実装
- `solution.py` の `monthly_sales(path)` は `sales.csv` を読み込み、`{"YYYY-MM": 税抜金額(int)}` を月の昇順で返します。
- 省略可能なキーワード引数: `tz`（どのタイムゾーンで月を判定するか。既定は JST）、`counted_statuses`（集計対象にする status。既定は `("completed",)`）。
- 実行結果（sales.csv）: `{"2026-01": 15000, "2026-02": 10000, "2026-03": 0, "2026-04": 17000, "2026-05": 7000}`

## 前提（answers.md の回答を反映）
1. **タイムゾーン**（Q1 で確認済み）: `ordered_at` は UTC として読み、**JST（UTC+9）** で月を判定します。
2. **status**（Q2 で確認済み）: `cancelled` を除外します。実装では `completed` の行だけを集計しています。
3. **マイナス金額**（Q3 は指定なし。推奨案どおり）: 返金・値引きとみなし、差し引いて集計します。
4. **税**（Q4）: 税込金額を月ごとに合計してから、税抜金額（税込 / 1.1）に換算します。端数は四捨五入し、マイナスの金額では 0 から遠い方へ丸めます。
5. **売上ゼロの月**（Q5）: 最初の注文月から最後の注文月まで、すべての月を返します。対象の注文がない月は 0 です。範囲は cancelled を含む全注文の月から決めます。
6. **その他**（Q6 は指定なし。推奨案どおり）: タイムゾーンのない日時は UTC とみなします。金額の桁区切りカンマは取り除きます。

## 今回修正した点
- 返す金額を税込から**税抜（税込 / 1.1、四捨五入、int）**に変更しました（Q4）。
- 最初の注文月から最後の注文月まで、**注文がない月も 0 として含める**ようにしました（Q5。例: `2026-03: 0`）。
- 上の2点に合わせて、docstring と report.md を更新しました。
- タイムゾーン、status、マイナス金額などの扱い（Q1・Q2・Q3・Q6）は変更していません。

## 新たに残った確認事項
- 税抜への換算は**月の合計に対して1回**行っています。注文ごとに換算して端数処理する方式とは、端数が出る場合に結果が変わることがあります（今回のデータはすべて 1.1 で割り切れるため、結果は同じです）。
- 月の範囲は cancelled を含む全注文で決めています。cancelled の注文しかない月が範囲の端にある場合も、その月は 0 として含まれます。
