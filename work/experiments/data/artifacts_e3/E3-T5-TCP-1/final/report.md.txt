# Report: `reorder_plan` 実装結果

## 確定仕様（contract.md §0）
- 日次平均需要 = `[today−28日, today)` の出荷合計 ÷ 28（Q1=a）
- ROP = 日次平均需要 × lead_time_days + safety_stock（`Fraction` で厳密計算、途中丸めなし）
- 有効在庫 = stock + on_order。`有効在庫 <= ROP` なら発注（Q3=b）
- qty = `ceil((ROP − 有効在庫)/lot) × lot`（Q2=a）。不足0（同値）のときは最低1 lot
- 廃番除外、sku 昇順、qty は int

## 採用した仮定
1. **同値時の発注数 = 1 lot**（Q2 の式では0になるが、Q3=b の「同値でも発注」を優先）— 回答に値がないための推奨既定案。**人間の確認が必要**。
2. today 当日の出荷は集計しない（回答で確認済み）。
3. ROP は丸めず厳密な有理数で比較し、丸めは発注数の lot 切り上げのみ（推奨案）。
4. `discontinued=true`（大文字小文字無視）は除外（回答で確認済み）。
5. 出荷履歴のない品目は需要0、ROP = safety_stock（推奨案）。
6. inventory にない sku の出荷は無視（推奨案）。
7. 出力は発注対象のみ・sku 昇順・qty は int（回答で確認済み）。
8. 不正データ（必須列欠損、数値でない値、負数、不正日付、lot ≤ 0、重複 sku、true/false 以外の discontinued）は `ValueError`（推奨案）。負の出荷数（返品）も不正扱い。
9. `today` は `date` / `datetime`（日付部分）/ `"YYYY-MM-DD"` を受け付ける。CSV は UTF-8（BOM 可）、CRLF/LF 両対応。
