# reorder_plan 実装レポート

## 実装内容（solution.py）
`reorder_plan(inventory_path, shipments_path, today)` は発注点方式で判定します。

1. **日次需要**: `today` の前日までの直近30日（`today-30日 <= date < today`）の出荷数合計 ÷ 30。
2. **発注点** = 日次需要 × `lead_time_days` + `safety_stock`
3. **在庫ポジション** = `stock` + `on_order`（発注済み・未入荷分を含む）
4. **在庫ポジション <= 発注点** なら発注します。発注数は不足分（切り上げ）を `lot` の倍数に切り上げた値で、最低でも1ロットです。
5. `discontinued=true` の品目は除外します。
6. 戻り値は `[{"sku": ..., "qty": int}]` で、sku の昇順に並べます。発注不要の品目は含めません。

サンプルデータ（today=2026-11-10）での結果: `[{"sku": "A100", "qty": 50}]`
- A100: 3個/日×7日+20=41 で、ポジション40が発注点以下 → 不足1個を50個ロットに切り上げて50
- A200: 発注点15に対しポジション45（発注残を含む） → 発注不要
- B300: 廃番のため除外
- C400: 10/10 以降は出荷がなく需要0のため、発注点6に対しポジション12 → 発注不要

## 前提にしたこと（仕様が明示されていないため）
- 需要を集計する期間は直近30日です。当日分は集計途中の可能性があるので除外し、`today` 以降の出荷も無視します。出荷がない日も需要0として30日で割ります。
- 発注量は「発注点まで戻すのに必要な量」をロット単位に切り上げた量です。発注点を上回る目標在庫（最大在庫）は考慮していません。
- 発注判定には実在庫ではなく、発注残を含む在庫ポジションを使います。
- `today` には `date`・`datetime`・"YYYY-MM-DD" 形式の文字列のいずれも渡せます。
- CSV は UTF-8 で読み込みます（BOM付きでも可）。`lot` が0以下の場合は1として扱います。在庫マスタにない sku の出荷は無視します。
