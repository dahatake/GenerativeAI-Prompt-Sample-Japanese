# reorder_plan 実装レポート

## 実装内容（solution.py）
`reorder_plan(inventory_path, shipments_path, today)` は発注点方式で判定します。

1. **日次需要**: `today` の前日までの直近28日（`today-28日 <= date < today`）の出荷数合計 ÷ 28。
2. **発注点** = 日次需要 × `lead_time_days` + `safety_stock`
3. **有効在庫** = `stock` + `on_order`（発注済み・未入荷分を含む）
4. **有効在庫 <= 発注点** なら発注します。発注数は「発注点 − 有効在庫」を `lot` の倍数に切り上げた値で、最低でも1ロットです。
5. `discontinued=true` の品目は除外します。
6. 戻り値は `[{"sku": ..., "qty": int}]` で、sku の昇順に並べます。発注不要の品目は含めません。

サンプルデータ（today=2026-11-10）での結果: `[{"sku": "A100", "qty": 50}]`
- A100: 3個/日×7日+20=41 で、有効在庫40が発注点以下 → 不足1個を50個ロットに切り上げて50
- A200: 発注点15に対し有効在庫45（発注残を含む） → 発注不要
- B300: 廃番のため除外
- C400: 10/10 以降は出荷がなく需要0のため、発注点6に対し有効在庫12 → 発注不要

## 前提・確認結果（answers.md の回答を反映）
- Q1: 需要の集計期間は `today` を含まない前日までの28日間で、出荷数合計を28で割ります（回答により30日から変更）。出荷がない日も需要0として扱い、`today` 以降の出荷は無視します。
- Q2: 発注数は「発注点 − 有効在庫」を lot の倍数に切り上げた値です（回答で確認済み）。最大在庫は考慮しません。有効在庫が発注点とちょうど等しい場合は、従来どおり1ロット発注します。
- Q3: 発注判定には `stock` + `on_order` の有効在庫を使います（回答で確認済み）。
- Q4・Q5: 特に指定がなかったため、推奨案のまま進めています。
- `today` には `date`・`datetime`・"YYYY-MM-DD" 形式の文字列のいずれも渡せます。
- CSV は UTF-8 で読み込みます（BOM付きでも可）。`lot` が0以下の場合は1として扱います。在庫マスタにない sku の出荷は無視します。
