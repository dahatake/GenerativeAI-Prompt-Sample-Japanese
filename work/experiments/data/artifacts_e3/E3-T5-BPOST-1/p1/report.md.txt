# reorder_plan 実装レポート

## 実装内容
`solution.py` の `reorder_plan(inventory_path, shipments_path, today)` は、発注点方式で発注が必要な品目を判定します。

1. 出荷履歴から、`today` の前日までの直近30日間（`today-30日` ～ `today-1日`）の出荷数を品目ごとに合計し、30で割って1日あたり平均需要を出します。出荷がない日は0として扱います。
2. 発注点は `平均需要 × lead_time_days + safety_stock` で計算します。
3. 有効在庫は `stock + on_order` です。
4. 有効在庫が発注点以下の品目を発注対象にします。発注数は不足分（発注点 − 有効在庫）を `lot` の倍数に切り上げた数で、最低でも1ロット発注します。
5. 戻り値は `[{"sku": ..., "qty": int}, ...]` で、sku順に並べています。発注がなければ空リストを返します。

サンプルデータで `today=2026-11-10` を渡すと、結果は `[{"sku": "A100", "qty": 50}]` になります。A100 は発注点41に対して有効在庫40です。

## 前提にしたこと（仕様が明示されていない点）
- `discontinued=true` の品目（B300）は発注しません。
- 需要の算出期間は直近30日です。C400 は10/10以降出荷がないため、現在の需要はないとみなします。
- `today` 当日とそれ以降の出荷は集計に含めません。
- 出荷履歴が30日に満たない場合は、最初の出荷日から `today` までの日数で割ります。
- 在庫ファイルにない sku の出荷は無視します。出荷がない在庫品目は需要0として扱います。
- 目標在庫は発注点までの補充とし、最大在庫や発注サイクルは考慮しません。
- `today` には `date`、`datetime`、ISO形式の文字列（`YYYY-MM-DD`）のどれでも渡せます。
- CSVはUTF-8（BOMの有無は問いません）として読み込みます。
