# Task Contract 案: monthly_work_hours(path)

## 1. 調査結果

作業ディレクトリにあるファイル: `shifts.csv`（224 bytes）だけ。`timing.txt` は計測用です。`solution.py`、テスト、仕様書はまだありません。

`shifts.csv` の内容:

```
employee,date,type,start,end
E001,2026-10-01,work,09:00,18:00
E001,2026-10-02,work,09:00,14:50
E001,2026-10-03,paid_leave,,
E002,2026-10-01,work,22:00,06:00
E002,2026-10-02,work,13:00,19:00
E003,2026-10-01,work,08:30,17:45
```

### 1.1 確認できた事実
- F1: 列は `employee,date,type,start,end` の5列で、ヘッダ行があります。
- F2: エンコーディングは UTF-8/ASCII で BOM はありません。改行は CRLF で、最終行も改行で終わっています。
- F3: `type` の値は `work` と `paid_leave` の2種類です。
- F4: `paid_leave` の行は `start` と `end` が空欄です（E001, 2026-10-03）。
- F5: 日付をまたぐ勤務があります。E002 の 2026-10-01 は `22:00`〜`06:00` で、end < start です。
- F6: 時刻は `HH:MM` 形式で、分単位の端数があります（14:50 や 08:30 / 17:45 など）。
- F7: 休憩時間の列はありません。
- F8: データは 2026年10月分だけです。従業員は E001・E002・E003 の3名です。
- F9: 戻り値は `{従業員ID: 労働時間(時間, float)}` と指定されています。関数の引数は `path` だけで、対象月を指定する引数はありません。

### 1.2 仮定（回答がなければこの内容で進めます）
- A1: 1ファイルが1か月分です。ファイル内の全行を合計し、月の絞り込みはしません。
- A2: end <= start の勤務は翌日終了とみなし、24時間を足して計算します。勤務時間はすべて開始日（`date`）の分として数えます。
- A3: 1つの勤務の長さは 0 より大きく 24 時間未満とします。start == end はエラーにします。
- A4: CSV の読み込みには標準ライブラリの `csv` を使います。pandas などの外部依存は使いません。BOM 付き UTF-8 も読めるように `utf-8-sig` で開きます。
- A5: 出力には、ファイルに1行でも出てくる従業員をすべて含めます。`paid_leave` だけの従業員は 0.0 にします。
- A6: 次の不正データは `ValueError` にします: 未知の `type`、`work` 行の start/end が空欄、時刻の書式エラー、日付の書式エラー、必須列の欠落。
- A7: 空ファイル、またはヘッダ行だけのファイルは `{}` を返します。

### 1.3 不足情報
- M1: 休憩時間を差し引くかどうか、差し引く場合のルール（→ Q1）
- M2: `paid_leave`（とその他の休暇種別）を労働時間に含めるかどうか（→ Q2）
- M3: 端数を丸めるかどうかと、その方法（→ Q3）
- M4: 複数月が混ざったファイルの扱い（→ Open questions。仮定 A1 で進めます）
- M5: 月末をまたぐ夜勤を開始日側と終了日側のどちらの月に入れるか（→ Open questions。仮定 A2 で進めます）

## 2. 質問（最大3問。外れると手戻りが大きいものだけ）

### Q1. 休憩時間の控除
データに休憩の列がありません。どちらを選ぶかで、ほぼ全員の数値が変わります。
- **(A) 控除しない。終了時刻−開始時刻をそのまま労働時間にする** ← **推奨（既定案）**
  - 理由: データに根拠のない控除を入れずに済み、結果を説明しやすいためです。
- (B) 法定の最低休憩を自動で引く。6時間を超えたら45分、8時間を超えたら60分を引きます（境界の「ちょうど」は超えないものとして扱います）。
- (C) 一律に固定値（例: 60分）を引く。値を指定してください。

### Q2. `paid_leave`（有給休暇）の扱い
- **(A) 労働時間に含めない（0時間）。`work` だけを合計する** ← **推奨（既定案）**
  - 理由: 名前が「労働時間」で、有休には時刻情報もないためです。
- (B) 1日あたりの所定時間（例: 8.0h）として加算する。時間数を指定してください。
- (C) A に加えて、`work` と `paid_leave` 以外の type はエラーにせず無視する（既定案ではエラーにします。A6 参照）。

### Q3. 端数の丸め
例: E001 の合計は 14.8333…h です。
- **(A) 丸めない。分単位で正確に計算した float を返す（14.833333…）** ← **推奨（既定案）**
  - 理由: 情報が失われず、表示側で自由に丸められるためです。
- (B) 合計を小数第2位で丸める（`round(x, 2)` で 14.83）。
- (C) 勤務ごとに15分単位で切り捨ててから合計する（勤怠の慣行に合わせる場合）。

### 既定案（A/A/A）を選んだときに shifts.csv から出る期待値
| 従業員 | 計算 | 結果 |
|---|---|---|
| E001 | 9:00 + 5:50（有休は 0） | 14.833333… |
| E002 | 8:00（夜勤、日付をまたぐ）+ 6:00 | 14.0 |
| E003 | 9:15 | 9.25 |

参考として、Q1=(B) を選んだ場合は E001=13.8333…、E002=13.25、E003=8.25 になります。

## 3. Task Contract 案

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装します。勤怠 CSV を読み、従業員IDごとの月間労働時間（単位は時間、float）を返します。

### Scope
- `solution.py` を新しく作り、`monthly_work_hours(path)` を実装する。
- CSV を読み込み、行ごとに検証する。
- 日付をまたぐ勤務を正しく計算する。
- Q1〜Q3 で決まった休憩・休暇・丸めのルールを適用する。
- 不正データのときに `ValueError` を出す（A6）。

### Out of scope
- 休憩列・残業・深夜割増・法定労働時間超過の判定（Q1 で B/C を選んだ場合の控除を除く）
- 月の指定・絞り込み・複数月の分割集計（A1）
- タイムゾーン・夏時間の考慮
- CLI、ファイル出力、外部ライブラリの導入
- `shifts.csv` の修正

### Data sources
- 入力: 引数 `path` で指定する CSV。サンプルは作業ディレクトリの `shifts.csv`（列は F1、形式は F2〜F6 のとおり）。
- このほかのデータソースはありません。作業ディレクトリの外は参照しません。

### Constraints
- Python 3 の標準ライブラリだけを使う（`csv`, `datetime`）。
- 関数シグネチャは `monthly_work_hours(path)` に固定し、戻り値は `dict[str, float]` にする。
- 作業ディレクトリの外のファイルは読み書きしない。
- 入力ファイルは変更しない（読み取り専用）。

### Definition of Done（検証できる条件）
1. `solution.py` が存在し、`from solution import monthly_work_hours` が成功する。
2. `monthly_work_hours("shifts.csv")` が、合意したルールの期待値と一致する。既定案 A/A/A の場合は `{"E001": 14.8333…, "E002": 14.0, "E003": 9.25}` で、許容誤差は 1e-9 とする。
3. 戻り値のキーがすべて `str`、値がすべて `float`（`int` ではない）である。
4. 日付をまたぐ勤務（例: 22:00→06:00）が 8.0h になる。
5. `paid_leave` 行が Q2 で決めたルールどおりに扱われる。
6. ヘッダ行だけの CSV が `{}` を返す。
7. 未知の type、`work` 行の時刻欠落、時刻の書式エラー（例: `25:00`、`9-00`）、start == end のどれでも `ValueError` になる。
8. BOM 付き UTF-8、LF 改行、CRLF 改行のどれでも同じ結果になる。
9. 上の 2〜8 を一時的な検証スクリプトで確認する。検証用ファイルは作業ディレクトリ内に作り、終わったら削除する。

### Evidence（完了報告に含めるもの）
- `monthly_work_hours("shifts.csv")` の実際の出力
- DoD 2〜8 の各ケースの実行結果（入力・期待値・実際の値・合否）
- 採用したルール（Q1〜Q3 の回答、仮定 A1〜A7）の一覧
- `timing.txt` に記録した開始時刻と終了時刻

### Open questions
- Q1〜Q3（上記）。回答がない場合は既定案 A/A/A で進めます。
- OQ4: 複数月が混ざったファイルを渡されたとき、全行を合計するか（既定）、`ValueError` にするか。シグネチャに月の引数がないため、既定は全行の合計とします。
- OQ5: 月末をまたぐ夜勤（例: 10/31 22:00→11/01 06:00）を開始日の月にすべて入れるか（既定）、月の境界で分けるか。
- OQ6: 従業員IDの前後の空白や大文字・小文字を正規化するか。既定は前後の空白だけを除き、大文字・小文字は区別します。
- OQ7: 同じ従業員の同じ日に、時間帯が重なる勤務が複数あったときの扱い。既定は重複を検出せず、単純に合計します。
