## 1. 確認できた事実（作業ディレクトリ内のファイルから）

作業ディレクトリにある入力データは `inventory.csv` と `shipments.csv` の2つです。仕様の回答は `answers.md` にあります。`solution.py` と既存のテストはありません。

### inventory.csv（4行、UTF-8、ヘッダーあり）
| sku | stock | on_order | lead_time_days | safety_stock | lot | discontinued |
|---|---|---|---|---|---|---|
| A100 | 40 | 0 | 7 | 20 | 50 | false |
| A200 | 15 | 30 | 5 | 10 | 20 | false |
| B300 | 5 | 0 | 10 | 5 | 100 | true |
| C400 | 12 | 0 | 14 | 6 | 10 | false |

### shipments.csv（70行、列は `date,sku,qty`、日付は ISO 形式）
| SKU | 行数 | 合計 | 期間 | パターン |
|---|---|---|---|---|
| A100 | 40 | 120 | 2026-10-01〜2026-11-09 | 毎日 3 |
| A200 | 20 | 40 | 2026-10-01〜2026-11-08 | 1日おきに 2 |
| C400 | 10 | 50 | 2026-10-01〜2026-10-10 | 毎日 5 |
| B300 | 0 | 0 | — | 出荷なし |

## 2. 確定した仕様（answers.md の回答）
- **Q1 日次需要**: `today-28 ≤ date < today` の出荷数の合計を 28 で割る。today 当日は含めない。記録のない日は出荷0として数える。
- **Q2 発注の条件と数量**: 有効在庫 = `stock + on_order`、発注点（ROP）= `日次需要 × lead_time_days + safety_stock`。`有効在庫 <= ROP` なら発注対象。発注数は `ROP − 有効在庫` を lot の倍数に切り上げた値。
- **Q3 廃番品**: `discontinued=true` の品目は常に対象から外す。
- **補足（データの終端）**: 集計期間は today の前日で終える（データの最終日には合わせない）。記録のない日は出荷0とする。

## 3. 採用した仮定（回答で「指定なし」となった A1〜A9 と、解釈が必要だった点）
- A1. Python 3 の標準ライブラリだけを使う。
- A2. `today` は `datetime.date`、`datetime.datetime`、`"YYYY-MM-DD"` 文字列のどれでも受け付ける。
- A3. 有効在庫は `stock + on_order` とする（Q2 で確定）。
- A4. ROP は小数のまま比較する。浮動小数の誤差を避けるため、`fractions.Fraction` で正確に計算する。
- A5. 発注数は `ceil(不足量 / lot) × lot` とする。
- A6. 戻り値は発注数が 0 より大きい品目だけで、`sku` の昇順に並べる。`qty` は `int`。
- A7. today 当日と、それより後の出荷行は使わない（Q1 で確定）。
- A8. inventory にない SKU の出荷行は無視する。
- A9. CSV は UTF-8 で読み、BOM が付いていても扱える。`discontinued` は前後の空白を除き、大文字・小文字を区別せずに `"true"` と一致するかで判定する。
- **A10（解釈）**: `有効在庫 == ROP` のときは不足量が 0 なので、式どおりだと発注数も 0 になる。回答では「発注対象にする」とあるため、このときは **1 lot** を発注する。これは前回の契約案で示した選択肢 Q2(b)「ちょうど ROP のときは 1 lot 発注する」に合わせた解釈。→ 人間の確認が必要。

## 4. Task Contract

### Outcome
`solution.py` の `reorder_plan(inventory_path, shipments_path, today)` が、`[{"sku": str, "qty": int}, ...]` を `sku` の昇順で返す。

### Scope
- CSV の読み込み
- `today` の正規化
- 28日間の日次需要の計算
- ROP の計算
- 発注の判断（`<=`）と lot 単位への切り上げ
- 廃番品の除外

### Out of scope
- 需要予測（季節性・傾向）と安全在庫の再計算
- 価格・発注先・予算の制約
- ファイル出力と CLI
- 外部ライブラリの追加
- 入力値の厳密な検証（列の欠落、lot ≤ 0 など）

### Data sources
- `inventory.csv`
- `shipments.csv`
- 引数 `today`

### Constraints
- 標準ライブラリだけを使う。
- 関数に副作用を持たせない（入力ファイルを変更しない）。
- 作業ディレクトリの外にあるファイルを読み書きしない。テスト用の一時ファイルも作業ディレクトリの下に作り、最後に削除する。

### Definition of Done（検証できる条件）
1. `reorder_plan("inventory.csv", "shipments.csv", "2026-11-10") == [{"sku": "A100", "qty": 50}]`
   - 集計期間は 10/13〜11/09
   - A100: 需要は 84/28 = 3、ROP = 41、有効在庫 40 ≤ 41 → 不足 1 → 50
   - A200: 需要は 28/28 = 1、ROP = 15、有効在庫 45 → 発注なし
   - C400: 需要 0、ROP = 6、有効在庫 12 → 発注なし
   - B300: 廃番のため対象外
2. `today=datetime.date(2026, 11, 10)` と `datetime.datetime(2026, 11, 10, 9, 0)` でも、1 と同じ結果になる。
3. `today="2026-11-25"` のとき `[]` を返す。
   - 集計期間は 10/28〜11/24
   - A100: 需要は 39/28、ROP = 29.75 < 40
   - A200: 需要は 12/28、ROP ≈ 12.14 < 45
4. today 当日以降の出荷行は結果に影響しない。today=2026-11-05 で、元のデータと 11/05 以降の行を除いたデータの結果が一致する。
5. 28日間の境界が正しい。`today-28` 日の出荷は含め、`today-29` 日と today 当日の出荷は含めない。
6. 返す `qty` はすべて正の整数で、その品目の `lot` の倍数になっている。
7. `discontinued=true`（`TRUE` などの表記も含む）の品目は、在庫が 0 でも戻り値に入らない。
8. 境界ケース:
   - `有効在庫 == ROP` のときは 1 lot を発注する（A10）。
   - `有効在庫 == ROP + 1` のときは発注しない。
   - 出荷のない品目は `stock + on_order <= safety_stock` のときだけ発注する。
   - inventory にない SKU の出荷行は無視する。
   - 小数の ROP でも誤差なく判定できる。
