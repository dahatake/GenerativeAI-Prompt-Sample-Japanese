## 2. 実データでの計算過程

today=2026-11-10（集計期間 2026-10-13〜2026-11-09）の結果は `[{'sku': 'A100', 'qty': 50}]` です。

| SKU | 28日間の出荷合計 | 日次需要 | ROP | 有効在庫 | 判定 |
|---|---|---|---|---|---|
| A100 | 84 | 3.0 | 41.0 | 40 | 40 ≤ 41 → 不足 1 → **50**（lot 50） |
| A200 | 28 | 1.0 | 15.0 | 45 | 発注なし |
| B300 | 0 | 0.0 | 5.0 | 5 | 5 ≤ 5 だが廃番のため除外 |
| C400 | 0 | 0.0 | 6.0 | 12 | 発注なし |

today=2026-11-25（集計期間 2026-10-28〜2026-11-24）の結果は `[]` です。

| SKU | 合計 | 日次需要 | ROP | 有効在庫 | 判定 |
|---|---|---|---|---|---|
| A100 | 39 | 1.3929 | 29.75 | 40 | 発注なし |
| A200 | 12 | 0.4286 | 12.1429 | 45 | 発注なし |
| B300 | 0 | 0.0 | 5.0 | 5 | 廃番のため除外 |
| C400 | 0 | 0.0 | 6.0 | 12 | 発注なし |

（この表は、上の検証と同じ手順で `python -` に計算スクリプトを渡して出力した結果です。）

## 4. 採用した仮定の一覧

| ID | 内容 | 根拠 |
|---|---|---|
| A1 | Python 3 の標準ライブラリだけを使う | answers.md で「指定なし」→ 推奨既定案 |
| A2 | `today` は `date`、`datetime`、`"YYYY-MM-DD"` 文字列のどれでも受け付ける | 同上 |
| A3 | 有効在庫は `stock + on_order` | Q2 の回答で確定 |
| A4 | ROP は丸めずに `Fraction` で正確に比較する（float では 60.999… のような誤差で判定が変わる場合があるため） | 推奨既定案。`test_dod8_fractional_rop_exact` で確認 |
| A5 | 発注数は `ceil(不足量 / lot) × lot` | Q2 の回答で確定 |
| A6 | 戻り値は qty > 0 の品目だけで、sku の昇順。qty は int | 推奨既定案 |
| A7 | today 当日と、それより後の出荷は使わない | Q1 の回答で確定 |
| A8 | inventory にない SKU の出荷行は無視する | 推奨既定案 |
| A9 | CSV は UTF-8 で読む（BOM 付きでも可）。`discontinued` は前後の空白を除き、大文字・小文字を区別せずに `"true"` かどうかで判定する | 推奨既定案 |
| A10 | `有効在庫 == ROP`（不足 0）のときは **1 lot** を発注する | 回答「発注点以下なら発注対象」と「不足量の切り上げ」を同時に満たすための解釈。**人間の確認が必要** |
| — | 記録のない日は出荷0として数え、集計期間は today の前日で終える | answers.md の補足で確定 |

## 5. 人間に確認してほしい点
- **A10**: 有効在庫がちょうど発注点に等しいときの発注数。現在は 1 lot を発注します。「発注しない」や「qty=0 で返す」に変える場合は、`solution.py` の `max(1, ...)` と、それに対応するテストを修正します。なお、実データの非廃番品は 2026-11-10 と 2026-11-25 ではこのケースに当たらないため、この2日の結果は A10 の解釈に左右されません。
