## 2. 仮定（質問しない項目。違っていたら指摘してください）
- A1. 使う言語は Python 3 の標準ライブラリだけにする（pandas は使わない）。
- A2. `today` には `datetime.date`、`datetime.datetime`、`"YYYY-MM-DD"` 文字列のどれを渡しても受け付ける。
- A3. 発注判断に使う手持ちは「在庫ポジション = stock + on_order」とする。
- A4. 発注点（ROP）は `日次需要 × lead_time_days + safety_stock` とする。小数は丸めずに比較する。
- A5. 発注数は lot の倍数に切り上げる（`ceil(不足量 / lot) × lot`）。
- A6. 戻り値には発注数が 0 より大きい品目だけを入れ、`sku` の昇順に並べる。`qty` は `int` にする。
- A7. `today` 当日と、それより後の日付の出荷行は需要の計算に使わない。
- A8. inventory にない SKU の出荷行は無視する。
- A9. CSV は UTF-8 で読む（BOM 付きでも読める）。`discontinued` は大文字・小文字を区別せずに `"true"` かどうかで判定する。

## 4. 質問（最大3問。どれも結果が大きく変わる点です）

### Q1. 日次需要はどう計算しますか？（影響が最も大きい点）
このデータは算出方法によって結果が大きく変わります。例えば C400 は 10/1〜10/10 にだけ出荷があり、A100 は 11/9 以降の記録がありません。
- **(a) 推奨**: `today` の直前30暦日（`today-30 ≤ date < today`）の出荷合計を30で割る。出荷がない日は需要0として数える。
- (b) 出荷履歴全体（最初の出荷日から `today` の前日まで）の合計を暦日数で割る。
- (c) 出荷があった日だけで平均する（出荷のない日は分母に入れない）。
- (d) 期間を引数で渡せるようにする（既定値は30日、計算方法は (a)）。

影響例（`today=2026-11-10`、Q2・Q3 は推奨案とした場合）:
- C400: (a) 発注なし ／ (b) 20 ／ (c) 70
- `today=2026-11-25` にすると、(a) では A100 の日次需要が 1.5 になり、発注が不要になります。

### Q2. いつ、いくつ発注しますか？
- **(a) 推奨**: `stock + on_order < ROP` のときに発注する。発注数は `ceil((ROP − (stock + on_order)) / lot) × lot`（ROP に届く最小の lot 倍数）。
- (b) (a) と同じ考え方で、条件を `≤ ROP` にする。ちょうど ROP のときは 1 lot 発注する。
- (c) 目標在庫まで補充する: `目標 = 日次需要 × (lead_time_days + 補充サイクル日数) + safety_stock`。サイクル日数は別途指定が必要。
- (d) 条件を満たしたら常に 1 lot を固定で発注する。

### Q3. 廃番品（discontinued=true）はどう扱いますか？
- **(a) 推奨**: 発注の対象から常に外す（戻り値に入れない）。
- (b) 他の品目と同じように計算する。
- (c) 外したうえで、警告用に別の情報として返す（戻り値の形が変わります）。

## 5. Task Contract 案（Q1〜Q3 は推奨案を採用した前提）

### Outcome
`solution.py` に `reorder_plan(inventory_path, shipments_path, today)` を実装する。この関数は、発注が必要な品目の `[{"sku": str, "qty": int}, ...]` を `sku` の昇順で返す。

### Scope
- CSV 2ファイルの読み込みと型の変換
- `today` の正規化（A2）
- 日次需要の計算（Q1）、ROP の計算（A4）、発注の判断と lot 単位への切り上げ（Q2, A5）
- 廃番品を対象から外す（Q3）

### Out of scope
- 季節性や傾向を考慮した需要予測、統計的な安全在庫の再計算（`safety_stock` は CSV の値をそのまま使う）
- 発注先、価格、MOQ（lot 以外）、予算の制約
- ファイルへの書き出し、CLI、ログ出力
- 外部ライブラリの追加

### Data sources
- `inventory.csv`: `sku, name, stock, on_order, lead_time_days, safety_stock, lot, discontinued`
- `shipments.csv`: `date, sku, qty`
- 引数 `today`

### Constraints
- Python 3 標準ライブラリだけを使う。ファイルパスは引数で受け取り、ハードコードしない。
- 関数に副作用を持たせない（入力ファイルを変更しない）。
- 作業ディレクトリの外にあるファイルを読み書きしない。
- 契約が確定するまで、`solution.py` やテストを作成しない。

### Definition of Done（検証できる条件）
推奨案を採用した場合の期待値です。手計算で確認しています。

1. `reorder_plan("inventory.csv", "shipments.csv", "2026-11-10") == [{"sku": "A100", "qty": 50}]`
   - A100: 需要 3/日、ROP は 3×7+20 = 41、在庫ポジション 40 < 41 なので不足 1 → 50 に切り上げ
   - A200: 需要 1/日、ROP は 15、在庫ポジション 45 なので発注なし
   - C400: 直近30日の需要 0、ROP は 6、在庫ポジション 12 なので発注なし
   - B300: 廃番のため対象外
2. `today` に `datetime.date(2026, 11, 10)` を渡しても、1 と同じ結果になる。
3. `today="2026-11-25"` のとき `[]` を返す（A100 の需要 1.5/日、ROP 30.5、在庫ポジション 40）。
4. `today` 当日以降の出荷行は計算に影響しない（例えば today=2026-11-05 なら、11/05〜11/09 の行を除いた結果と一致する）。
5. 返す `qty` はすべて正の整数で、その品目の `lot` の倍数になっている。
6. `discontinued=true` の品目は、在庫がいくら少なくても戻り値に入らない。
7. 一時ディレクトリで作った小さな CSV を使って、境界ケースを確認する。対象は、出荷のない品目、在庫ポジションがちょうど ROP の場合（推奨案 (a) では発注しない）、inventory にない SKU の出荷行。

### Evidence（完了時に示すもの）
- `solution.py` の差分
- DoD の 1〜7 を実行したテストのコマンドと結果（すべて合格したログ）
- 品目ごとの計算過程（日次需要、ROP、在庫ポジション、発注数）を表で示す
