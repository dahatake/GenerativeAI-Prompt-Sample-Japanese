### 推定値の比較（需要の集計期間を決める重要性を示すための試算）

以下の条件で計算しました。
- 発注点 ROP = 日平均需要 × lead_time + safety_stock
- 在庫ポジション = stock + on_order
- 不足量は lot の倍数に切り上げる

| 条件 | A100 | A200 | C400 | B300 |
|---|---|---|---|---|
| today=2026-11-10、直近30暦日 | **50** | 0 | 0 | 除外 |
| today=2026-11-10、全履歴（40日） | **50** | 0 | **20** | 除外 |
| today=2026-11-25、直近30暦日 | 0（1.5/日） | 0 | 0 | 除外 |
| A200 で on_order を数えない場合 | – | 15 ≤ ROP 15 → 境界 | – | – |
| B300 を除外しない場合 | – | – | – | 5 ≤ ROP 5 → 境界 |

→ 集計期間、on_order の扱い、境界値の判定（`<` か `<=` か）、廃番品の扱いで結果が変わります。

### 仮定（既定値として置くもの）
1. `today` は `datetime.date` と `"YYYY-MM-DD"` 文字列の両方を受け付けます。
2. 需要の集計に使う出荷は **date < today** のものだけです（当日分と未来日は除外）。
3. 日平均需要 = 集計期間内の出荷数の合計 ÷ **集計期間の暦日数**。出荷のない日は0として数えます。
4. 在庫ポジション = `stock + on_order`
5. 発注点 ROP = 日平均需要 × `lead_time_days` + `safety_stock`。小数のまま使い、途中で丸めません。
6. 不足量 = ROP − 在庫ポジション。**不足量 > 0** のときだけ発注します。
7. 発注数 = `ceil(不足量 / lot) × lot`。lot の倍数に切り上げます。
8. `discontinued == true` の品目は対象外です。
9. qty が0の品目は戻り値に含めません。
10. 戻り値は `sku` の昇順で、qty は `int` です。
11. inventory にない sku の出荷行は無視します。出荷履歴のない品目の需要は0です。

### 不足情報（ファイルからは判断できない点）

## 2. 質問（最大3問。既定案が外れると手戻りが大きい点だけ）

> いずれの質問も、選択肢に当てはまらない場合は **具体的な値**（日数、式、閾値など）で回答してください。

### Q1. 日平均需要の集計期間と分母
- **A（推奨）**: 直前30暦日（`today-30` 〜 `today-1`）の合計 ÷ 30。出荷のない日は0として数えます。
- B: 履歴全体（最初の出荷日 〜 `today-1`）の合計 ÷ その暦日数
- C: 直前28暦日（4週間）の合計 ÷ 28
- D: 直前N暦日。N の値を指定してください。

*影響*: today=2026-11-10 の場合、C400 の発注数は A なら0、B なら20 になります。today=2026-11-25 の場合、A なら A100 も発注不要です。

### Q2. 発注のきっかけと発注数の式
- **A（推奨）**: `stock + on_order < ROP` のとき発注します。発注数は `ceil((ROP − (stock+on_order)) / lot) × lot`（発注点まで戻す最小量を lot 単位で切り上げ）です。
- B: きっかけは A と同じです。補充の目標を `ROP + 日平均 × 30日`（発注点に1か月分を上乗せした量）とし、`ceil((目標 − ポジション)/lot) × lot` を発注します。
- C: A と同じ式ですが、`on_order` を数えず `stock` だけで判断します。
- いずれの場合も、`<`（推奨）と `<=` のどちらで判定するかを指定してください。`<=` にする場合、ちょうど一致したときは1ロット発注します。

### Q3. 廃番品（`discontinued=true`）の扱い
- **A（推奨）**: 常に対象外とし、戻り値に含めません。
- B: ほかの品目と同じように計算します。
- C: 対象外としますが、`{"sku": ..., "qty": 0}` として戻り値に含めます。

## 3. Task Contract 案

### Outcome
`solution.py` の `reorder_plan(inventory_path, shipments_path, today)` は、発注が必要な品目だけを `[{"sku": str, "qty": int}, ...]` の形で返します。発注要否と数量は、Q1〜Q3 で合意した規則で決まります。

### Scope
- CSV 2ファイルの読み込み（UTF-8。BOM付きも許容）
- 日平均需要、発注点、在庫ポジション、発注数の計算
- lot 単位への切り上げ、廃番品の扱い、並び順の確定

### Out of scope
- ファイルへの出力、CLI、ログ出力
- 需要予測モデル（季節性やトレンドの考慮）、最大在庫、予算、MOQ（最小発注数量）の制約
- 入荷予定日の考慮（on_order の着荷日は扱いません）
- `solution.py` 以外のファイル（テストコードは検証用の一時ファイルとし、納品物には含めません）

### Data sources
- `inventory.csv`: `sku,name,stock,on_order,lead_time_days,safety_stock,lot,discontinued`
- `shipments.csv`: `date,sku,qty`
- 引数 `today`: `date` または `"YYYY-MM-DD"`

### Constraints
- Python の標準ライブラリだけを使います（`csv`, `datetime`, `math`）。
- 入力ファイルは変更しません（読み取りのみ）。
- 作業ディレクトリの外にあるファイルは読み書きしません。
- 浮動小数の誤差で lot が1つ増えないように、切り上げの前に小さな許容誤差を設けます。または `fractions.Fraction` で計算します。

### Definition of Done（検証できる条件）
1. `from solution import reorder_plan` が成功する。
2. 既定案（Q1-A / Q2-A / Q3-A）を前提とした実データでの結果:
   - `reorder_plan("inventory.csv", "shipments.csv", "2026-11-10") == [{"sku": "A100", "qty": 50}]`
   - `reorder_plan("inventory.csv", "shipments.csv", "2026-11-25") == []`
   - `today` を `datetime.date(2026,11,10)` で渡しても、文字列で渡したときと同じ結果になる。
3. 境界値: 在庫ポジションが ROP とちょうど等しいときは発注しない（Q2 の回答に従う）。
4. 廃番品は戻り値に含まれない（Q3 の回答に従う）。
5. 発注数はすべて lot の正の整数倍である。
6. 当日分と未来日の出荷は需要に含まれない。
7. 戻り値は sku の昇順で、各要素のキーは `sku` と `qty` だけである。
8. 質問の回答が既定案と異なる場合は、2. の期待値をその回答で計算し直したうえで、Evidence に記載する。
