## 4. 質問（手戻りが大きい 3 点のみ）

どの選択肢にも当てはまらない場合は、**具体的な値（日数・式・丸め方）で回答してください**。

### Q1. 平均日次出荷の集計期間（C400 を発注するかが変わります）
- **(a) 推奨: `today` の前日までの直近 28 日（`today-28日` 〜 `today-1日`）の合計 ÷ 28**
  → today=2026-11-10 で A100=3.0, A200=1.0, C400=0.0
- (b) 直近 W 日の合計 ÷ W（W に別の値を指定してください。例: 14 / 30 / 60 / 90）
- (c) shipments.csv の全期間（最初の出荷日〜 `today-1日`）の合計 ÷ その日数
  → today=2026-11-10 で C400=1.25/日 となり、C400 も発注対象になる（qty=20）

### Q2. 発注するかの判定と、発注量の目標
- **(a) 推奨: `stock + on_order < ROP` のときに発注する（ROP ちょうどなら発注しない）。発注量の素の値 = `ROP − (stock + on_order)`（ROP まで戻すだけ）。その後 Q3 で丸める**
- (b) 判定は (a) と同じく `<`。発注量の目標を「発注点 + リードタイム分の需要」にする: 素の値 = `ROP + 平均日次×lead_time_days − (stock+on_order)`
- (c) 判定を `≤` にする（ROP ちょうどでも発注する）。発注量の計算は (a) と同じ
- ※ today=2026-11-10、Q1=(a) の場合、A100 は ROP=3×7+20=41 > 40 で、(a)(b)(c) どれでも発注対象になります。境界の違いが結果に出るのは、ROP ちょうどの品目や小数になる ROP の品目です

### Q3. `lot` の扱い
- **(a) 推奨: 発注単位として扱う。素の値を `lot` の倍数に切り上げる（`ceil(need/lot)*lot`）** → A100: 1 → 50
- (b) 最小発注数として扱う。`max(lot, ceil(need))` → A100: 50（need が 50 を超えたら 1 個単位）
- (c) lot を使わない。`ceil(need)` の整数 → A100: 1

### 回答（answers.md、2026-11-25）
- **Q1 = (a)**: `today` の前日までの直近 28 日（today 当日は含めない）の出荷合計 ÷ 28
- **Q2 = (c)**: 有効在庫（stock + on_order）≤ ROP なら発注する（ROP ちょうども発注）。素の値 = ROP − 有効在庫
- **Q3 = (a)**: 素の値を lot の倍数に切り上げる
- A1 / A3 / A4 / A5 / A7: 了承。A9: 指定なしのため推奨案（不正な入力は例外にする）

### 回答をそのまま当てはめると生じる境界の問題と、その解決（仮定 A10）
Q2=(c) と Q3=(a) をそのまま組み合わせると、有効在庫 == ROP の品目は「発注する」と判定されるのに、素の値が 0 になり `ceil(0/lot)*lot = 0` 個の発注になってしまいます。
「ROP ちょうども発注する」という回答の意図を優先し、**発注すると判定された品目は最低 1 lot を発注する**（`qty = max(lot, ceil(need/lot)*lot)`）ことにしました。
例データ（today=2026-11-10 と 2026-11-25）にはこの境界に当たる発注対象品目がないため、結果には影響しません。report.md で「人間の確認が必要」として挙げています。

## 5. Task Contract（承認済み）

### Outcome
`solution.py` に `reorder_plan(inventory_path, shipments_path, today)` を実装する。発注が必要な品目について `[{"sku": str, "qty": int}, ...]` を返す。

計算手順（確定）:
1. 平均日次出荷 `d = (today-28日 〜 today-1日 の出荷合計) / 28`（出荷のない日は 0 として数える）
2. `ROP = d × lead_time_days + safety_stock`
3. `position = stock + on_order`
4. `discontinued` が false で `position ≤ ROP` のとき、`need = ROP − position`、`qty = max(lot, ceil(need / lot) × lot)`（A10）
5. qty > 0 の品目を sku 昇順で返す。qty は `int`

### Scope
- CSV 2 ファイルの読み込みと検証、需要の集計、発注点の判定、lot 丸め、戻り値の組み立て
- `today` の型の正規化（date / datetime / `YYYY-MM-DD` 文字列）

### Out of scope
- 需要予測モデル（移動平均以外、季節性、トレンド）、発注サイクル・発注コストの最適化（EOQ など）
- ファイルへの出力、CLI、ログ、DB 連携
- 外部ライブラリ（pandas など）の使用

### Data sources
- `inventory.csv`: 品目マスタと在庫（列は 1 節のとおり）
- `shipments.csv`: 日次出荷履歴（`date,sku,qty`）
- 引数 `today`: 集計の基準日

### Constraints
- Python 3 の標準ライブラリだけを使う。入力ファイルは変更しない
- 結果は決定的にする（同じ入力なら同じ出力、sku 昇順）
- 境界判定と切り上げは `fractions.Fraction` で正確に計算する（浮動小数の誤差を持ち込まない）
- 不正な入力（必須列の欠落、数値・日付・真偽値を解釈できない値、lot ≤ 0、inventory 内の sku 重複）は `ValueError` にする

### Definition of Done（検証できる条件）
1. `reorder_plan("inventory.csv", "shipments.csv", "2026-11-10")` が `[{"sku": "A100", "qty": 50}]` を返す。A200（position 45 > ROP 15）、B300（廃番）、C400（需要 0 で ROP 6 < 12）は含まれない
2. `today` に `datetime.date(2026,11,10)` や `datetime.datetime` を渡しても、文字列と同じ結果になる
3. `today="2026-11-25"` では `[]` になる（A100 の ROP が 29.75 < 40 になるため）
4. 境界: position == ROP の品目は発注する（qty = lot）。position == ROP + 1 の品目は発注しない。小数の ROP（例: 40.5）に対して need 0.5 は 1 lot に切り上げる（一時 CSV を使ったテストで確認）
5. 窓の境界: `today-28日` の出荷は含み、`today-29日` と `today` 当日以降の出荷は含まない（テストで確認）
6. 戻り値の qty はすべて正の `int` で `lot` の倍数。結果は sku 昇順。`discontinued=true` の品目は条件を満たしても含まれない
7. 必須列がない / 数値が不正な CSV では `ValueError` が出る
