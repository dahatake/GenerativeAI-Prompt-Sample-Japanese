- 成果物: `solution.py`（実装）、`test_solution.py`（検証用テスト。標準ライブラリの `unittest`）
- 実行環境: Python 3.12.10 / Windows

## 実装の要点
- `ordered_at`（UTC）を JST（UTC+9 の固定オフセット）に変換し、`YYYY-MM` で月を決める。
- `status == "completed"` の行だけを集計し、負の金額は返金として差し引く。`cancelled` の行は除外する。
- `amount_incl_tax` は税込のまま `int` で合計する。
- 売上のない月はキーに含めない。キーは昇順。
- 次の場合は `ValueError` を送出する: 必須列がない、日時を解析できない、日時にタイムゾーンがない、金額が整数でない・空、未知の status。

## 採用した仮定（すべて未確認。回答がなかったため既定案を採用）

| ID | 内容 | 外れた場合の影響 |
|---|---|---|
| Q1=a | 月は JST（UTC+9）の暦月で区切る | UTC にすると `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}` になる |
| Q2=a | `completed` だけを集計する。負の金額は返金として相殺し、`cancelled` は除外する | 全件集計なら JST で `{"2026-01": 38500, "2026-02": 15400, ...}` になる |
| Q3=a | 税込金額（`amount_incl_tax`）をそのまま合計する | 税抜にする場合は換算と端数処理の仕様が必要 |
| A2 | 売上のない月（2026-03 など）はキーに含めない | 0 で埋める場合は期間の定義が必要 |
| A3 | キーは昇順で構築する | dict の等価比較には影響しない |
| A4 | 入力は UTF-8（BOM の有無は問わない）、ヘッダ付きのカンマ区切り | Shift_JIS などは読めない |
| A5 | 標準ライブラリのみ。Python 3.11 以上（`str \| os.PathLike` 型注釈と `fromisoformat` の `Z` 対応のため） | 3.10 以下では動かない |
| A6 | 不正な行はスキップせず `ValueError` を送出する。`cancelled` の行も検証対象 | スキップを望む場合は挙動の変更が必要 |
| A7 | 金額は整数のみ受け付ける（`10.5` はエラー） | 小数を含むデータは読めない |
| — | status の既知値は `completed` / `cancelled` の 2 つだけ。それ以外はエラー | `refunded` などが実データにあると失敗する |
