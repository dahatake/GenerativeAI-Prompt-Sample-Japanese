## 1. 調査結果

### 1.1 確認できた事実（作業ディレクトリ内の調査結果）

- 作業ディレクトリには `shifts.csv` しかありません（`timing.txt` は今回作成したもの）。`solution.py`、テスト、README、仕様書はまだありません。
- `shifts.csv` について:
  - 文字コードは UTF-8 で BOM はありません。中身はすべて ASCII です。サイズは 224 bytes です。
  - 改行コードが混在しています。最終行だけが CRLF（`\r\n`）で、ほかの行は LF です。
  - ヘッダは `employee,date,type,start,end` です。データは 6 行あります。
  - `employee` には `E001` / `E002` / `E003` の形式の値が入っています。
  - `date` は `YYYY-MM-DD` 形式です。今回のデータはすべて **2026-10**（1 か月分）です。
  - `type` は `work` と `paid_leave` の 2 種類です。
  - `start` / `end` は `HH:MM` 形式（24 時間制）です。`paid_leave` の行では両方とも空欄です。
  - **日付をまたぐシフトが 1 件あります**: `E002,2026-10-01,work,22:00,06:00`
  - 休憩時間の列はありません。
  - 分単位の端数が出るデータがあります: `09:00–14:50`（5h50m）と `08:30–17:45`（9h15m）
- 実行環境は Python 3.12.10 です。
- 依頼で決まっているのは、関数名 `monthly_work_hours(path)`、ファイル名 `solution.py`、戻り値 `{従業員ID: 労働時間(時間, float)}` の 3 点です。

### 1.2 仮定（質問では確認せず、この前提で進めます。違う場合は指摘してください）

- A1: `end <= start` の場合は、終了が翌日にまたがったとみなし、24 時間を足して計算します。
- A2: 1 シフトの時間は `(end - start)` を分単位で求め、60 で割った値です。**丸めはしません**（例: 5h50m → 5.8333…）。テストでの比較には許容誤差（`math.isclose` / `pytest.approx`）を使います。
- A3: 戻り値のキーは、CSV に現れる従業員 ID をすべて含みます。労働時間が 0 の従業員（例: 有給の行しかない人）も `0.0` で含めます。
- A4: 標準ライブラリ（`csv`, `datetime`）だけを使い、外部依存は追加しません。ファイルは UTF-8 で読み、BOM があっても扱えるように `utf-8-sig` を使います。LF / CRLF が混在していても読めるようにします。
- A5: 前後の空白は無視します。空行は読み飛ばします。
- A6: `type=work` なのに `start` / `end` が空欄や不正な形式の行は、データ不正として `ValueError` を出します。黙って読み飛ばすことはしません。
- A7: 同じ従業員・同じ日付の `work` 行が複数ある場合（分割勤務）は、すべて合算します。重複かどうかの判定はしません。

### 1.3 不足情報

- 休憩時間をどう扱うか（データに休憩列がありません）→ **Q1**
- `paid_leave` やそのほかの非 `work` 種別を労働時間に数えるかどうか → **Q2**
- 「月間」の意味（ファイルに複数の月が含まれる場合や、月末の日付またぎをどう扱うか）。関数の引数は `path` だけです → **Q3**
- 想定するデータ規模、実データの出どころ、ほかの勤怠システムとの突き合わせが必要かどうか（今回は規模を気にしない前提です）

## 2. 質問（最大 3 問。回答によって実装が変わり、外れたときの手戻りが大きいものだけ）

### Q1. 休憩時間を差し引きますか？
| 選択肢 | 内容 | 本データでの結果 (E001 / E002 / E003) |
|---|---|---|
| **A（推奨）** | 差し引かない。`end - start` をそのまま労働時間とする | 14.8333 / 14.0 / 9.25 |
| B | 労基法の最低基準で差し引く（6h 超は 45 分、8h 超は 60 分） | 13.8333 / 13.25 / 8.25 |
| C | 一律 1 時間を差し引く（または別途指定する固定値） | 12.8333 / 12.0 / 8.25 |

推奨理由: CSV に休憩の情報がないため、勝手にルールを持ち込むと誤った値になるおそれがあります。B / C が必要な場合も、後から引数を追加する形で対応できます。

### Q2. `paid_leave`（とそのほかの `work` 以外の種別）はどう扱いますか？
| 選択肢 | 内容 |
|---|---|
| **A（推奨）** | 実労働時間だけを数える。`work` 以外の行は 0 時間として扱う（従業員キーは残す） |
| B | `paid_leave` を所定労働時間（例: 8.0h）として加算する |
| C | 未知の `type` は `ValueError`、`paid_leave` は 0 時間にする（A の厳格版） |

推奨理由: 「労働時間」は普通は実労働を指します。有給を加算するには所定時間の定義が必要ですが、データからは分かりません。
※ 推奨 A では、未知の type も黙って 0 時間として扱います。厳格にしたい場合は C を選んでください。

### Q3. 「月間」の範囲をどう決めますか？（ファイルに複数の月が含まれる場合や、月末の日付またぎ）
| 選択肢 | 内容 |
|---|---|
| **A（推奨）** | ファイルを 1 か月分の勤怠とみなし、全行を合計する。日付またぎのシフトは**開始日の月**にまとめて計上する。複数の月が含まれる場合は `ValueError` |
| B | ファイル内の全行を月の区別なく合計する（複数の月でもエラーにしない） |
| C | 戻り値を `{従業員ID: {"YYYY-MM": 時間}}` に変える。または `month` 引数を追加し、指定された月だけを集計する（日付またぎは暦日で分割） |

推奨理由: 依頼の関数シグネチャ（`path` のみ）と戻り値の形（フラットな dict）にそのまま合います。複数の月が混ざったデータを黙って合計してしまう誤りも防げます。

## 3. Task Contract 案

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装します。勤怠 CSV を読み込み、従業員ごとの月間労働時間（単位: 時間、float）を返します。

### Scope
- `solution.py` を新規作成し、`monthly_work_hours(path)` を実装する
- CSV の読み込み（ヘッダ `employee,date,type,start,end`、LF / CRLF 混在、BOM の有無の両方に対応）
- `HH:MM` の解析と、日付をまたぐシフトの計算（A1）
- `type` による集計対象の判定（Q2 の回答に従う）
- 休憩の扱い（Q1 の回答に従う）
- 月の範囲の扱い（Q3 の回答に従う）
- 不正な入力の検出と `ValueError` の送出（A6）
- 上記を確かめる最小限のテスト（※ テストファイルの追加は契約の合意後、実装フェーズで行います）

### Out of scope
- 残業、深夜、休日の割増時間の区分集計
- 給与計算、端数処理ルール（15 分単位の切り捨てなど）の適用（Q1 / Q2 で別の方針が選ばれた場合を除く）
- `shifts.csv` 自体の修正、CLI や UI、DB 連携
- タイムゾーンや夏時間の考慮（すべてローカル時刻として扱う）
- 外部ライブラリ（pandas など）の導入

### Data sources
- `shifts.csv`（作業ディレクトリ内）。列は `employee,date,type,start,end` の 5 つです。
- 上記以外の資料（就業規則、所定労働時間、休憩規定）はありません。

### Constraints
- Python 3.12 で動き、標準ライブラリだけを使う
- 関数名、ファイル名、戻り値の型（`dict[str, float]`）は依頼の内容から変えない（Q3 で C が選ばれた場合だけ変える）
- 作業ディレクトリの外にあるファイルは読み書きしない
- 入力ファイルは変更しない（読み取りのみ）

### Definition of Done（検証できる条件）
1. `python -c "from solution import monthly_work_hours as f; print(f('shifts.csv'))"` がエラーなく実行できる。
2. 推奨既定案（Q1=A, Q2=A, Q3=A）の場合、`shifts.csv` に対する結果が次と一致する（許容誤差 1e-9）:
   - `E001`: 14.8333…（= 9 + 35/6）
   - `E002`: 14.0（= 8〔22:00→06:00 の日付またぎ〕+ 6）
   - `E003`: 9.25
   - 戻り値のキーはちょうど `{"E001","E002","E003"}` で、値はすべて `float` 型
3. 日付をまたぐシフト（`22:00→06:00`）が 8.0h になる。
4. `paid_leave` だけの従業員が `0.0` で返る（Q2=A の場合）。
5. CRLF / LF の混在と、BOM 付き UTF-8 のどちらでも同じ結果になる。
6. `type=work` で `start` が空欄、または時刻の形式が不正な行があると `ValueError` になる。
7. 複数の月を含む CSV で `ValueError` になる（Q3=A の場合）。
