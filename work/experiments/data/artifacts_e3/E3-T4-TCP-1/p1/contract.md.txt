## 1. 調査結果

### 確認できた事実（作業ディレクトリ内のファイルから）
- 作業ディレクトリにあるのは `shifts.csv` だけ（`timing.txt` は今回の計測用）。既存の `solution.py`、テスト、仕様書はない。
- `shifts.csv` は ASCII（UTF-8 互換）で BOM なし、改行は LF。ヘッダー 1 行とデータ 6 行。
- 列は `employee,date,type,start,end` の 5 つ。
  - `employee`: `E001` 形式の文字列 ID（E001, E002, E003）
  - `date`: `YYYY-MM-DD`。全行が **2026-10**（ファイル内は 1 か月分だけ）
  - `type`: `work` と `paid_leave` の 2 種類
  - `start` / `end`: `HH:MM` 形式の 24 時間表記。`paid_leave` の行は空欄
- **休憩の列はない**（例: E001 は `09:00–18:00`、E003 は `08:30–17:45`）。
- **日をまたぐ勤務がある**: E002 `2026-10-01 22:00–06:00`（end < start）。
- 端数のある勤務がある: E001 `09:00–14:50`（= 5 時間 50 分 = 5.8333… 時間）。
- 関数のシグネチャは `monthly_work_hours(path)` で、**対象月を指定する引数がない**。戻り値は `{従業員ID: 労働時間(float, 時間)}`。
- 環境: Python 3.12.10

### 仮定（質問しなかったもの。この仮定で進めます）
- A1. 日をまたぐ勤務: `end < start` なら翌日の終了とみなし、24 時間を足して計算する。時間はすべて**勤務開始日（`date`）の月**に計上する（日付ごと・月ごとに分割しない）。
- A2. `end == start` は 0 時間とする（24 時間勤務とはみなさない）。
- A3. 対象月: 関数に月の引数がないため、**ファイル全行を集計する**（「1 ファイル = 1 か月分」という前提）。月でのフィルタリングや分割はしない。
- A4. `paid_leave` だけの従業員も、キーとして結果に含める（値は Q2 の回答に従う）。
- A5. `type` が `work` / `paid_leave` 以外の場合、`work` の行で `start` / `end` が空欄や不正な形式の場合、必須の列がない場合は `ValueError` を送出する（黙ってスキップしない）。
- A6. 時刻は `HH:MM`（00:00–23:59）。`24:00` や秒付きの表記は不正として扱う（A5 と同じ）。
- A7. ファイルは UTF-8 として読む（BOM があっても許容するため `utf-8-sig` を使う）。前後の空白は除去する。空行は無視する。
- A8. 同じ従業員・同じ日付の行が複数ある場合は、それぞれ別の勤務として合算する（重複の検出はしない）。
- A9. 標準ライブラリ（`csv`、`datetime`）だけを使い、外部パッケージは使わない。

### 不足情報（調べても分からなかったもの）
- 休憩時間をどう扱うか（データに休憩の列がない）→ **Q1**
- 有給休暇を労働時間として数えるか → **Q2**
- 丸めの方法・単位（戻り値を float で比較するため）→ **Q3**
- 深夜・残業の区分、所定労働時間、複数か月のデータの扱い → 今回は範囲外、または A1・A3 の仮定で進めます

## 2. 質問（最大 3 問。外れたときの手戻りが大きいものに絞っています）

> どの選択肢にも当てはまらない場合は、**具体的な値**（例:「6 時間超なら 30 分を控除」「1 分単位で切り捨て」）で答えてください。

### Q1. 休憩時間の控除（全員の数値が変わります）
データに休憩の列がありません。`09:00–18:00` のような典型的な勤務時間帯が含まれているため、控除するかどうかで結果が大きく変わります。

| 選択肢 | ルール | E001 / E002 / E003 の結果（Q2=A、Q3=A の場合） |
|---|---|---|
| **A（推奨）** | 控除しない（終了 − 開始 をそのまま労働時間とする） | 14.83 / 14.0 / 9.25 |
| B | 労基法の最低ラインで控除する: 勤務が 6 時間を超えて 8 時間以下なら 45 分、8 時間を超えるなら 60 分 | 13.83 / 13.25 / 8.25 |
| C | 勤務が 6 時間以上なら、一律 60 分を控除する | 13.83 / 12.0 / 8.25 |

推奨理由: データにない休憩を推測で引かず、記録された値をそのまま使うのが最も検証しやすいためです。B または C を選んだ場合は、控除を 1 勤務（1 行）ごとに適用します。

### Q2. 有給休暇（`paid_leave`）の扱い
| 選択肢 | ルール | E001 の結果（Q1=A、Q3=A の場合） |
|---|---|---|
| **A（推奨）** | 0 時間（実際に働いた時間だけを集計する） | 14.83 |
| B | 所定労働時間として 1 日 **8.0 時間** を加算する | 22.83 |
| C | 1 日 X 時間を加算する（X を具体的に指定してください。例: 7.5） | 14.83 + X |

推奨理由: 関数名と依頼文が「労働時間」なので、給与計算用の「みなし時間」は含めないのが自然だと考えました。

### Q3. 丸めの方法（float の一致判定に直接影響します）
| 選択肢 | ルール | E001 の値 |
|---|---|---|
| **A（推奨）** | 分単位で正確に合計し、**最後に従業員ごとに `round(hours, 2)`**（小数第 2 位、Python の round） | 14.83 |
| B | 丸めない（合計分数 / 60 の生の float） | 14.833333333333334 |
| C | 1 勤務ごとに **15 分単位で切り捨て**てから合計する（最後は丸めなし） | 14.75（5:50 → 5:45） |

推奨理由: 給与表示で一般的な小数第 2 位までにそろえつつ、丸め誤差がたまらないように最後に 1 回だけ丸めます。

## 3. Task Contract 案（推奨の既定値 Q1=A, Q2=A, Q3=A を前提にしています）

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装する。勤怠 CSV を読み、従業員 ID ごとに合計労働時間（時間単位の float）を返す。

### Scope
- CSV（`employee,date,type,start,end`）を読み込み、検証する。
- `work` 行の労働時間を計算する（日をまたぐ勤務にも対応: A1、A2）。
- `paid_leave` 行は Q2 に従って扱う（既定は 0 時間）。従業員のキーは残す（A4）。
- 従業員ごとに合計し、Q3 に従って丸める（既定は最後に `round(…, 2)`）。
- 不正なデータは `ValueError` にする（A5、A6）。

### Out of scope
- 深夜・残業・休日の区分、割増の計算
- 月をまたぐデータの分割や、対象月の指定（A3）
- 休憩の推定（Q1=A の場合）、打刻の丸め規定（Q3=C 以外）
- CLI、ファイル出力、外部ライブラリの導入、`shifts.csv` の変更
- テストファイルの作成（必要であれば別途指示してください）

### Data sources
- 入力: 引数 `path` で指定された CSV（形式は `shifts.csv` と同じ）
- 参照サンプル: 作業ディレクトリの `shifts.csv`（2026-10、3 名、6 行）

### Constraints
- Python 3.12、標準ライブラリだけを使う（A9）
- 作業ディレクトリの外は読まない・書かない
- 変更・作成するのは `solution.py` だけ（`shifts.csv` は読み取りのみ）
- 戻り値の値は `float` 型（整数時間でも `14.0` のように float にする）

### Definition of Done（検証できる条件）
1. `monthly_work_hours("shifts.csv")` が既定値（Q1=A、Q2=A、Q3=A）で **`{"E001": 14.83, "E002": 14.0, "E003": 9.25}`** と完全に一致する。
   - 内訳: E001 = 9:00 + 5:50 + 有給 0 = 14h50m → 14.83、E002 = 8:00（日またぎ）+ 6:00 = 14.0、E003 = 9:15 = 9.25
2. 戻り値の値がすべて `float` 型である。
3. 日をまたぐ勤務 `22:00–06:00` が 8.0 時間になる（マイナスや 16 時間にならない）。
4. `paid_leave` だけの従業員が `0.0` で結果に含まれる。
5. 不正な `type`、`work` 行で時刻が空欄、`25:00` のような不正な時刻のいずれかを含む CSV で `ValueError` が送出される。
6. ヘッダー行だけの CSV を渡すと `{}` が返る。
7. Q1〜Q3 で推奨以外を選んだ場合は、1. の期待値を上の表の値に置き換えて検証する。
