## 2. 確認できた事実 / 仮定 / 不足情報

### 確認できた事実
- 関数名、引数名、戻り値の形（`[{"sku": str, "qty": int相当}, ...]`）は依頼文で指定されています。
- 発注判断に使えそうな列は在庫（`stock`）、発注残（`on_order`）、リードタイム（`lead_time_days`）、安全在庫（`safety_stock`）、発注単位（`lot`）、廃番フラグ（`discontinued`）です。
- 出荷履歴は日次・品目別の数量です。出荷がない日の行はありません。
- 判断が分かれやすいケースがデータに含まれています。
  - **C400**: 出荷が途中で止まっているため、需要を見る期間によって発注するかどうかが変わります。
  - **A200**: `on_order` を数えないと在庫ポジションは 15 で、ROP（下記の発注点）もちょうど 15 になります。`<` と `<=` のどちらで判定するかで結果が変わります。
  - **B300**: 廃番で出荷もありません。在庫ポジション 5 と ROP 5 が等しくなります。
  - **A100**: ROP 41 に対して在庫ポジションが 40 で、不足は 1 です。発注単位 50 への丸め方で発注数が変わります。

### 仮定（質問の回答で上書きします）
- **発注点（ROP）** = 1日あたり需要 × `lead_time_days` + `safety_stock`
- **在庫ポジション** = `stock` + `on_order`
- `discontinued == true` の品目は発注対象から外します。
- 発注数が 0 以下の品目は戻り値に含めません。
- 戻り値は `sku` の昇順に並べます。`qty` は `int` で返します。
- `today` には `datetime.date` と `"YYYY-MM-DD"` 形式の文字列の両方を受け付けます。需要の計算には **`today` より前**の出荷だけを使います。
- `stock` は `today` 時点の在庫として扱います。
- `shipments.csv` に履歴がない品目は、需要 0 として扱います。
- 外部ライブラリは使わず、標準ライブラリ（`csv`、`datetime`、`math`）だけで実装します。

## 3. 質問（最大3問）

### Q1. 1日あたり需要はどう算出しますか？（C400 の結果が変わります）
- **A（推奨）**: `today` の前日までの**直近30日間**の出荷合計を、**30（暦日数。出荷がない日も含む）**で割る
- B: 直近 N 日間（N を指定してください。例: 14日、28日）で、A と同じ計算をする
- C: 履歴全体（最初の出荷日から `today` の前日まで）の合計を暦日数で割る
- D: 出荷があった日だけで平均する（出荷がない日は除く）

参考（Q2・Q3 が推奨案の場合）: `today=2026-11-10` のとき、A では C400 は発注不要です（需要 0）。C では C400 に 20 個発注します。

### Q2. 発注するかどうかは何で判定しますか？（A200 と B300 の結果が変わります）
- **A（推奨）**: `stock + on_order < ROP` のとき発注する（発注残を含め、等しい場合は発注しない）
- B: `stock + on_order <= ROP` のとき発注する（等しい場合も発注する）
- C: `on_order` を数えず、`stock < ROP`（または `<=`）で判定する

### Q3. 発注数はどう決めますか？（すべての品目の qty が変わります）
- **A（推奨）**: 不足分 `ROP − 在庫ポジション` を **`lot` の倍数に切り上げる**（例: A100 は不足 1 なので 50）
- B: 目標在庫（例: ROP + `lot`、または ROP + 需要 × 発注サイクル日数）まで補充し、`lot` の倍数に切り上げる
- C: 不足分をそのまま使う（`lot` で丸めない。小数は切り上げる）

## 4. Task Contract 案

### Outcome
`solution.py` に `reorder_plan(inventory_path, shipments_path, today)` を実装します。発注が必要な品目と発注数を、`[{"sku": "A100", "qty": 50}, ...]` の形で決まった順に返します。

### Scope
- CSV の読み込み（UTF-8、BOM あり・なし、CRLF・LF 改行に対応）
- 需要の算出（Q1）、発注の判定（Q2）、発注数の算出（Q3）
- 廃番品目の除外、発注不要の品目の除外、`sku` 昇順での並べ替え

### Out of scope
- CLI、ファイルへの出力、ログ出力
- 需要予測の高度化（季節性、トレンド、移動平均の重み付けなど）
- 発注先、価格、最小発注金額、倉庫を分けた管理
- 不正なデータの修復（必須列がない場合などは例外を送出し、黙って補正しません）

### Data sources
- `inventory_path`: `inventory.csv` と同じ形式
- `shipments_path`: `shipments.csv` と同じ形式
- `today`: 判定の基準日。`date` または `"YYYY-MM-DD"` 形式の文字列

### Constraints
- Python 3、標準ライブラリだけを使います。
- 入力ファイルを変更しません。関数に副作用はありません。同じ入力には同じ出力を返します。
- 浮動小数点の誤差で境界の判定がぶれないようにします（例: `fractions.Fraction` を使うか、整数演算で比較する）。
- `today` 以降の日付の出荷は、需要の計算に使いません。
