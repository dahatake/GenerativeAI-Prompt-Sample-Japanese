# Task Contract 案（Spec Mode）: `monthly_sales(path)`

## 1. 確認できた事実（作業ディレクトリ調査結果）

- 作業ディレクトリにあるのは `sales.csv`（488 bytes）だけ。`solution.py`、テスト、README、仕様書はない。
- `sales.csv` の形式: UTF-8（BOM なし）、改行は CRLF、ヘッダー 1 行とデータ 10 行。
- 列: `order_id, ordered_at, amount_incl_tax, status`
  - `order_id`: `A-1001`〜`A-1010`。すべて異なる値で、重複はない。
  - `ordered_at`: ISO 8601 形式の UTC 時刻（末尾 `Z`）。例: `2026-01-05T02:15:00Z`
  - `amount_incl_tax`: 列名から税込金額と判断できる。値はすべて整数。どれも 1,100 の倍数なので、10% 税抜きにしても割り切れる。
  - `status`: `completed`（8 件）と `cancelled`（2 件: A-1003 22000、A-1007 4400）。
- 負の金額が 1 件ある: `A-1006, 2026-02-14T11:11:00Z, -1100, completed`（返金や値引きの可能性がある）。
- 2026-03 のデータは 1 件もない（2026-01、02、04 だけ）。
- **月境界をまたぐ行がある**。UTC で集計するか JST で集計するかで、月が変わる:
  - `A-1004 2026-01-31T16:20:00Z`: UTC では 1 月、JST では 2026-02-01 01:20 で 2 月。
  - `A-1010 2026-04-30T15:30:00Z`: UTC では 4 月、JST では 2026-05-01 00:30 で 5 月。
- 実行環境は Python 3.12.10。`zoneinfo` で `Asia/Tokyo` を使えることを確認した。

### 参考: 解釈ごとの集計結果（このデータでの計算値）

| 解釈 | 結果 |
|---|---|
| **推奨既定**（JST、税込、completed のみ、負の金額も含める） | `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` |
| UTC、税込、completed のみ、負の金額も含める | `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}` |

| JST、税込、cancelled も含める | `{"2026-01": 38500, "2026-02": 15400, "2026-04": 18700, "2026-05": 7700}` |
| JST、税込、completed のみ、負の金額は除外 | `{"2026-01": 16500, "2026-02": 12100, "2026-04": 18700, "2026-05": 7700}` |

## 2. 仮定（既定値として埋めるもの）

- A1. 戻り値のキーは `"YYYY-MM"`、値は Python の `int`。データがある月だけを含め、キーは昇順に並べる。
- A2. 欠損月（例: 2026-03）はキーに含めない（0 で埋めない）。
- A3. 標準ライブラリだけを使う（`csv`, `datetime`, `zoneinfo`）。pandas は使わない。
- A4. ファイルは UTF-8 として読む。BOM があっても許容するため `utf-8-sig` で開く。改行は CRLF と LF の両方に対応する。
- A5. `ordered_at` にタイムゾーン情報がない値は UTC とみなす。
- A6. 不正な行（日時や金額を解釈できない、必須列がない）があれば `ValueError` を送出する。黙ってスキップはしない。
- A7. `order_id` の重複は考慮しない（現データには重複がない）。
- A8. `status` は前後の空白を除き、小文字にして比較する。

## 3. 不足情報

- 月の区切りに使うタイムゾーン（UTC か JST か）。
- 「売上」を税込で出すか税抜で出すか。税抜なら丸め方も必要。
- 集計対象にする `status` と、負の金額の扱い。
- `completed` / `cancelled` 以外の status が将来現れたときの扱い。

## 4. 質問（手戻りが大きいものだけ、最大 3 問）

> 選択肢のどれにも当てはまらない場合は、**具体的な値**（例:「UTC+9 固定」「税抜、行ごとに切り捨て」「completed と shipped を対象」）で回答してください。

### Q1. 月の区切りに使うタイムゾーンはどれですか？
CSV の時刻は UTC（`Z`）です。このデータでは A-1004 と A-1010 の 2 件で、集計月が変わります。
- **(a) 推奨: JST（Asia/Tokyo, UTC+9）に変換してから月を決める** → `2026-05` が出現する
- (b) UTC のまま月を決める
- (c) その他（具体的なタイムゾーンかオフセットを指定してください）

### Q2. 集計する金額は税込ですか、税抜ですか？
- **(a) 推奨: `amount_incl_tax` をそのまま合計する（税込、丸めなし）**
- (b) 税抜（税率 10%）: 行ごとに `amount * 100 / 110` を計算し、**0 方向に切り捨て**てから合計する
- (c) 税抜（税率 10%）: 月合計の税込額を 1.1 で割り、**四捨五入（half-up）**する
- (d) その他（税率と丸め方を具体的に指定してください）

※ 現データはすべて 1,100 の倍数なので、(b) と (c) の結果は同じです。違いが出るのは将来のデータだけです。

### Q3. どの行を集計対象にしますか？（status と負の金額）
- **(a) 推奨: `status == "completed"` の行だけを対象にし、負の金額（A-1006 の -1100）もそのまま加算する（純額）** → 2026-02 = 11000
- (b) `completed` だけを対象にし、負の金額の行は除外する → 2026-02 = 12100
- (c) status に関係なく全行を対象にする（cancelled も含める）
- (d) その他（対象にする status の値と、負の金額の扱いを具体的に指定してください）

## 5. Task Contract 案

### Outcome
`solution.py` に `monthly_sales(path)` を実装します。`path` で指定した `sales.csv` 形式のファイルを読み、Q1〜Q3 で確定したルールで月ごとの売上を合計して、`{"YYYY-MM": int}` の dict を返します。

### Scope
- `solution.py` を新規作成し、`monthly_sales(path)` を実装する。
- CSV の読み込み、タイムゾーン変換、status による絞り込み、金額の合計、エラー処理（A6）。

### Out of scope
- `sales.csv` の変更。
- CLI、グラフ、ファイル出力。
- 通貨換算。
- 重複注文の排除（A7）。
- pandas など外部ライブラリの導入。

- `sales.csv`（作業ディレクトリ内、列は `order_id, ordered_at, amount_incl_tax, status`）。
- 関数は任意の `path` を受け取る。テストでは同じ形式の別ファイルも使う想定。

- Python 3.12 と標準ライブラリだけを使う。
- 戻り値の値は `int` 型にする（`float` は使わない）。
- 作業ディレクトリの外は読み書きしない。
- 作成・変更するファイルは `solution.py` だけにする。`timing.txt` の追記と、必要ならテストファイルの作成は除く。

### Definition of Done（検証できる条件）
1. `from solution import monthly_sales` で import できる。
2. 推奨既定（Q1=a, Q2=a, Q3=a）が採用された場合、`monthly_sales("sales.csv") == {"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` が成り立つ。別の選択肢が選ばれた場合は、セクション 1 の表の該当する値を期待値にする。

6. ヘッダーだけの CSV なら `{}` を返す。不正な日時や金額を含む CSV なら `ValueError` を送出する。
