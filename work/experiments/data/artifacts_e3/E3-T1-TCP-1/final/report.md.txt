## 採用した仮定の一覧

- Q1: UTC の時刻を JST（UTC+9）に変換してから月を決める（回答）。
- Q2: 税抜で返す。月ごとの税込合計 × 10/11 を Decimal で厳密に計算し、ROUND_HALF_UP で int にする。丸め方は推奨案への委任を受けてエージェントが決めた。なお、.5 ちょうどになるケースは数学的に発生しない。
- Q3: `cancelled` の行だけを除外する。負の金額は純額として加算する（回答と推奨案）。
- 未知の status: `cancelled` 以外はすべて集計に含める（回答）。
- A2（変更）: 最初の月から最後の月までの欠損月を 0 で含める（回答）。
- A1: キーは `"YYYY-MM"` で昇順に並べる。値は int。
- A3: 標準ライブラリだけを使う。
- A4: `utf-8-sig` で読み込む。CRLF と LF の両方に対応する。
- A5: タイムゾーン情報のない日時は UTC とみなす。
- A6: 不正な行や必須列の欠落があれば ValueError を送出する。金額は整数だけを受け付ける。
- A7: `order_id` の重複は排除しない。
- A8: status は前後の空白を除き、小文字にして比較する。
- A9: 0 埋めする範囲は、集計対象の行（cancelled 以外）の最初の月から最後の月までとする。
- A10: 集計対象の行が 0 件なら `{}` を返す。
