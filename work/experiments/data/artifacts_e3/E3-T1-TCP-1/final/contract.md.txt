# Task Contract: `monthly_sales(path)` — **承認済み（Execution Mode）**

更新日: 2026-11-25（answers.md の回答を反映）

## 1. 確認できた事実

- `sales.csv` の形式: UTF-8（BOM なし）、CRLF 改行、ヘッダー 1 行とデータ 10 行。列は `order_id, ordered_at, amount_incl_tax, status`。
- `ordered_at` は UTC で記録されている（末尾 `Z`。回答 Q1 でも確認済み）。
- `amount_incl_tax` は税込の整数。負の値が 1 件ある（A-1006、-1100）。
- `status` には `completed` と `cancelled` がある。
- 2026-03 の注文はない。
- 月境界をまたぐ行がある: A-1004 は JST では 2026-02-01、A-1010 は JST では 2026-05-01。
- 実行環境は Python 3.12.10。

## 2. 確定した仕様（answers.md より）

| 項目 | 決定内容 | 出典 |
|---|---|---|
| Q1 タイムゾーン | UTC の時刻を JST（UTC+9）に変換してから月を決める | 回答 (a) |
| Q2 金額 | **税抜**で返す。月ごとの税込合計 × 10 / 11 を厳密に計算し、**四捨五入（ROUND_HALF_UP）**して int にする | 回答（税率 ÷1.1）。丸め方は推奨案に委任されたため、元の契約案の選択肢 (c) を採用（下の注記を参照） |
| Q3 行の対象 | `cancelled` の行だけを除外する。負の金額はそのまま加算する（純額） | 回答と推奨案 (a) |
| 未知の status | `cancelled` 以外の status はすべて集計に含める（例: refunded, pending, 空文字） | 回答 |
| A2 欠損月 | **最初の月から最後の月までの間にある月は、注文がなくても 0 として必ず含める** | 回答（元の仮定 A2 は不採用） |

注記（Q2 の丸め方）: 元の契約案では、税抜の丸め方に推奨案を指定していませんでした。回答は「推奨案で進めて」だったので、**誤差が最小になる「月合計 → ÷1.1 → 四捨五入」**を採用します。税込の整数 x について 10x/11 がちょうど .5 になることはありません（20x = 22n + 11 は左辺が偶数、右辺が奇数になり、整数解がない）。そのため、四捨五入で同値の端数をどちらに寄せるか（half-up か half-even か）は結果に影響しません。影響するのは「行ごとに丸めるか、月合計で丸めるか」の選択だけです。

## 3. 採用した仮定（回答で「推奨案で進める」とされたもの、または回答がないもの）

- A1. キーは `"YYYY-MM"` で昇順に並べる。値は `int`。
- A3. 標準ライブラリだけを使う（`csv`, `datetime`, `decimal`）。
- A4. ファイルは `utf-8-sig` で開く（BOM を許容）。改行は CRLF と LF の両方に対応する。
- A5. タイムゾーン情報のない日時は UTC とみなす。
- A6. 不正な行（日時や金額を解釈できない、値が足りない、必須列がない）があれば `ValueError` を送出する。金額は整数だけを受け付ける。
- A7. `order_id` の重複は排除しない。
- A8. `status` は前後の空白を除き、小文字にして `cancelled` と比較する。
- A9. 0 埋めする月の範囲は、**集計対象の行（cancelled 以外）**の最初の月から最後の月までとする。cancelled の行しかない月は範囲を広げない。
- A10. 集計対象の行が 0 件なら `{}` を返す。

## 4. Task Contract

### Outcome
`solution.py` の `monthly_sales(path)` が、セクション 2 のルールで集計した `{"YYYY-MM": 税抜金額(int)}` を返す。

### Scope
- `solution.py` を新規作成し、`monthly_sales(path)` を実装する。
- 検証用の `test_solution.py` を新規作成する。

### Out of scope
- `sales.csv` の変更、CLI、ファイル出力、通貨換算、重複排除、外部ライブラリの導入。
- 作業ディレクトリ外へのアクセス。

### Data sources
- `sales.csv`、およびテストで生成する同じ形式の CSV（作業ディレクトリ内の `_test_data/` に作成し、テスト後に削除する）。

### Constraints
- Python 3.12 と標準ライブラリだけを使う。
- 戻り値の値は int。float は使わない（金額は Decimal で厳密に計算する）。

### Definition of Done
1. `from solution import monthly_sales` で import できる。
2. `monthly_sales("sales.csv") == {"2026-01": 15000, "2026-02": 10000, "2026-03": 0, "2026-04": 17000, "2026-05": 7000}` が成り立つ。
3. 値はすべて `type(v) is int` を満たし、キーは `^\d{4}-\d{2}$` に一致し、昇順に並ぶ。
4. 最初の月から最後の月までの欠損月が 0 で含まれる。年をまたぐ場合も同様。
5. JST の月境界（UTC 14:59:59 と 15:00:00）が正しく振り分けられる。オフセット付きの日時と、タイムゾーンなしの日時（UTC とみなす）も正しく扱われる。
6. `cancelled` だけが除外される（大文字小文字や空白の違いは無視する）。それ以外の status と負の金額は加算される。
7. 税抜額は月合計 × 10/11 の四捨五入になる（行ごとに丸めた場合とは結果が異なるケースで検証する）。
8. ヘッダーだけの CSV では `{}` を返す。BOM 付きや CRLF のファイルも読める。不正な日時や金額、値の欠けた行、必須列の欠落では `ValueError` を送出する。
9. 1〜8 を確認する `python -m unittest -v test_solution` がすべて成功する。
