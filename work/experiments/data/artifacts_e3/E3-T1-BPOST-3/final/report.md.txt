# monthly_sales 実装レポート

## 実装内容
- `solution.py` の `monthly_sales(path, tz=JST, exclude_statuses=("cancelled",))`
- CSV (`order_id,ordered_at,amount_incl_tax,status`) を読み込み、JST の月ごとに `amount_incl_tax` を合算 → 税抜に換算して `{"YYYY-MM": int}` を月昇順で返す。
- 実行結果 (sales.csv): `{'2026-01': 15000, '2026-02': 10000, '2026-03': 0, '2026-04': 17000, '2026-05': 7000}`

## 前提 (answers.md の回答を反映)
1. **タイムゾーン (Q1 確定)**: `ordered_at` は UTC。JST に変換して月を判定する。
2. **キャンセル除外 (Q2 確定)**: `status == "cancelled"` は集計しない。
3. **負の金額 (Q3: 推奨案)**: 返金とみなし、そのまま差し引く。
4. **税抜換算 (Q4 確定)**: 税込 10% として `税込 / 1.1` を整数で返す。
   - 補足 (独自判断): 換算は注文ごとではなく**月合計に対して1回**行い、端数は**四捨五入**。sales.csv では端数は出ない。
5. **0 円月 (Q5 確定)**: 最初の月から最後の月まで、注文のない月も 0 で出力する。
   - 補足 (独自判断): 範囲は「集計対象 (キャンセル除外後) の注文がある最初/最後の月」。対象注文が1件もなければ `{}`。

## 今回の修正点
- 金額を税込から**税抜 (月合計 ÷ 1.1、四捨五入して int)** に変更 (Q4)。
- 最初の月〜最後の月の間で**注文のない月を 0 で補完**するよう変更 (Q5)。例: `2026-03: 0`。
- docstring をこの仕様に合わせて更新。
- タイムゾーン (JST)・キャンセル除外・返金の扱いは変更なし (Q1〜Q3 は現行の実装どおり)。
