# monthly_sales 実装レポート

## 実装内容
- `solution.py` の `monthly_sales(path, tz=JST, exclude_statuses=("cancelled",))`
- CSV (`order_id,ordered_at,amount_incl_tax,status`) を読み込み、月ごとに `amount_incl_tax` を合算し `{"YYYY-MM": int}` を月昇順で返す。
- 実行結果 (sales.csv): `{'2026-01': 16500, '2026-02': 11000, '2026-04': 18700, '2026-05': 7700}`

## 前提にしたこと（仕様が明示されていないため要確認）
1. **タイムゾーン**: `ordered_at` は UTC (`Z`) なので、日本の業務として **JST に変換して月を判定**。
   - 影響あり: A-1004 (01-31 16:20Z → 2月), A-1010 (04-30 15:30Z → 5月)。
   - UTC で集計したい場合は `tz=timezone.utc` → `{'2026-01': 19800, '2026-02': 7700, '2026-04': 26400}`
2. **キャンセル除外**: `status == "cancelled"` は売上に含めない (A-1003, A-1007)。
3. **負の金額 (A-1006: -1100)**: 返品・返金とみなし、そのまま差し引く。
4. **金額**: 税込 (`amount_incl_tax`) のまま集計。税抜換算はしない。
5. **売上ゼロの月** (例: 2026-03): キーを出力しない（0 埋めしない）。

## 確認したい点
- 月の境界は JST と UTC のどちらか / 税込・税抜どちらか / 返金の扱い / 0 円月を含めるか。
