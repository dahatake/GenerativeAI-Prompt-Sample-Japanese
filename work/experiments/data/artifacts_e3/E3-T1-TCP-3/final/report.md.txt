## 採用した仮定の一覧
回答で指定された仕様:
- 月の判定: `ordered_at`（UTC）を JST（UTC+09:00 固定）に変換して判定する（Q1）。
- 金額: 税抜（税率 10%）にする。各行で `sign(x) × (|x| × 10 // 11)` を計算して 0 方向へ切り捨て、月ごとに合計する。整数演算だけを使う（Q2、followup は推奨案）。
- 対象行: `status == "completed"` の行だけを集計する。cancelled は除外する（Q3）。
- 注文がない月: 最初の月から最後の月まで 0 で埋める（Q4、仮定を訂正）。

推奨既定案（回答で「推奨案で」と指定された点）:
- 負の金額は差し引く（純額）（Q3）。
- キーは昇順にする（Q5）。
- 不正な行は `ValueError` を送出し、スキップしない（Q6）。
- 未知の status の行は集計しない（Q7）。
- UTF-8 で読み、BOM 付きも許容する（Q8）。

値が指定されなかった細部（contract.md の B1〜B6）:
- B1: タイムゾーンのない `ordered_at` は UTC とみなす。
- B2: 日時と金額の検証は status にかかわらず全行で行う。
- B3: status は前後の空白を除いたうえで、大文字と小文字を区別して比較する。
- B4: 金額は整数文字列だけを受け付ける。
- B5: completed 行が 0 件の場合は `{}` を返す。
- B6: 0 埋めの範囲は completed 行の月の最小から最大までとする。
