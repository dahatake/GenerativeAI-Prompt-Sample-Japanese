## 1. 調査結果

### 確認できた事実（作業ディレクトリ内の調査結果）
- 作業ディレクトリにあるのは `sales.csv`（488 bytes）だけ。`solution.py`、テスト、README、既存コードはない。
- `sales.csv` は UTF-8（BOM なし）、改行は CRLF。ヘッダーは 1 行、データは 10 行。
- 列は `order_id, ordered_at, amount_incl_tax, status` の 4 つ。
- `ordered_at` は ISO 8601 形式の **UTC**（末尾 `Z`）。例: `2026-01-05T02:15:00Z`。
- `amount_incl_tax` は列名どおり **税込** の整数（円と思われる）。全件が 1,100 の倍数で、税率 10% の税込額と矛盾しない。
- `status` の値は `completed`（8 件）と `cancelled`（2 件: A-1003、A-1007）だけ。
- **負の金額が 1 件ある**: A-1006 `-1100 completed`（返金または値引きと思われる）。
- **2026-03 のデータがない**。対象期間は 2026-01〜2026-04（UTC 基準）。
- **UTC と JST で月が変わる行が 2 件ある**:
  - A-1004 `2026-01-31T16:20Z` → JST では 2026-02-01 01:20
  - A-1010 `2026-04-30T15:30Z` → JST では 2026-05-01 00:30
  - A-1003 `2026-01-20T23:30Z` は JST で 1/21 になるが、月は変わらない。

### 解釈ごとの期待値（`completed` のみ、負の金額を含む、税込の場合）
| 月 | JST 基準 | UTC 基準 |
|---|---|---|
| 2026-01 | 16500 | 19800 |
| 2026-02 | 11000 | 7700 |
| 2026-04 | 18700 | 26400 |
| 2026-05 | 7700 | （なし） |

→ タイムゾーンの決め方で 4 か月すべての値が変わります。

### 仮定（既定値で埋める点）
- A1: 入力の文字コードは UTF-8 とし、BOM 付き（`utf-8-sig`）でも読めるようにする。ヘッダー名は上記 4 列で固定する。
- A2: 戻り値のキーは `"YYYY-MM"`、値は Python の `int`。キーは昇順で作る（dict の挿入順）。
- A3: **データがない月（例: 2026-03）はキーに含めず、0 埋めもしない。** 対象行がすべて除外された月も同じ扱いにする。
- A4: 集計対象の行が 0 件なら `{}` を返す。
- A5: 日時の解釈に失敗した行、整数でない金額、必須列の欠落があれば `ValueError` を送出する。黙ってスキップはしない。
- A6: `completed` と `cancelled` 以外の未知の status は集計しない（Q3 の方針に従う）。
- A7: 外部ライブラリは使わず、Python 標準ライブラリ（`csv`、`datetime`、`zoneinfo` または固定 +09:00）だけで実装する。

### 不足情報
- 月を区切るタイムゾーン（UTC か JST か）→ Q1
- 売上を税込で集計するか税抜で集計するか。税抜の場合の丸め方 → Q2
- `cancelled` 行と負の金額の行の扱い → Q3
- データがない月を 0 埋めするか → 仮定 A3 で進めます（Open questions 参照）

### Q1. 月の区切りはどのタイムゾーンで判定しますか？（A-1004 と A-1010 の所属月が変わります）
- **(a) 推奨: JST（Asia/Tokyo, UTC+09:00 固定）に変換してから `YYYY-MM` を取る。** → 2026-01: 16500 / 02: 11000 / 04: 18700 / 05: 7700
- (b) UTC のまま `YYYY-MM` を取る。 → 2026-01: 19800 / 02: 7700 / 04: 26400
- (c) その他（タイムゾーン名またはオフセットを具体的に指定してください）

### Q2. 金額は税込・税抜のどちらで集計しますか？
- **(a) 推奨: 税込（`amount_incl_tax` をそのまま合計する）。**
- (b) 税抜・行単位: 各行で `amount_incl_tax * 100 // 110`（税率 10%、1 円未満は切り捨て）を計算してから合計する。
- (c) 税抜・月単位: 月の税込合計に `* 100 // 110`（税率 10%、切り捨て）を適用する。
- (d) その他（税率と丸め方。切り捨て・四捨五入・切り上げのどれかを具体的に指定してください）

### Q3. `cancelled` 行と負の金額の行はどう扱いますか？
- **(a) 推奨: `status == "completed"` の行だけを集計する。負の金額（A-1006 の -1100）は返金として差し引く（純額）。**
- (b) `completed` の行だけを集計し、負の金額の行は除外する。 → JST 基準の場合、2026-02 は 12100
- (c) status にかかわらず全行を集計する（`cancelled` も含め、負の金額も差し引く）。
- (d) その他（含める status の一覧と、負の金額の扱いを具体的に指定してください）

## 3. Task Contract 案

### Outcome
`solution.py` に `monthly_sales(path) -> dict[str, int]` を実装する。この関数は、指定された CSV を読み、月ごとの売上合計を `{"YYYY-MM": int}` で返す。

### Scope
- `solution.py` の新規作成と、その中の `monthly_sales(path)` の実装。
- 月の判定（Q1）、金額の定義（Q2）、行の絞り込み（Q3）を合意した仕様どおりに実装する。
