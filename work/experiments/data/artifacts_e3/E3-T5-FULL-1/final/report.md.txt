# reorder_plan 実装レポート

## 実装内容 (`solution.py`)
- `reorder_plan(inventory_path, shipments_path, today)` は `[{"sku": str, "qty": int}, ...]` を sku 昇順で返します。
- 1日平均出荷数 = `today-28日` ～ `today-1日` (両端含む、today 当日は除外) の出荷数合計 ÷ 28。
- 有効在庫 = `stock + on_order`。
- 発注点 = 1日平均出荷数 × `lead_time_days` + `safety_stock`。
- `有効在庫 <= 発注点` なら発注し、発注数 = `(発注点 − 有効在庫)` を `lot` の倍数に切り上げた値です。
- `discontinued` が true の品目は除外します。
- 浮動小数点の誤差で判定や切り上げがずれないよう、計算には `Fraction` を使っています。

## 前提にしたこと
- **有効在庫 = 発注点 の場合**: 不足数は 0 なので、そのまま切り上げると発注数が 0 になります。「この場合も発注対象とする」という要件に合わせて、最低 1 ロット (`lot`) を発注します。発注数 0 として返したい場合は、この点を変更する必要があります。
- `today` には `"YYYY-MM-DD"` 形式の文字列、`date`、`datetime` のどれでも渡せます。
- 直近28日間に出荷がない品目は、平均 0 として扱います。在庫表にない sku の出荷は無視します。
- `discontinued` は `true` / `1` / `yes` などを大文字小文字を区別せずに真と判定します。空欄は false とします。
- `on_order` などの数値列が空欄なら 0 とします。`lot` が空欄または 0 以下なら 1 とします。
- CSV は UTF-8 (BOM 付きでも可) として読み込みます。

## 動作確認 (同梱データ)
- today=2026-11-10 → `[{"sku": "A100", "qty": 50}]`
  - A100 は平均 3、発注点 41、有効在庫 40 で不足 1 → 50。
  - A200 は発注点 15、有効在庫 45 で対象外。
  - C400 は発注点 6、有効在庫 12 で対象外。
  - B300 は廃番のため除外。
- today=2026-10-11 → `[{"sku": "C400", "qty": 20}]`
  - C400 は発注点 31、有効在庫 12 で不足 19 → 20。
