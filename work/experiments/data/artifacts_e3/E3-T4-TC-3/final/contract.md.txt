## 1. 調査結果

### 1.1 確認できた事実

- 作業開始時点のファイルは `shifts.csv`、`answers.md`、`contract.md`、`timing.txt` で、`solution.py` はありませんでした。
- `shifts.csv` は列が `employee,date,type,start,end` で、UTF-8（BOM なし）、改行は LF、データは 6 行です。
- 日付はすべて 2026-10 です。`type` は `work` と `paid_leave` の 2 種類です。
- `paid_leave` の行は `start` / `end` が空です。
- 日付をまたぐ勤務（22:00→06:00）が 1 行あります。休憩の列はありません。

### 1.2 回答で確定したルール（answers.md）

- **Q1（休憩）**: 1 シフトの拘束時間が 6 時間を**超える**場合は、一律で 60 分を控除します。6 時間ちょうどは控除しません。
- **Q2（paid_leave）**: 所定労働時間の **7.5 時間**として計上します。
- **Q3（複数月）**: 推奨案 (a) を採用します。1 ファイル = 1 か月とし、月が混在していれば `ValueError` にします。
- **A1**: `end < start` は翌日に終了した勤務として扱います。計上月は推奨どおり開始日（`date`）の月です。
- **A3（変更）**: 丸めなしではなく、**シフトごとの実労働時間（休憩控除後）を 15 分単位で切り捨て**ます。
- **A2、A4〜A7、同一従業員・同一日の複数行**: 推奨案を採用します。

### 1.3 採用した仮定（回答で明示されておらず、こちらで解釈した点）

- H1. 休憩控除の要否（6 時間を超えるか）は、**15 分切り捨て前の拘束時間**で判定します。
  - 例: 6h10m は 6h を超えるので控除して 5h10m、切り捨てて 5.0h。
  - 根拠は、回答の文言「拘束時間が6時間を超える場合」です。
- H2. 処理順は「拘束時間 → 休憩控除 → 15 分切り捨て」です。控除が 60 分（15 の倍数）なので、切り捨てを控除の前に行っても後に行っても結果は同じです。
- H3. `paid_leave` は `start` / `end` の値に関係なく 7.5h 固定です。休憩控除と切り捨ては適用しません。
- H4. ヘッダーだけでデータ行がない CSV は `{}` を返します。

## 3. Task Contract

### Outcome

`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装します。CSV を読み、従業員ごとの月間労働時間（時間単位の float）を返します。

### Scope

- CSV の読み込み（列名ベース。BOM の有無どちらでも可）。
- `work` 行の勤務時間の計算:
  - 拘束時間 = `end - start`（`end < start` のときは +24h）
  - 拘束時間が 6h を超えれば 60 分を控除
  - シフトごとに 15 分単位で切り捨て
- `paid_leave` 行は 7.5h です。
- 従業員ごとに合計します。同一従業員・同一日の複数行も単純に合計します。
- 複数月の混在、未知の `type`、`work` 行の時刻の欠損・不正、必須列の欠如、日付の不正、従業員 ID が空の行は `ValueError` にします。

### Out of scope

- 残業・深夜・休日の割増の区分。
- 複数月の分割集計、月を指定する引数。
- CLI、外部ライブラリの導入。

### Data sources

- 入力 CSV（`path`）。サンプルは `shifts.csv` です。
- 列は `employee`、`date`(YYYY-MM-DD)、`type`(`work`|`paid_leave`)、`start`/`end`(HH:MM) です。

### Constraints

- Python 3 の標準ライブラリのみを使います。作業ディレクトリの外は読み書きしません。
- シグネチャは `monthly_work_hours(path)`、戻り値は `dict`（キーは `str`、値は `float`）です。入力ファイルは変更しません。

### Definition of Done（検証できる条件）

1. `from solution import monthly_work_hours` が成功する。
2. `monthly_work_hours("shifts.csv")` の結果が次と一致する（キー集合は完全一致、各値の誤差は 1e-9 以内）。
   - `E001` = **21.25**
     - 09:00-18:00: 9h → 8h
     - 09:00-14:50: 5h50m（控除なし）→ 5.75h
     - paid_leave: 7.5h
   - `E002` = **13.0**
     - 22:00-06:00: 8h → 7h
     - 13:00-19:00: ちょうど 6h なので控除なし → 6h
   - `E003` = **8.25**
     - 08:30-17:45: 9h15m → 8h15m → 8.25h
3. 値はすべて `float` 型である。
4. 休憩控除の境界が正しい: 拘束 6h00m → 6.0、6h01m → 5.0、6h10m → 5.0。
5. 15 分切り捨てがシフトごとに行われる: 14 分の勤務 2 件は合計 0.0、5h59m → 5.75。
6. `paid_leave` の行しかない従業員は 7.5 で返る。
7. 10/31 22:00 開始、11/01 06:00 終了のシフトは 10 月分として計上され、エラーにならない。
8. 次の場合はいずれも `ValueError` になる。
   - 未知の `type`
   - `work` 行で `start` が空
   - `25:00` のような不正な時刻
   - 2 か月分の行が混在している
   - 必須列が欠けている
9. 列の順序を入れ替えた CSV と BOM 付き CSV でも、2. と同じ結果になる。
10. ヘッダーだけの CSV では `{}` を返す。
