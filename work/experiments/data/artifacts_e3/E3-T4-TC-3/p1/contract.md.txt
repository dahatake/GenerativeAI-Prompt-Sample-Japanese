# Task Contract 案: `monthly_work_hours(path)`

ステータス: **ドラフト（Spec Mode）**。下の質問 Q1〜Q3 に回答をもらってから確定し、実装に入ります。

## 1. 調査結果

### 1.1 確認できた事実（作業ディレクトリ内のファイルで確認）

- 作業ディレクトリにあるのは `shifts.csv`（224 bytes）と `timing.txt` だけです。`solution.py`、既存テスト、仕様書、README はありません。
- `shifts.csv` の形式:
  - UTF-8 / ASCII で BOM なし、改行は LF、ヘッダーは 1 行です。
  - 列は `employee,date,type,start,end` です。
  - `employee` は `E001` 形式の文字列 ID です。
  - `date` は `YYYY-MM-DD` 形式です。
  - `start` / `end` は `HH:MM` 形式（24 時間表記）です。
- データは 6 行で、日付はすべて **2026-10** です（1 ファイル = 1 か月分に見えます）。
- `type` の値は `work` と `paid_leave` の 2 種類です。
- `paid_leave` の行（`E001,2026-10-03`）は `start` / `end` が空です。
- 日付をまたぐ勤務が 1 行あります（`end < start`）: `E002,2026-10-01,work,22:00,06:00`。
- 休憩を表す列（`break` など）はありません。
- 分単位の端数がある行があります: `09:00-14:50` = 5h50m、`08:30-17:45` = 9h15m。
- 従業員 1 人・1 日に 1 行だけで、同じ日の重複行はありません（このサンプルの範囲で確認）。

### 1.2 仮定（回答がなければこの前提で進めます）

- A1. 日付をまたぐ勤務（`end < start`）は終了時刻を翌日として計算します（22:00→06:00 = 8.0h）。勤務時間は `date`（開始日）の月に計上します。
- A2. `start == end` の `work` 行は 0h とします（24h 勤務とはみなしません）。
- A3. 戻り値の値は丸めない `float` です（例: 5h50m = 5.8333…）。比較には許容誤差 `1e-9` を使います。
- A4. 次の場合は黙って読み飛ばさず `ValueError` にします。
  - 未知の `type`
  - `work` 行で `start` / `end` が空、または `HH:MM` として解釈できない
  - ヘッダーに必須列が欠けている
- A5. 標準ライブラリ（`csv`、`datetime`）だけを使います。pandas などの外部依存は入れません。
- A6. CSV はヘッダー付き UTF-8 で読みます（BOM があっても `utf-8-sig` で許容します）。列の順序には依存せず、列名で読みます。
- A7. 戻り値のキーは CSV の `employee` 文字列そのままです（`"E001"`）。

### 1.3 不足情報

- `paid_leave` などの休暇行を労働時間としてどう扱うか（0h／所定時間を計上／集計から除外）。
- 休憩の控除ルール。休憩列がないため、拘束時間をそのまま労働時間とするのか、法定休憩を差し引くのか。
- 1 ファイルに複数月が含まれる場合の扱い。また、関数名は「monthly」なのに戻り値に月の次元がない点をどう扱うか。
- 端数処理（分単位の丸め、小数点以下の桁数）の要否。
- `work` / `paid_leave` 以外の `type`（例: `absence`、`holiday_work`）が今後増えるかどうか。

## 2. 確認したい質問（最大 3 問）

いずれも、回答によって集計値や戻り値の構造が変わり、推測が外れると手戻りが大きい点です。

### Q1. 休憩時間の控除

休憩列がありません。`start`〜`end` の時間をそのまま労働時間にしますか？

| 選択肢 | 内容 | E001 の例（10/01 09:00-18:00） |
|---|---|---|
| **(a) 推奨** | 控除しない（拘束時間＝労働時間） | 9.0h |
| (b) | 労基法の最低休憩を控除（6h 超→45 分、8h 超→60 分） | 8.0h |
| (c) | 一律で 1h を控除（勤務が 1h 未満なら 0h） | 8.0h |

**推奨既定案: (a)**。データに休憩の情報がないため、推測で差し引かないほうが安全です。必要になったら控除ルールを後から追加します。

### Q2. `paid_leave`（有給休暇）の扱い

| 選択肢 | 内容 |
|---|---|
| **(a) 推奨** | 0h として扱う（実労働時間だけを集計）。休暇しかない従業員も `0.0` でキーに含める |
| (b) | 所定労働時間（例: 8h）として計上する。何時間とするかも指定が必要 |
| (c) | 行ごと無視する。`work` 行がない従業員は戻り値に含めない |

**推奨既定案: (a)**。「労働時間」は実労働と解釈し、従業員の一覧は CSV に登場する全員を含めます。

### Q3. 「月間」の扱い（複数月データ／戻り値の構造）

戻り値が `{従業員ID: float}` なので月を区別できません。

| 選択肢 | 内容 |
|---|---|
| **(a) 推奨** | 1 ファイル = 1 か月を前提に、全行を合計する。開始日ベースで 2 か月以上が混在していたら `ValueError` |
| (b) | 引数を追加する（`monthly_work_hours(path, month="2026-10")`）。指定月の行だけを集計し、省略時は (a) と同じ動作 |
| (c) | 戻り値を `{従業員ID: {"YYYY-MM": float}}` に変える（指定の dict 形式から変わる） |

**推奨既定案: (a)**。依頼にあるシグネチャと戻り値の型をそのまま守り、複数月が混ざって誤って集計されることはエラーで防ぎます。

## 3. Task Contract 案（推奨既定案 Q1=(a)、Q2=(a)、Q3=(a) の場合）

### Outcome

`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装します。`shifts.csv` と同じ形式の CSV を読み、従業員ごとの労働時間（時間単位の float）を返します。

### Scope

- CSV の読み込み（列名ベース、UTF-8、BOM の有無どちらでも可）。
- `work` 行の勤務時間を計算します（`end - start`、日付またぐ場合は +24h）。
- `paid_leave` 行は 0h です。キーは作ります。
- 従業員ごとに合計します。
- 複数月の混在、未知の `type`、時刻の欠損・不正、必須列の欠如は `ValueError` にします。

### Out of scope

- 休憩の控除、残業・深夜・休日の割増の区分、端数の丸め。
- 複数月の分割集計、月の指定引数（Q3 で (b)/(c) が選ばれた場合は Scope に移します）。
- CLI、ファイル出力、外部ライブラリの導入。
- テストファイル（Definition of Done の検証はアドホックに実行します。テストファイルを残すかどうかは別途指示に従います）。

### Data sources

- 入力: `path` で指定される CSV。サンプルは作業ディレクトリの `shifts.csv` です。
- 列: `employee`、`date`(YYYY-MM-DD)、`type`(`work`|`paid_leave`)、`start`(HH:MM)、`end`(HH:MM)。

### Constraints

- Python 3 の標準ライブラリのみを使います。
- 作業ディレクトリの外は読み書きしません。
- 関数のシグネチャは `monthly_work_hours(path)` です。戻り値は `dict`（キーは `str`、値は `float`）です。
- 入力ファイルを変更しません。

### Definition of Done（検証できる条件）

1. `from solution import monthly_work_hours` が成功する。
2. `monthly_work_hours("shifts.csv")` の結果が次と一致する（各値の誤差は `1e-9` 以内、キー集合は完全一致）。
   - `E001` = 9 + 5 + 50/60 = **14.833333…**（paid_leave は 0）
   - `E002` = 8（日付またぎ 22:00→06:00）+ 6 = **14.0**
   - `E003` = 9 + 15/60 = **9.25**
3. 値はすべて `float` 型である。
4. `paid_leave` の行しかない従業員を含む CSV では、その従業員が `0.0` で返る。
5. 次の CSV ではいずれも `ValueError` になる。
   - 未知の `type`
   - `work` 行で `start` が空
   - `25:00` のような不正な時刻
   - 2 か月分の行が混在している
6. 列の順序を入れ替えた CSV と、BOM 付き CSV でも、2. と同じ結果になる。

### Evidence（完了報告に添えるもの）

- DoD 1〜6 を確認したコマンドとその出力（実際の値の dict と、各 `ValueError` が送出されたこと）。
- 変更・作成したファイルの一覧（`solution.py`。必要なら検証用の一時ファイルと、その削除の記録）。
- 採用した前提（A1〜A7 と、Q1〜Q3 への回答）の要約。

### Open questions

- Q1〜Q3（上記）。回答がなければ推奨既定案で確定します。
- 仮定 A1（日付をまたぐ勤務は開始日の月に計上）、A3（丸めなし）、A4（不正行は `ValueError`。スキップではない）は、違っていれば指摘してください。
- 同じ従業員・同じ日に複数行がある場合（分割勤務）は単純に合計する想定です。重複データとして扱う必要があれば教えてください。
