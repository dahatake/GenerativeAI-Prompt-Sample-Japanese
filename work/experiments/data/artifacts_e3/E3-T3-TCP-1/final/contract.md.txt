# Task Contract 案: validate_invoice_id(value) -> bool

## 1. 調査結果

### 確認できた事実
- 作業ディレクトリには `samples.txt` しかありません（作業開始時点）。`solution.py`、既存テスト、仕様書、README はありません。
- `samples.txt` の内容は「最近発行された請求書番号の例:」の見出しと、次の4件です。いずれも**有効な例**として書かれています。無効な例はありません。
  - `INV-202601-0001`
  - `INV-202601-0002`
  - `INV-202512-0347`
  - `INV-202603-1200`
- 4件はすべて同じ形です: `INV` + `-` + 数字6桁 + `-` + 数字4桁（全15文字、大文字、前後に空白なし）。
- 中央の6桁は `YYYYMM`（年4桁 + 月2桁）と読めます。年は 2025 / 2026、月は 01 / 03 / 12 です。
- 末尾の4桁はゼロ埋めされた連番と読めます（0001, 0002, 0347, 1200）。月ごとに 0001 から始まるように見えます（202601 に 0001 と 0002 があります）。
- 今日は 2026-11-25 です。`INV-202603-1200` は過去の月です。将来の月（例: 202612 以降）の例はありません。

### 仮定（例からの推測で、明記はされていません）
- 6桁の部分は発行年月（YYYYMM）を表す。
- 4桁の部分は連番で、チェックディジットではない（4件の例では検算方法は分かりません）。
- 「正しい番号」とは**書式が正しいこと**を指す。実在するか（発行済みか、DB に登録されているか）は確認しない。

### 不足情報
- 年月をどこまで検証するか（月が 01〜12 か、年の範囲、未来の年月を認めるか）。
- 入力をどこまで許容するか（小文字、前後の空白、全角文字、str 以外の型）。
- 連番 `0000` を認めるか、5桁以上を認めるか。
- 無効例と正式な仕様書がないため、境界値は例だけでは決められません。

## 2. 質問（最大3問。どの選択肢にも当てはまらない場合は、具体的な値で回答してください）

### Q1. YYYYMM（年月）の検証範囲
- A: 数字6桁であれば何でも可（`INV-209913-0001` も True）
- **B（推奨）: 月は `01`〜`12` に限る。年は `1000`〜`9999`（先頭が0の年は False）。未来の年月も可**
- C: B に加えて、年を `2000`〜`2099` に限る
- D: C に加えて、未来の年月は不可。実行日の年月（`datetime.date.today()`）より後なら False。テスト用に基準日を渡せる引数 `today=None` を追加する
- 理由: 外れた場合、判定結果が大量に反転します。D は実行日によって結果が変わるため、テストの設計も変わります。

### Q2. 入力の許容範囲（正規化するか）
- **A（推奨）: 厳格に判定します。`str` 型で、ASCII の `INV-` + 数字6桁 + `-` + 数字4桁に完全一致するときだけ True。小文字 `inv-`、前後の空白・改行、全角数字はすべて False。`str` 以外（None、int、bytes など）は例外を出さず False**
- B: 前後の空白（`str.strip()`）を除いてから判定する。大文字小文字は区別する
- C: 前後の空白を除き、大文字小文字も区別しない（`inv-202601-0001` も True）
- D: A と同じだが、`str` 以外の型には `TypeError` を送出する
- 理由: 呼び出し側（フォーム入力か、DB の値か）によって正解が変わります。また、例外を出すか False を返すかで呼び出し側のコードが変わります。

### Q3. 連番4桁の範囲
- **A（推奨）: ちょうど4桁で、`0001`〜`9999`（`0000` は False）**
- B: ちょうど4桁で、`0000`〜`9999`
- C: 4桁以上（10000件を超えると `10000` のように桁が増える前提）。ただし `0000` は False
- 理由: 例から「0001 始まり」は読み取れますが、上限や0の扱いは分かりません。桁数の仮定が外れると、正規表現とテストを両方作り直すことになります。

## 2.5 回答（answers.md、2026-11-25）
- Q1: 選択肢外 → **年 `2020`〜`2099`、月 `01`〜`12`。範囲内なら未来の年月も True。**
- Q2: **A**（厳格。小文字・区切り違い・前後空白・全角は False、str 以外は例外なしで False）
- Q3: **A**（ちょうど4桁、`0001`〜`9999`、`0000` は False）
- Open questions: プレフィックス大文字 `INV` 固定・区切りは半角 `-` のみを確定。その他は推奨案どおり。

## 3. Task Contract（承認済み / Execution Mode）

### Outcome
- `solution.py` に `validate_invoice_id(value) -> bool` があり、請求書番号の**書式**が正しいときは `True`、それ以外は `False` を返す。

### Scope
- `solution.py` を新規作成し、`validate_invoice_id` を実装する（標準ライブラリ `re` のみ）。
- 有効な書式: `INV-` + 年4桁 + 月2桁 + `-` + 連番4桁 に**完全一致**すること。
  - 数字は ASCII `[0-9]` のみ（`\d` は全角数字に一致するため使わない）。
  - `re.fullmatch` を使い、末尾改行も不可。
  - 年 `2020`〜`2099`、月 `01`〜`12`、連番 `0001`〜`9999`。未来の年月も範囲内なら可（実行日に依存しない）。
  - プレフィックスは大文字 `INV` 固定、区切りは半角 `-` のみ。
  - 入力が `str` 以外（`str` のサブクラスは str として扱う）なら `False`。

### Out of scope
- 番号の実在・発行済み・重複の確認。
- 正規化（大文字化・空白除去）や整形。
- 採番・生成。
- チェックディジット検証。
- `samples.txt` の変更。
- テストファイルの作成（検証は標準入力から渡す Python スクリプトで行い、ファイルは残さない）。

### Data sources
- `samples.txt`（有効例4件）、`answers.md`（Q1〜Q3 と Open questions への回答）。

### Constraints
- Python 標準ライブラリのみ。作業ディレクトリ外は読み書きしない。
- シグネチャは `validate_invoice_id(value)`、戻り値は常に `bool`。
- どんな入力にも例外を送出しない。

### Definition of Done（検証できる条件）
1. `solution.py` が存在し、`from solution import validate_invoice_id` が成功する。
2. `samples.txt` の4件すべてで `True` を返す。
3. 次の入力で `False` を返す:
   - 型: `""`、`None`、`202601`（int）、`b"INV-202601-0001"`、`["INV-202601-0001"]`
   - 表記: `"inv-202601-0001"`、`"Inv-202601-0001"`、`" INV-202601-0001"`、`"INV-202601-0001 "`、`"INV-202601-0001\n"`
   - 区切り: `"INV_202601_0001"`、`"INV202601-0001"`、`"INV-202601–0001"`（全角系ダッシュ）、`"INV－202601-0001"`（全角ハイフン）
   - 月: `"INV-202600-0001"`、`"INV-202613-0001"`
   - 年: `"INV-201912-0001"`、`"INV-210001-0001"`、`"INV-100001-0001"`、`"INV-999912-0001"`
   - 連番: `"INV-202601-0000"`、`"INV-202601-001"`、`"INV-202601-00001"`
   - その他: `"INV-20261-0001"`、`"ABC-202601-0001"`、`"INV-２０２６０１-0001"`（全角数字）
4. 境界値で `True` を返す: `"INV-202001-0001"`、`"INV-209912-9999"`、`"INV-202612-0001"`、`"INV-202601-9999"`、`"INV-205006-0500"`（未来の年月）。
5. 3 と 4 のどの入力でも例外を送出しない。
6. 戻り値の型が常に `bool`（`type(r) is bool`）。
