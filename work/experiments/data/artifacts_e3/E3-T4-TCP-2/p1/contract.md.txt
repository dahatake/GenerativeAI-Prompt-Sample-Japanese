# Task Contract 案: `monthly_work_hours(path)`（Spec Mode）

## 1. 調査結果

作業ディレクトリにあるのは `shifts.csv` と `timing.txt` だけです。既存の `solution.py`、テスト、仕様書、README はありません。

### 確認できた事実（`shifts.csv` から確認）
- ヘッダー: `employee,date,type,start,end`（5列）。ファイルは 224 バイトで、データは 6 行です。
- 文字コード・形式: BOM なしの ASCII（UTF-8 互換）、改行は CRLF、末尾に改行あり。
- `employee` は `E001` 形式の文字列で、E001/E002/E003 の 3 名が含まれます。
- `date` は `YYYY-MM-DD` 形式です。全行が 2026-10 で、1 か月分のデータです。
- `type` には `work` と `paid_leave` の 2 種類があります。
- `start`/`end` は `HH:MM`（24 時間表記）です。`paid_leave` 行では空欄です。
- 日付をまたぐ勤務があります: `E002,2026-10-01,work,22:00,06:00`（end < start）。
- 休憩時間の列はありません。
- 確認のために注目した行:
  - `E001 09:00-18:00`（拘束 9h）
  - `E001 09:00-14:50`（5h50m。6h をわずかに下回ります）
  - `E002 13:00-19:00`（ちょうど 6h）
  - `E003 08:30-17:45`（9h15m）
  - `E001 2026-10-03 paid_leave`（時刻なし）
- 戻り値の型: `{従業員ID(str): 労働時間(時間, float)}`（依頼文で指定）。

### 仮定（質問にしない既定値）
- A1: 日付をまたぐ勤務は `end <= start` のとき `end + 24h` として計算し、全時間を `date`（開始日）の月に計上します。22:00-06:00 は 8.0h です。
- A2: 入力ファイルは 1 か月分です。複数の月が含まれていても月で分けずに合計します（戻り値に月のキーがないため）。
- A3: `type=work` 以外の行だけを持つ従業員も、値 `0.0` で dict に含めます。
- A4: 不正なデータ（必須列がない、`work` 行の時刻が空欄・形式不正、未知の `type`）は `ValueError` にします。`start == end` の `work` 行も `ValueError` にします（0h か 24h か判断できないため）。
- A5: 読み込みは `encoding="utf-8-sig"` と `newline=""` で行い、BOM の有無と CRLF/LF のどちらにも対応します。前後の空白は除去します。
- A6: 実装には標準ライブラリ（`csv`、`datetime`）だけを使い、外部依存は使いません。
- A7: 同じ従業員・同じ日付の行が複数ある場合も、すべて合算します（重複は除去しません）。

### 不足情報
- 休憩時間をどう差し引くか（データに休憩列がない）→ Q1
- `paid_leave` を労働時間に含めるか → Q2
- 戻り値の丸め方（5h50m = 5.8333… が発生する）→ Q3
- 深夜・残業の区分や割増は依頼に含まれないため、扱いません（Out of scope）。

## 2. 質問（最大3問。外れたときの手戻りが大きいもの）

選択肢のどれでもない場合は、**具体的な値**（例: 「拘束 7h 超で 30 分控除」「15 分単位で切り捨て」）で回答してください。

### Q1. 休憩時間の控除（全員の数値が変わります）
- **(a) 控除しない【推奨既定】**: 労働時間 = end − start（拘束時間そのまま）。データに休憩列がないためです。
  - 期待値: E001 = 9 + 5.8333 = **14.8333**、E002 = 8 + 6 = **14.0**、E003 = **9.25**
- (b) 労基法の最低休憩を控除: 1 シフトの拘束時間が **6h 超で 45 分**、**8h 超で 60 分**を差し引きます（ちょうど 6h/8h は控除なし）。
  - 期待値: E001 = 8 + 5.8333 = **13.8333**、E002 = 7.25 + 6 = **13.25**、E003 = **8.25**
- (c) 一律控除: 拘束時間が **6h 以上なら 60 分**を差し引きます。
  - 期待値: E001 = 8 + 5.8333 = **13.8333**、E002 = 7 + 5 = **12.0**、E003 = **8.25**

### Q2. `paid_leave`（有給）の扱い
- **(a) 0h として扱う【推奨既定】**: 実労働時間ではないため加算しません。その従業員は dict には含めます。
- (b) 1 日 **8.0h** として加算します。この場合、E001 は Q1(a) で 22.8333 になります。
- (c) 所定時間を別の値（例: **7.5h**）で加算します。値を指定してください。

### Q3. 戻り値の丸め
- **(a) 丸めない【推奨既定】**: 分単位で合計し、最後に `/ 60` します（例: 5h50m → 5.833333…）。検証は許容誤差 1e-9 で行います。
- (b) 従業員ごとの合計を `round(x, 2)` で小数 2 桁に丸めます（14.8333… → 14.83）。
- (c) シフトごとに **15 分単位で切り捨て**てから合計します（5h50m → 5.75h）。

## 3. Task Contract 案

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装します。`shifts.csv` 形式の CSV を読み、従業員ごとの月間労働時間（時間単位の float）を返します。

### Scope
- CSV を読み込み、ヘッダー（`employee,date,type,start,end`）の列名でアクセスします。
- `work` 行の労働時間を計算します。日付をまたぐ勤務にも対応し（A1）、休憩の扱いは Q1、丸めは Q3 に従います。
- `paid_leave` は Q2 に従って扱います。
- 不正なデータは `ValueError` にします（A4）。

### Out of scope
- 深夜・残業・休日の区分や割増計算、給与計算
- 複数月を月ごとに分けた出力（A2）
- CLI、ファイル出力、外部ライブラリ、タイムゾーン・夏時間の考慮
- `solution.py` 以外のファイル変更（テストを追加する場合は、別途合意してから行います）

### Data sources
- 作業ディレクトリ内の `shifts.csv`（上記の事実を参照）。ほかにデータソースはありません。

### Constraints
- Python 標準ライブラリだけを使います。関数名・引数・戻り値の型は依頼どおりにします。
- 作業ディレクトリの外のファイルは読み書きしません。
- 戻り値のキーは CSV の `employee` 文字列をそのまま使います。値は必ず `float` にします。

### Definition of Done（検証できる条件）
1. `from solution import monthly_work_hours` が成功する。
2. `monthly_work_hours("shifts.csv")` のキーの集合が `{"E001","E002","E003"}` になり、すべての値が `float` である。
3. 値が Q1〜Q3 の回答に対応する期待値と一致する。既定案（Q1a/Q2a/Q3a）では `E001 ≈ 14.833333`、`E002 == 14.0`、`E003 == 9.25` で、誤差は 1e-9 以内。
4. 日付をまたぐ勤務: `22:00-06:00` が 8.0h として計上される。
5. `paid_leave` だけを持つ従業員が `0.0`（Q2a の場合）で含まれる。
6. `work` 行で時刻が空欄、未知の `type`、`start == end` のいずれかがあると `ValueError` になる。
7. BOM 付き UTF-8 と LF 改行の CSV でも、同じ結果になる。

- 上記 DoD 1〜7 を確認するスクリプト（一時スクリプトまたは合意したテスト）の実行コマンドと出力
