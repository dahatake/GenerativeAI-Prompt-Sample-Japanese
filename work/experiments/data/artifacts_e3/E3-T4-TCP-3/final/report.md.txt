人間の確認が必要な点: 6h01〜6h59 の勤務は、60 分を控除すると 6h 未満になり、控除しない 6h ちょうどの勤務より短く計上される（例: 6:30 → 5.5h）。これは回答どおりの仕様だが、業務上それでよいかは確認を推奨する。

## 採用した仮定
- A1（回答で確定）: end < start の場合は、翌日に終了した勤務として扱う。
- A2: 日付をまたぐ勤務は、全時間を開始日の勤務として数える。
- A3: ファイル内の全行を合計する。月でフィルタしたり分割したりはしない。
- A4: `work` と `paid_leave` 以外の type は 0h とする（その従業員もキーとして返す）。
- A5: start == end の work 行は 0h とする。
- A6: `utf-8-sig` で読み込み、列はヘッダー名で参照する。employee は前後の空白を除いてキーにする。
- A7: work 行の start / end が空または不正な場合、employee が空の場合は ValueError を送出する。
- A8: 標準ライブラリだけを使う。
- 補足: 計算は整数の分で行い、最後に /60 して float にする。paid_leave 行の start / end は無視する。休憩控除と切り捨ては paid_leave には適用しない（7.5h は 15 分の倍数なので結果に影響はない）。
