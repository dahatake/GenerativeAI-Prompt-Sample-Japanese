# Task Contract 案: `monthly_work_hours(path)`（Spec Mode・未実装）

## 1. 確認できた事実（作業ディレクトリ内の調査結果）

- 作業ディレクトリには `shifts.csv` しかない（`solution.py`、テスト、仕様書、README はない）。
- `shifts.csv`: UTF-8（BOMなし）、改行は LF、ヘッダー 1 行とデータ 6 行。
  ```
  employee,date,type,start,end
  E001,2026-10-01,work,09:00,18:00
  E001,2026-10-02,work,09:00,14:50
  E001,2026-10-03,paid_leave,,
  E002,2026-10-01,work,22:00,06:00
  E002,2026-10-02,work,13:00,19:00
  E003,2026-10-01,work,08:30,17:45
  ```
- 列は `employee`（例: `E001`）、`date`（`YYYY-MM-DD`）、`type`、`start` / `end`（`HH:MM`）の 5 つ。
- **休憩時間の列はない**。9 時間を超える勤務がある（E001 10/01 の 09:00–18:00 = 9h、E003 の 08:30–17:45 = 9.25h）。
- `type` には `work` と `paid_leave` がある。`paid_leave` の行は `start` / `end` が空。
- **日付をまたぐ勤務がある**（E002 10/01 の 22:00–06:00。end < start）。
- **割り切れない時間がある**（E001 10/02 の 09:00–14:50 = 5h50m = 5.8333…h）。
- サンプルのデータはすべて 2026-10 のもの。関数の引数は `path` だけで、対象月を指定する引数はない。
- 実行環境は Python 3.12.10。

## 2. 仮定（質問しない項目。この仮定で進めます）

- A1: 勤務 1 件の労働時間は `end - start` とする。`end < start` の場合は翌日の `end` として扱う（22:00–06:00 = 8h）。
- A2: 日付をまたぐ勤務は、全時間を `date`（開始日）の勤務として数える。
- A3: 関数はファイル内の全行を集計し、月によるフィルタや月ごとの分割はしない（ファイルには 1 か月分だけが入っている前提）。戻り値は `{employee: float}` のみ。
- A4: `work` と `paid_leave` 以外の `type` は労働時間 0 として扱う。
- A5: `start == end` の `work` 行は 0h とする（24h 勤務とは解釈しない）。
- A6: 読み込みは `utf-8-sig` で行い、BOM の有無どちらにも対応する。ヘッダー名で列を参照するため、列の順序には依存しない。`employee` の値は前後の空白を除いた文字列のまま dict のキーにする。
- A7: `work` 行の `start` / `end` が空または `HH:MM` 形式でない場合は `ValueError` を送出する（黙ってスキップしない）。
- A8: 外部ライブラリは使わない（標準ライブラリの `csv` と `datetime` のみ）。

## 4. 質問（手戻りが大きいものだけ、3 問）

選択肢のどれにも当てはまらない場合は、**具体的な値**（例: 「6h 超で 30 分控除」「有給は 7.5h」「各勤務を 1 分単位で切り捨てる」など）で回答してください。

### Q1. 休憩時間の控除（全員の数値が変わります）
- **(a) 推奨: 控除しない。** `end - start` をそのまま労働時間とする（CSV に休憩の列がないため）。
  → サンプルの期待値: E001 = 14.8333…、E002 = 14.0、E003 = 9.25
- (b) 労働基準法の最低ラインで控除する。勤務 1 件の拘束時間が 6h を超え 8h 以下なら 0.75h、8h を超えるなら 1.0h を引く（6h ちょうどは控除なし）。
  → E001 = 8.0 + 5.8333 = 13.8333…、E002 = 7.0 + 6.0 = 13.0、E003 = 8.25
- (c) 拘束時間が 6h 以上の勤務から一律 1.0h を引く。
  → E001 = 13.8333…、E002 = 13.0、E003 = 8.25

### Q2. `paid_leave` の扱い（E001 の値と、キーの出方が変わります）
- **(a) 推奨: 労働時間に含めない（0h）。** ただし、CSV に出てくる従業員は全員キーとして返す（有給だけの従業員は `0.0`）。
- (b) 1 日あたり 8.0h として加算する（E001 = 14.8333… + 8.0）。
- (c) 0h として扱い、`work` 行がない従業員はキーごと返さない。

### Q3. 丸め（期待値の比較方法が変わります）
- **(a) 推奨: 戻り値は丸めない。** float のまま返し（E001 = 14.833333…）、テストは `abs(x - expected) < 1e-9` で比較する。
- (b) 従業員ごとの合計を小数 2 桁に四捨五入する（`round(x, 2)` → E001 = 14.83）。
- (c) 勤務 1 件ごとに 15 分単位で切り捨ててから合計する（09:00–14:50 → 5.75h、E001 = 14.75）。

## 5. Task Contract 案

### Outcome
`solution.py` に `monthly_work_hours(path) -> dict[str, float]` を実装する。勤怠 CSV を読み込み、従業員 ID ごとの月間労働時間（単位: 時間、float）を返す。

### Scope
- `shifts.csv` と同じ形式（列は `employee,date,type,start,end`）の CSV を読み込む。
- `work` 行の時間計算。日付をまたぐ勤務にも対応する（A1・A2）。
- Q1 で決まる休憩控除、Q2 で決まる `paid_leave` の扱い、Q3 で決まる丸めを適用する。
- 不正な `work` 行では `ValueError` を送出する（A7）。

### Out of scope
- 月によるフィルタや月ごとの分割（A3）。
- 残業・深夜・休日の区分や割増の計算、給与計算。
- 同じ従業員の勤務が重複していないかの検出。
- CLI、ファイル出力、外部ライブラリの導入。
- `solution.py` 以外のファイルの作成（テストを作る場合は、合意したうえで別途作成する）。

### Data sources
- 入力: `path` で指定する CSV（サンプルは作業ディレクトリの `shifts.csv`）。
- 上記以外のデータソースは使わない。

### Constraints
- Python 3.12、標準ライブラリのみ。
- 作業ディレクトリの外にあるファイルは読み書きしない。
- 入力ファイルは変更しない（読み取り専用）。

### Definition of Done（検証できる条件）
1. `from solution import monthly_work_hours` が成功する。
2. `monthly_work_hours("shifts.csv")` が、Q1〜Q3 の回答に対応する期待値と一致する。推奨案の (a)/(a)/(a) なら `{"E001": 14.8333…, "E002": 14.0, "E003": 9.25}` で、各値は誤差 1e-9 以内。
3. 戻り値の型が `dict` で、キーは `str`、値は `float`。
4. 日付をまたぐ勤務（22:00–06:00）が 8.0h として計算される。
5. `paid_leave` が Q2 で決めたとおりに扱われる。
6. `work` 行の `start` が空のとき `ValueError` が送出される。
7. BOM 付きの UTF-8 CSV でも同じ結果になる。
