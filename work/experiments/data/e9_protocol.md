# E9 分類の手順（盲検の判定者に渡す定義）

作成: 2026-11-26（判定者の実行前に固定）

## 判定の対象

T1〜T6 の隠し要件 32 件。判定者に渡すのは、各課題の依頼文、作業ディレクトリの入力ファイル、要件の文面だけである。被験エージェントの成果物、合格率、条件名は渡さない。

## 2つの軸

1. **cue（論点の手がかり）**: 依頼文または入力ファイルの中に、注意深い実装者が「この点は決める必要がある」と気づける具体的な手がかりがあるか。
   - yes の例: 列の値に cancelled がある。時刻に Z（UTC）が付いている。end が start より前の行がある。type に paid_leave の行がある。
   - no の例: データにも依頼文にも、その論点が存在することを示すものがない。
2. **value（値の導出）**: 手がかりから、要件の具体的な値（閾値、率、丸め方、順序など）まで一意に導けるか。
   - yes: データや依頼文だけから、要件と同じ値に決まる。
   - no: 論点は分かっても、値は依頼者に聞かないと決まらない。

## 出力

要件ごとに `{"id": "T1-R1", "cue": "yes|no", "value": "yes|no", "evidence": "根拠となるファイルと行（1文）"}` の JSON 配列。

## 判定者

- 判定者 A: general-purpose エージェント（既定モデル）
- 判定者 B: explore エージェント（既定モデル）
- 2者の一致率を報告し、不一致の要件は、両者の判定を併記して、主分析では判定者 A の判定を使う。感度分析として、両者が一致した要件だけでも集計する。

## 分析（事前登録 H28）

v2/v3 の B 条件と TC 系条件（TC、TCP、TC+）の Phase 1/最終の要件ごとの合格率を、cue の yes/no で層別に記述する。
