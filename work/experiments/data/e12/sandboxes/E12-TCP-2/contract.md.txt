# 1. 確認できた事実

### 入力仕様
- CSVには `order_id`, `ordered_at`, `amount_incl_tax`, `status` の4列がある。
- `ordered_at` はすべて `Z` で終わっており、提示データ上はUTC時刻。
- `amount_incl_tax` は提示データではすべて整数表記。
- `status` は `completed` と `cancelled` の2種類。
- `completed` にも負額 `-1100` が1件ある。

### 日付の重要な境界
UTCの年月をそのまま使う場合：
- 2026-01: A-1001〜A-1004
- 2026-02: A-1005〜A-1007
- 2026-03: **レコードなし**
- 2026-04: A-1008〜A-1010

ただしタイムゾーンを UTC+09:00 とすると、少なくとも次が翌月へ移ります。

- `A-1004`: `2026-01-31T16:20:00Z` → **2026-02-01 01:20**
- `A-1010`: `2026-04-30T15:30:00Z` → **2026-05-01 00:30**

したがってタイムゾーン指定は実際に期待結果を変えます。

### statusによる差
例えばUTC基準で全statusを集計すると、1月には cancelled の `22000` が含まれます。`completed` のみなら含まれません。

# 2. 仮定

質問への回答で変更されない限り、以下を仮定します。

- CSVはヘッダー付き。
- `amount_incl_tax` は **整数として読み込み、整数として加算**する。
- **負額もそのまま売上金額に加算する**。したがって `-1100` は `1100` を差し引く。
- 戻り値のキー形式は厳密に `YYYY-MM`。
- 同じ月の複数注文は合算する。
- `order_id` は集計結果には使用しない。
- 今回は提示された正常形式のCSVを対象とし、不正行、欠損列、不正日時などに対する独自のエラー回復処理は設けない。

# 4. Task Contract 案

## Outcome

Python関数

```python
monthly_sales(path)
```

を作成し、CSVから月次売上を計算して、

```python
{"YYYY-MM": 金額}
```

形式の `dict[str, int]` を返す。

## Scope

- 指定されたCSVファイルを読み込む。
- `ordered_at` から集計年月を決定する。
- 確定したstatusルールで対象行を選別する。
- `amount_incl_tax` を整数として月別合計する。
- 確定した欠損月ルールに従ってdictを構成する。

### Out of scope

- `order_id` 単位の重複排除
