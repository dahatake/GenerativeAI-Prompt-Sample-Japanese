# Task Contract 案 — 月間労働時間の集計

この段階は仕様の確認のみ。回答を受けて契約を確定するまで実装・テストは行いません。

## 確認できた事実

- 依頼の関数は `solution.py` の `monthly_work_hours(path)`。戻り値は従業員IDをキー、時間単位の `float` を値とする `dict`。
- 既存の入力例 `shifts.csv` は、ヘッダー `employee,date,type,start,end` と6件のデータ行からなる。日付は `2026-10-01`〜`2026-10-03`、従業員IDは3種類。`type` は `work` が5件、`paid_leave` が1件。
- 時刻は `HH:MM`。`work` に `22:00` → `06:00` の行と、差がちょうど6時間の行がある。`paid_leave` は開始・終了がともに空欄。
- サンプルに `status`・休憩・金額・タイムゾーン・対象月の列はなく、既存の実装・テスト・仕様書もない。

## 仮定

- 日時は日本標準時（JST、UTC+09:00固定）とし、夜勤の全時間を開始日の月に帰属させる。
- 金額・給与は対象外。時間は整数分で合算して最後に時間へ換算し、追加の丸めはしない。
- サンプルで決められない対象月、休憩、有給休暇は下記の質問で確認する。質問にしない仮定の詳細は Open questions に記載する。

## 不足情報

- 2か月以上が混在するCSVの取り扱いと、出力対象月の決め方（Q1）。
- 休憩欄がない場合の控除の有無と閾値（Q2）。
- 時刻のない `paid_leave` を労働時間に含めるか、含める場合の換算時間（Q3）。

## Outcome

`monthly_work_hours(path)` が指定されたCSVから、合意した1か月分の労働時間を従業員別に集計して返す。

## Scope・Out of scope

- **Scope:** CSVの読み取り・検証、対象月と対象行の選定、夜勤の経過時間計算、合意した控除・換算、従業員別合算。
- **Out of scope:** 金額・給与・消費税（税込／税抜、金額の丸めは適用しない）、法令適合の判定、残業・割増の内訳、勤怠の重複修正、従業員マスター、CLIやファイル出力。

## Data sources

- 入力：呼び出し元が `path` で指定する `shifts.csv` と同じ列構成のCSV。
- 仕様の根拠：今回の依頼と作業ディレクトリ内の `shifts.csv`。別ファイルの従業員・休憩・対象月情報は使わない。

## Constraints

- 入力はUTF-8（BOM可）、ヘッダー付きのカンマ区切りCSV。必須の5列は順不同。余分な名前付き列は無視し、`status` による追加の絞り込みはしない。
- Python標準ライブラリのみ。入力は変更せず、実行日の年月やマシンのタイムゾーンに依存しない。
- 関数の引数は `path` のみ。出力は `dict[str, float]` で、金額や月を含めない。
- 仕様確認の段階で作成・変更するのは `contract.md` と `timing.txt` のみ。

## Definition of Done

1. `solution.py` から `monthly_work_hours` を読み込め、合意した年月・種別の行のみが出力に反映される。既定案（Q1〜Q3すべてA）では `shifts.csv` の結果が `{'E001': 890/60, 'E002': 14.0, 'E003': 9.25}` となる（`890/60` は約 `14.833333333333334`）。キーはこの順で、値はすべて `float`。
2. `22:00` → `06:00` は控除前480分。`2026-10-31` の同じ夜勤は全480分が10月に帰属する。10月始まりと11月始まりの行が同居する場合はQ1-Aなら `ValueError`、Q1-Bなら11月始まりの行のみを集計する。
3. Q2-Aなら5時間59分・6時間ちょうど・6時間1分・8時間ちょうど・8時間1分の各シフトで控除0分。Q2-Bなら順に0分・0分・45分・45分・60分を控除する。複数行の正味分数を合算後に一度だけ60で割る。
4. 開始・終了が空欄の `paid_leave` だけを持つ従業員は、Q3-Aなら出力されず、Q3-Bなら1行につき `8.0` 時間となる。有効な `work` の開始＝終了は `0.0` 時間としてキーを残す。ヘッダーのみは `{}`。
5. 必須列や必須値の欠損、存在しない日付、範囲外の勤務時刻（例：`24:00`）、未対応の種別は `ValueError`。`00:00` と `23:59` は有効で、`00:00` → `23:59` の控除前の長さは1439分。

## Open questions

### Q1. CSVに複数の月がある場合、対象月をどうしますか？

対象月の判定には、有給休暇を含む全データ行の `date` の `YYYY-MM` を使います。

- **A（推奨）：** `YYYY-MM` が1種類ならその月。2種類以上なら `ValueError`。データ行が0件なら `{}`。月の混在を見落とさない案です。
- **B：** 最大の `date` が属する月のみを対象にし、それ以外の月に開始した行を集計しない。データ行が0件なら `{}`。

どちらでもなければ、対象月の具体的な指定・選択方法と、月をまたぐ勤務の配分を変更する場合はその境界・配分ルールを指定してください。

### Q2. `work` の経過時間から休憩を控除しますか？

- **A（推奨）：** すべての行で控除0分。サンプルに休憩時間の情報がないため、推定で差し引かない案です。
- **B：** シフト1行ごとの控除前の経過時間が0〜360分なら0分、361〜480分なら45分、481〜1439分なら60分を控除する。有給休暇には適用しない。

どちらでもなければ、控除の計算単位、分単位の閾値（ちょうどの値を含む側）、および控除する分数を具体的に指定してください。

### Q3. `paid_leave` を労働時間に含めますか？

- **A（推奨）：** 集計対象外。有給休暇の行しかない従業員は出力しない。実際に勤務した時間だけを集計する案です。
- **B：** 対象月の `paid_leave` 1行につき480分（8時間）を加算する。開始・終了時刻は使わず、休憩控除はしない。

どちらでもなければ、対象とする有給休暇の条件と、1行あたりの時間（分）または列に基づく換算式を具体的に指定してください。

### 質問にしなかった既定値

- **日時・期間：この仮定で進めます。** `date` を勤務開始日のJST（UTC+09:00固定）の暦日とする。暦月は月初 `00:00` 以上・翌月初 `00:00` 未満。終了が開始より早ければ終了は翌日。同時刻は24時間勤務ではなく0分。月をまたぐ勤務も分割せず、開始日の月に全時間を計上する。
- **対象・除外：この仮定で進めます。** `type` は前後の空白を除いて大小文字を区別し、`work` と `paid_leave` のみ受理する。未知の種別はエラー。`status` は使わない。同じ日・従業員でも1行ずつ別シフトとして合算し、重複・重なりの自動補正はしない。
- **欠損・ゼロ・上下限：この仮定で進めます。** データ行の `employee,date,type` と、`work` の `start,end` は必須。値の前後の空白を除き、日付は実在する `YYYY-MM-DD`、勤務時刻は `00:00`〜`23:59`（両端含む）の `HH:MM`。`paid_leave` の時刻欄は空欄でもよく、入力されても集計に使わない。勤務1行の上限は1439分、従業員の月合計に上限は設けない。ヘッダーのみなら `{}`、空ファイル・必須列不足・重複ヘッダー・列数不一致は `ValueError`。空行は無視する。対象月や種別で除外する前に行を検証する（有給休暇の時刻は検証対象外）。ファイルを開けない場合は元のファイル例外をそのまま送出する。
- **控除・換算・金額：この仮定で進めます。** 経過時間と合意した控除・有給換算を整数分で扱う。対象行の分数を従業員ごとに合算し、最後に60で割る。行単位・月単位の丸めはしない。金額は扱わないため、税込・税抜や金額の端数処理は適用しない。
- **形式・順序：この仮定で進めます。** 従業員IDは前後の空白を除いた文字列のまま（先頭ゼロと大小文字を保持）。キーの辞書順（文字列昇順）に挿入し、値はすべて時間単位の `float`。集計対象の行がある従業員は合計0分でも `0.0` を返し、対象行がない従業員は出力しない。
