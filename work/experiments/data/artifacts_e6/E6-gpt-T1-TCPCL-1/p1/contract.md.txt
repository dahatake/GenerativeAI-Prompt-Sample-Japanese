# Task Contract（案・実装前）

## 確認できた事実

- 依頼の成果物は `solution.py` の `monthly_sales(path)`。戻り値は月を `YYYY-MM` で表した文字列をキー、整数の集計額を値とする辞書。
- 作業開始時に確認できた入力は `sales.csv` のみ。既存の `solution.py`、テスト、業務ルールを記したファイルはない。
- ヘッダーは `order_id,ordered_at,amount_incl_tax,status`。10件のうち `completed` は8件、`cancelled` は2件。注文IDは10件とも一意で、空欄はない。
- 日時は全件、秒精度のUTC表記（末尾 `Z`）。1月末と4月末に、UTC+09:00へ換算すると翌月になる注文がある。
- 金額列名は税込を示し、全件が整数表記。`completed` に負額 `-1100` が1件ある。税率、通貨、数量、時間、注文種別の列はない。

## 仮定

- 推奨案では、固定UTC+09:00で月を決め、`completed` の税込金額を負額も含めて合計する。
- 入力・出力の細則は、後述の「質問しない前提」を採用する。

## 不足情報

- 売上月の基準が固定UTC+09:00かUTCか、または別の基準か。
- `cancelled` など、売上として認める `status` の範囲。
- `completed` の負額が売上を減額する調整なのか、集計外のデータなのか。列名から負額の業務上の意味は判定できない。

## Outcome

`monthly_sales(path)` が、指定されたCSVを読み、合意した月境界・対象条件で売上を集計して `dict[str, int]` を返す。

## Scope・Out of scope

- **対象:** CSVの読み取りと検証、日時の月への割当、`status` と負額ルールによる行の選別、月次合計。
- **対象外:** 入力ファイルの編集、別ファイルへの集計結果出力、税額の再計算、通貨・数量・時間の換算、注文の照合や重複排除。この段階は契約案のみとし、実装やテストファイルの作成は行わない。

## Data sources

- `sales.csv` を入力例兼検証データとする。`ordered_at`、`amount_incl_tax`、`status` を集計に使用し、`order_id` は検証時の行の特定にのみ使用する。
- 意味が確定しない項目は下記の回答で確定する。外部データは参照しない。

## Constraints

- 実装時はPython標準ライブラリのみを使い、`path` で指定されたファイルを読み取り専用で開く。金額計算に浮動小数点数を使わない。
- 契約策定段階では作業ディレクトリ内の `contract.md` と `timing.txt` のみを作成・更新する。

## Definition of Done（検証条件）

1. 推奨案（Q1-A、Q2-A、Q3-A）では、`sales.csv` の結果が `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` と一致し、キーの反復順もこの順になる。別案で確定した場合は、その条件に合わせて期待値を更新する。
2. Q1-Aでは `2026-01-31T14:59:59Z` は1月、1秒後の `2026-01-31T15:00:00Z` は2月。入力順を逆にしても結果は月の昇順になる。
3. 推奨案では、`cancelled` の正額を除外し、`completed` の `-1100` は減額として含める。対象行が `0` の1件だけの月も値 `0` で返す。一方、対象行がない月はキーを作らず、ヘッダーのみ・全行対象外の入力は `{}` を返す。
4. 必須列の欠落、空の `status`、対象行の空欄・不正な日時や金額は `ValueError`。たとえば存在しない日付や `1.5` は受理せず、部分集計を返さない。

## Evidence

- `A-1004`（`3300`）はUTCで1月、固定UTC+09:00で2月。`A-1010`（`7700`）はUTCで4月、固定UTC+09:00で5月。
- `A-1003`（`22000`）と `A-1007`（`4400`）は `cancelled`。`A-1006` は `completed` の `-1100`。
- 実データを読み取り専用で照合した。対象を `completed` とし負額を含めた場合、固定UTC+09:00の集計は DoD 1 のとおり。UTCの集計は `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}`。これは契約案の照合結果であり、未実装の関数の実行結果ではない。

## Open questions

**Q1. 売上月はどのタイムゾーンで決めますか？** `A-1004` と `A-1010` の計上月が変わります。

- **A（推奨）:** UTCの日時を通年固定のUTC+09:00（JST）に換算。`A-1004` は2月、`A-1010` は5月。
- **B:** UTCのまま集計。`A-1004` は1月、`A-1010` は4月。
- どちらでもなければ、具体的なUTCオフセットまたはIANAタイムゾーン名を指定してください。

**Q2. どの `status` を売上に含めますか？** `cancelled` を含めるとこのサンプルの集計対象額が `26400` 増えます。

- **A（推奨）:** `completed` のみ含め、`cancelled` とその他の空でない値を除外する。
- **B:** `completed` と `cancelled` の両方を含め、その他の空でない値を除外する。
- どちらでもなければ、含める `status` の文字列を具体的に列挙してください。

**Q3. 対象 `status` の負額をどう扱いますか？** `A-1006` を含めると2月の売上が `1100` 減ります。

- **A（推奨）:** `amount_incl_tax < 0` の行も符号どおり合計する（`-1100` は `1100` の減額）。
- **B:** `amount_incl_tax < 0` の行は集計から除外する（`0` は除外しない）。
- どちらでもなければ、負額を含める条件と、補正が必要なら閾値・補正式を具体的に指定してください。

### 質問しない前提

- **金額・丸め:** `amount_incl_tax` を税込のまま、CSVの整数単位で合計する。ASCII数字による符号付き10進整数（先頭の `+` / `-` は任意）を受け付け、業務上の上限・下限は設けない。小数・桁区切り・通貨記号は不正とし、行単位でも合計後でも丸めない。この仮定で進めます。
- **集計期間・日時境界:** 日時は `YYYY-MM-DDTHH:MM:SSZ` の実在するUTC日時（年は `0001`〜`9999`、秒は `00`〜`59`）とし、換算後の年も同範囲とする。日付による切り捨ては設けず全期間を対象とし、集計タイムゾーンの各月1日 `00:00:00` 以上、翌月1日 `00:00:00` 未満をその月とする。ちょうど月初の時刻は新しい月に入れる。この仮定で進めます。
- **対象・種別:** `status` は大文字小文字を区別して完全一致で判定する。注文種別で追加除外せず、同じ `order_id` が複数あっても対象行をそれぞれ計上する。この仮定で進めます。
- **欠損・ゼロ:** 必須列は `ordered_at`、`amount_incl_tax`、`status`。空欄または空白のみの `status`、対象 `status` 行の日時・金額の欠損や不正値は `ValueError` とし、対象外 `status` の行は日時・金額を検証せず除外する。金額 `0` の対象行は有効で、相殺による月合計 `0` も出力する。この仮定で進めます。
- **控除・換算:** 数量・時間の控除や換算、通貨換算、税や値引きの再計算は行わない。採用した負額ルール以外で金額を調整しない。この仮定で進めます。
- **形式・順序:** UTF-8（BOMの有無を許容）のヘッダー付きカンマ区切りCSVを読み、未使用列は無視する。月の昇順で挿入した `dict[str, int]` を返す。対象行が存在しない月はゼロで補完せず、対象行が一件もなければ `{}` とする。この仮定で進めます。
