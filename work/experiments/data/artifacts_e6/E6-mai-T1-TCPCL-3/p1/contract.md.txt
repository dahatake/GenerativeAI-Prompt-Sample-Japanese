# Task Contract（Spec Mode）

## Outcome
- `solution.py` の `monthly_sales(path)` を実装し、指定された CSV を月単位で集計し、`{"YYYY-MM": 金額(int)}` の dict を返す。

## Scope・Out of scope
- 対象: 作業ディレクトリ内の `sales.csv` をデータとして読み、月次売上を算出する。
- 対象列: `ordered_at` と `amount_incl_tax` を使用する。`status` は集計対象判定に使用する候補列。
- Out of scope: 新規DB/API連携、他通貨・為替換算、税区分の再計算、数量や作業時間の換算、CSV以外のファイル形式、外部ネットワーク参照。

## Data sources
- 確認済みの入力: `sales.csv`
- 列: `order_id, ordered_at, amount_incl_tax, status`
- データ件数: 10件。
- 状態: `completed` 8件、`cancelled` 2件。
- 日時形式: ISO 8601、末尾 `Z`（例: `2026-01-31T16:20:00Z`）。
- 金額形式: 全件整数。正の売上と、`completed` の -1100 はマイナス値として表現されている。
- 月の観測範囲: 対象データ上は 2026-01、2026-02、2026-04（2026-03 はレコードなし）。

## Constraints
- 作業ディレクトリ外のファイルを読み書きしない。
- 入力パスは引数 `path` により指定する。
- 戻り値は Python の通常 dict とし、金額は整数型（`int`）。
- 月キーは厳密に `YYYY-MM`。
- 想定ライブラリ外の依存は追加しない（標準ライブラリのみを基本とする）。

## Definition of Done（検証できる条件）
- 推奨案（下記の Open questions を選択して確定する案）では、次の代表例を返すこと。
  - `2026-01`: 19800（完了済み 11000 + 5500 + 3300）
  - `2026-02`: 7700（完了済み 8800 - 1100）
  - `2026-04`: 26400（完了済み 16500 + 2200 + 7700）
- キャンセル済み行は推奨案では集計しないこと。
- 0額は集計対象月にキーを残し得る。マイナス額は単純加算すること。
- 必要な値は必ず整数として返すこと。
- 結果の月キーは昇順で並べること。

## Evidence
- 確認できた事実:
  - 作業ディレクトリには `sales.csv` と本契約作成前の `timing.txt` のみ確認。
  - `sales.csv` はヘッダーと 10 件のレコードを含む。
  - `completed` は 8件、`cancelled` は 2件。
  - 金額列名は `amount_incl_tax`、全値は整数表現。
  - 日時は UTC を示す末尾 `Z` を使用。
  - 2026-02-14 には完了済みのマイナス金額 -1100 が存在。
- 仮定:
  - 各行の金額は注文ごとの売上差額（返金を含む）。数量や作業時間はないため換算は不要。
  - 欠搓は破損データとして、必須列が欠ける行は例外を発生させる（推奨案）。
  - 0 は集計対象として加算し、対象行が存在する月には月キーを残す（推奨案）。
  - 出力は月キーの昇順の dict（推奨案）。
- 不足情報:
  - ユーザーが選択すべき集計対象 status。
  - 金額の税込/税抜変換方針と丸め方式。
  - 月境界に使用するタイムゾーン。

## Open questions

### 確認できた事実
- 上記 Evidence を参照。

### 質問 1: 集計対象の `status`
1. `completed` のみを集計する（推奨既定案）。
2. `completed` と `cancelled` を区別せず全行を集計する。
3. `cancelled` のみを集計する。
- 選択肢 1〜3以外の場合は、具体的な `status` 名と除外名を列挙してください（例: `completed,pending` を集計し、`cancelled,refunded` を除外）。

### 質問 2: 金額（税込・税抜・丸め）
1. `amount_incl_tax` を税込額としてそのまま整数加算し、丸めを行わない（推奨既定案）。
2. 金額を税率10%の税込額として税抜換算し、各行の税抜額を四捨五入して整数化する。各行の式は `int(Decimal(amount_incl_tax) / Decimal('1.10').quantize(Decimal('1'), rounding=ROUND_HALF_UP))` の意味に相当する具体的な値で処理する。
3. 金額を税率10%の税込額として税抜換算し、各行の税抜額を小数点以下切り捨てして整数化する。
- 選択肢 1〜3以外の場合は、税率（例: 8 または 10）、税込/税抜、行ごと/合計後の丸め方式（四捨五入・切り上げ・切り捨て）を具体的に指定してください。

### 質問 3: 日時のタイムゾーンと月境界
1. 末尾 `Z` を UTC と解釈し、UTC の暦月を `YYYY-MM` とする（推奨既定案）。
2. 日時を JST（UTC+09:00）として解釈し、JST の暦月を `YYYY-MM` とする。
3. 入力時刻をタイムゾーン変更せず、文字列先頭の年月（例: `2026-01-31T...` の `2026-01`）を月キーとする。
- 選択肢 1〜3以外の場合は、タイムゾーン（例: UTC+09:00）と月境界（そのタイムゾーンの 1日00:00:00 から翌月1日00:00:00の直前まで）を具体的に指定してください。

### 質問にしなかった重要な仮定（この仮定で進めます）
- 欠損・ゼロ・境界値: 必須列 `ordered_at` または `amount_incl_tax` が欠損する行は、可算値を決められないため実装時に例外とする。ゼロは加算値として月に0を残し得る（対象行が存在する月）。期間は月境界のみを扱い、時間・日・数量の控除や換算は行わない。
- 集計対象により除外される行は、金額の加算前に除外する。
- マイナス値（例: 返品・返金）は控除ではなく、金額の符号通り加算する。
- 出力形式・順序: 戻り値は月キー昇順の Python dict。対象レコードがない月はキーを生成しない。
- 時間や数量の控除・換算: CSV に該当列がないため、特別な控除・換算ルールは適用しない。
