# 実装内容

`solution.py` の `monthly_sales(path)` を、回答に合わせて修正した。

- `csv.DictReader` で CSV を読み込む。
- `status` が `cancelled` の注文だけを除外し、それ以外の注文を集計対象にする。
- `ordered_at` をUTCとして解釈し、UTC+9の日本時間へ変換して `YYYY-MM` を決定する。
- 各注文の税込額を `amount_incl_tax / 1.1` の整数（小数部切り捨て）として税抜額に換算する。
- 月ごとの税抜額を加算する。
- 対象レコードが存在する最初の月から最後の月までを連続したキーとして生成し、注文がない月は `0` とする。
- 結果は `{"YYYY-MM": 金額(int)}` のdictを返す。

## 今回修正した点

1. 集計対象を「`completed`のみ」から「`cancelled`以外」に変更した。
2. 金額を税込価格のまま集計せず、各行を税抜額へ換算してから集計するよう変更した。
3. `ordered_at` をUTCとして解釈し、JSTへ変換してから月を判定するよう変更した。
4. 最初の月から最後の月まで月を補完し、売上がない月を `0` にするよう変更した。
5. 結果を月順に並べて返すように変更した。

検証では `sales.csv` に対し、次の結果を確認した。

```text
{'2026-01': 15000, '2026-02': 10000, '2026-03': 0, '2026-04': 17000, '2026-05': 7000}
```

# 確認事項（前提）

1. 集計対象は `status == "cancelled"` の注文を除き、それ以外の注文を対象にする。
2. `status` は前後空白と大小文字を正規化して判定する。回答で指定がないため、前回実装の推奨案を維持する。
3. 負数の `amount_incl_tax` は有効な調整額として集計対象に含め、税抜換算後も加算する。
4. 税抜金額は各行ごとに `税込額 / 1.1` を整数へ変換してから加算し、小数部は切り捨てる。
5. 金額は整数として扱い、通貨変換は行わない。
6. `ordered_at` はUTCで記録され、日本時間（UTC+9）へ変換してから月を判定する。
7. 対象レコードが存在する最初の月から最後の月までのすべての月を返し、対象レコードのない月は `0` とする。
8. 同じ月の税抜額を加算する。
9. CSVはUTF-8（BOM可）で保存され、ヘッダーは `ordered_at`、`amount_incl_tax`、`status` を使用する。回答で指定がないため、前回実装の推奨案を維持する。
10. ISO形式の日時を想定し、タイムゾーン情報がない場合はUTCとして扱う。回答で指定がないため、前回実装の推奨案を維持する。
11. `amount_incl_tax` は空白除去後に `int()` で変換可能な整数であることを前提とする。不正な場合は例外をそのまま発生させる。回答で指定がないため、前回実装の推奨案を維持する。
