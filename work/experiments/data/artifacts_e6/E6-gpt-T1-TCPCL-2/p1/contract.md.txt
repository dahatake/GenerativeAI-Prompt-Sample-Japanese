# Task Contract 案 — `monthly_sales(path)`

**状態: Spec Mode・未承認。以下の質問への回答を受けて仕様を確定し、この段階では実装しません。**

## Outcome

`solution.py` に `monthly_sales(path)` を実装し、指定された売上 CSV の月別合計を `{"YYYY-MM": 金額(int)}` の辞書で返す。

## Scope・Out of scope

- 対象: 指定された CSV 1 ファイルの読み込み、対象行の判定、月の決定、整数合計、結果の返却。
- 対象外: CSV の書き換え、CLI・帳票の作成、税額の再計算、通貨換算、注文データの照合や重複排除。
- 今回の Spec Mode では `contract.md` と `timing.txt` のみを書き込み、`solution.py` やテストは作成しない。

## Data sources

### 確認できた事実

- 作業開始時の記録後、作業ディレクトリにあったのは `sales.csv` と `timing.txt`。既存の実装・テスト・業務仕様書はない。
- `sales.csv` は `order_id,ordered_at,amount_incl_tax,status` のヘッダーと 10 件の明細。日時は全件 `Z` 付き、金額は全件整数で、`completed` が 8 件、`cancelled` が 2 件。`completed` の `A-1006` に `-1100` があるが、その理由を示す列はない。
- `A-1004` の `2026-01-31T16:20:00Z` は JST では 2 月 1 日、`A-1010` の `2026-04-30T15:30:00Z` は JST では 5 月 1 日。3 月の明細はない。
- 通貨・税率・税抜額・数量・工数・控除を示す列はない。`timing.txt` は作業時刻の記録であり、集計の入力ではない。

## Constraints

- `path` が指す CSV を使用し、ファイル名を固定しない。外部データや追加パッケージに依存しない。
- 戻り値は月キーがゼロ埋めの `YYYY-MM`、値が Python の `int` の `dict`。並び順は昇順とする案（下記）。
- 調査・検証は指定の作業ディレクトリ内で行う。

## Definition of Done

承認後、以下を検証する。具体例の期待値は Q1〜Q3 の推奨案を選んだ場合。

1. `solution.monthly_sales(path)` に `sales.csv` を渡すと `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` がこの順で返り、全値が `int`。3 月のキーはない。別名の CSV にも同じ規則が適用される。
2. JST の月境界である `2026-01-31T15:00:00Z` ちょうどの行は 2 月、その 1 秒前の行は 1 月に入る。
3. 同じ月に `completed` の `100`、`-100`、`0` と `cancelled` の `999` があれば、その月は `0` で残る。金額が `-1` の行だけの別月は `-1` で残る。標準的な固定幅整数を超える金額（例: `9223372036854775808`）も切り詰めずに合計できる。
4. ヘッダーのみ、または対象行なしなら `{}`。必須列の欠落、集計する行の必須値の欠損、不正な日時や整数でない金額は `ValueError`。データが月順でなくても結果は昇順。

## Evidence

- 今回の調査では、CSV を読み取り専用で列挙し、`completed` の符号付き整数を合計する案を独立に試算した。JST の結果は上記のとおり、UTC なら `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}`。これは実装のテスト結果ではない。
- 実装後は、実ファイルでの戻り値（キー順と値の型を含む）と、上記の境界・対象外・欠損のケースのテスト結果を残す。

## Open questions

### 不足情報 — 確認したい 3 点

**Q1. 売上月はどのタイムゾーンで決めますか？** 元の `Z` の月を使うか、タイムゾーン換算するかで `A-1004` と `A-1010` の帰属月が変わります。

- **A（推奨）:** JST（固定 UTC+09:00）に換算した暦月。
- B: UTC（UTC+00:00）に換算した暦月。
- どちらも、選んだタイムゾーンの月初 00:00:00 以上、翌月初 00:00:00 未満をその月とします。

**Q2. どの行を集計し、負の金額をどう扱いますか？** CSV には `cancelled` の正額と `completed` の `-1100` が含まれます。

- **A（推奨）:** `status == "completed"` のみ。負額は符号のまま加え、ゼロも対象。他のステータスは除外。
- B: `status == "completed"` かつ `amount_incl_tax >= 0` のみ。ゼロは対象、負額と他のステータスは除外。
- C: 空欄でないすべてのステータス（`cancelled` を含む）を対象にし、負額は符号のまま加え、ゼロも対象。

**Q3. 対象行のない月も `0` で返しますか？** サンプルには 3 月の行がありません。

- **A（推奨）:** 対象行が 1 件以上ある月だけを返す。合計がちょうど `0` の月は残す。
- B: 対象行がある最初の月から最後の月まで（両端を含む）の全暦月を返し、途中で対象行がない月は `0`。この範囲の外は返さない。
- どちらも、対象行がファイル全体で 0 件なら `{}` とします。

各問は A/B/C の該当する記号で回答できます。選択肢のどれでもない場合は、タイムゾーンと月境界、対象ステータスと負額・ゼロの処理、または出力期間の開始月・終了月と空月の処理を、該当する問に具体的な値で回答してください。

### 仮定 — この仮定で進めます

- **税込額・丸め:** `amount_incl_tax` を入力と同じ金額単位の税込整数として使う。税率や通貨は推定せず、丸め・再課税・通貨換算はしない。小数表記（`1.0` を含む）は不正。業務上の金額上限・下限は別途設けない（負額の採否は Q2）。
- **日時・期間:** `ordered_at` は ISO 8601 の `YYYY-MM-DDTHH:MM:SS` に `Z` または `±HH:MM` を付けた形式とし、任意の小数秒（1〜6 桁）を許容する。オフセットなしの時刻は推定しない。開始日・終了日による行フィルターは設けず全期間を読み、月への割り当ては Q1、出力月の範囲は Q3 に従う。
- **欠損・不正値:** `ordered_at`、`amount_incl_tax`、`status` のヘッダーは必須。ヘッダーなし（空ファイルを含む）、明細の `status` 欠損、またはステータスが対象の行で日時・金額が欠損／不正の場合は `ValueError` とし、部分結果は返さない。ステータスで除外した行の日時・金額は集計に用いず、検証もしない。空の行は無視し、値の前後空白は取り除く。ステータスの大文字・小文字は区別する。
- **時間・数量の控除と換算:** そのための入力列がないので、控除や時間・数量による乗除算は行わない。日時の換算は月を決めるためだけに使う。`order_id` による重複排除はせず、対象行を 1 行につき 1 回数える。
- **出力と入力形式:** 出力は `YYYY-MM` 昇順にキーを挿入した `dict` とし、表示用の桁区切りや JSON 化は行わない。入力は UTF-8（BOM は任意）のヘッダー付きカンマ区切り CSV。`order_id` など集計に使わない列は無視する。
