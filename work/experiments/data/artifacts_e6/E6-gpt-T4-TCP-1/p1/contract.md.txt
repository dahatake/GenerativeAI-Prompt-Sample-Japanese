# Task Contract 案：従業員別の月間労働時間

## Outcome

`solution.py` に `monthly_work_hours(path)` を実装し、指定された勤怠 CSV から、従業員 ID（文字列）をキー、月間労働時間（時間単位の `float`）を値とする辞書を返す。これは仕様案であり、この段階では実装しない。

## Scope・Out of scope

- **Scope:** 1 ファイル・1 対象月について、勤務の経過時間を分単位で求め、下記で合意する休憩・有給・丸めの規則を適用して従業員ごとに合計する。
- **Out of scope:** 給与・割増賃金・法令適合の判定、勤務記録の自動補正、重複・重なりの検出、複数月をまとめた集計、CLI やレポート出力。

## Data sources — 確認できた事実

- `shifts.csv` のヘッダーは `employee,date,type,start,end`。データは 6 行、従業員は 3 人で、`date` はすべて 2026 年 10 月。
- `work` は 5 行。日付は `YYYY-MM-DD`、時刻は `HH:MM`。E002 の `22:00` → `06:00` では終了時刻が開始時刻より早い。
- `paid_leave` は 1 行（E001）で、その行の `start` と `end` は空欄。休憩時間・所定労働時間・タイムゾーンを示す列はない。
- 調査時点では、作業ディレクトリに `shifts.csv` と開始時刻を追記した `timing.txt` のみ。既存の実装、テスト、追加仕様は見当たらない。

## Constraints

- 関数は引数 `path` の CSV のみを読み、入力ファイルを変更しない。外部ライブラリは使わない。
- 分単位の整数で計算し、合意した丸めを適用した後、合計分を `60` で割り `float` の時間に変換する。
- この仕様策定では作業ディレクトリの外を参照せず、`contract.md` と `timing.txt` のみを作成・更新する。

## Definition of Done（検証できる条件）

- `solution.py` から `monthly_work_hours` を読み込め、入力を変更せず、`dict[str, float]` 相当の結果を返す。
- Q1〜Q3 の推奨案を採用した場合、`shifts.csv` に対し `{'E001': 890 / 60, 'E002': 14.0, 'E003': 9.25}` となる。全値が `float` で、時間の比較には絶対許容差 `1e-9` を使う。別案を採用した場合は、その規則から求めた期待値で検証する。
- 日またぎは `22:00` → `06:00` で休憩・丸め適用前 480 分。同時刻は 0 分。月末に始まり翌月に終わる勤務も開始日の月に全量を計上する。
- 有給のみの従業員も結果に含め、Q2 の A なら `0.0`、B なら 1 行で `8.0`。有効なヘッダーのみの CSV は `{}`。必須列の欠落、不正な勤務行、複数の対象月を含む入力では `ValueError`。
- 合意した規則の境界も検証する。Q1 の B なら、休憩差引後は 6:00 → 360 分、6:01 → 316 分、8:00 → 435 分、8:01 → 421 分。Q3 は同一従業員の各 8 分の勤務 2 行で検証でき、A／B／C の月合計はそれぞれ 16／15／0 分。

## Evidence

- `shifts.csv` 1 行目で列名、2〜7 行目で種別・時刻・日付を確認した。
- 推奨案の期待値は、E001 が `540 + 350 + 0 = 890` 分、E002 が `480 + 360 = 840` 分、E003 が `555` 分。これはサンプルの手計算であり、実装やテストの実行結果ではない。
- 実装後は、同じサンプルと上記の境界・エラーケースのテスト結果を証跡とする。

## Open questions

### 不足情報 — 確認したい 3 点

**Q1. 休憩欄がない `work` 行で、経過時間から休憩を引きますか？**

- **A（推奨の既定案）:** 0 分を差し引く。実際の休憩時間が記録されていないため、開始から終了までの時間を計上する。
- **B:** 丸め前の経過時間が 0〜360 分なら 0 分、361〜480 分なら 45 分、481〜1,439 分なら 60 分を、各勤務行から差し引く。
- どちらでもなければ、区間の境界と各区間の控除分数を具体的な値で回答してください。

**Q2. 開始・終了が空欄の `paid_leave` を合計に含めますか？**

- **A（推奨の既定案）:** 1 行あたり 0 分。実際に勤務した時間だけを集計する。
- **B:** 1 行あたり 480 分（8 時間）を加算する。休憩控除はしない。
- どちらでもなければ、1 行あたりの計上分数、または従業員別の計上分数とその取得元を具体的な値で回答してください。

**Q3. 時間を丸めますか？ 丸める場合、どの段階ですか？**

- **A（推奨の既定案）:** 集計値を丸めない。整数の分をそのまま月次合計し、最後に 60 で割る。
- **B:** 休憩控除と有給計上後、従業員の月合計を 15 分単位で切り捨てる（例：月合計 359 分 → 345 分）。
- **C:** 休憩控除と有給計上後、各行を 15 分単位で切り捨ててから合計する（例：1 行 359 分 → 345 分）。
- どれでもなければ、丸める段階・単位・方向（四捨五入なら中間値の扱いも）を具体的な値で回答してください。

### 仮定 — 質問にしない点

- 対象月の引数がないため、CSV 内の `date` は単一の暦月（年・月が同一）とし、異なる月が混ざる場合は `ValueError` とします。この仮定で進めます。
- `date` を勤務開始日とし、`work` の終了時刻が開始時刻より早い場合は翌日、同時刻なら 0 分とします。月をまたいでも開始月に全量を計上し、時刻はタイムゾーン変換を行わず分単位で差し引きます。この仮定で進めます。
- `employee` は空白のみを不可とし、ID は文字列のまま扱います。有効な行がある全従業員を出力し、0 時間も `0.0` とします。重複・重なりがあっても行は個別に加算します。この仮定で進めます。
- UTF-8（BOM 可）のヘッダー付きカンマ区切りとし、サンプルの 5 列を必須、追加列は無視します。`work` では両時刻に `00:00`〜`23:59` の `HH:MM` が必要で、`paid_leave` の時刻欄は使いません。存在しない日付、未知の種別、欠損した必須列など、不正入力を黙って読み飛ばさず `ValueError` とします。この仮定で進めます。
