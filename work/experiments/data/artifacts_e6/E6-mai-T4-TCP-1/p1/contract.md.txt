# Task Contract — Spec Mode

## Outcome
- `solution.py` に `monthly_work_hours(path)` を実装する。
- 戻り値は、従業員IDをキー、対象CSV全体の労働時間（単位: 時間、float）を値とする dict とする。

## Scope
- 指定されたパスのCSVを標準ライブラリ（特に `csv`）で読み込む。
- 確認済みの列名 `employee`, `date`, `type`, `start`, `end` を対象とする。
- `type == "work"` の行だけを労働時間に加算する。
- 1行ごとの労働時間を分単位で計算し、合計を時間単位のfloatで返す。

## Out of scope
- CLI、レポート生成、データベース連携、グラフ出力は対象外。
- 休憩控除、残業区分、月別dictへの分割、タイムゾーン変換は対象外。
- CSVの上書き・書き込みは行わない。

## Data sources
- 作業ディレクトリ内の `shifts.csv`（確認済みサンプル）。
- 実装対象は作業ディレクトリ内の `solution.py`。現時点では存在しない。
- 入力パスは `monthly_work_hours(path)` の引数から受け取る。

## Constraints
- すべての効果は作業ディレクトリ内に限定する。
- 外部パッケージに依存せず、標準ライブラリのみを使用する。
- 従業員IDは文字列としてそのままdictキーにする。
- 日本語や空白を含む入力もエンコーディング上の問題がない範囲で処理する。
- 出席区分 `work` 以外（確認済みでは `paid_leave`）は労働時間を加算しない。

## Definition of Done（検証できる条件）
- `solution.py` を作業ディレクトリ内に配置し、import可能である。
- `monthly_work_hours("shifts.csv")` を実行すると、少なくとも確認済みデータについて以下を返せる:
  - `E001` は約 `13.833333333333334`（09:00–18:00 = 9時間、09:00–14:50 = 5時間50分、合計14時間50分で約13.833333333333334ではない点に注意。正しくは約14.833333333333334。）
  - `E002` は約 `14.0`（日跨ぎ22:00–06:00を8時間、13:00–19:00を6時間）
  - `E003` は約 `9.25`（08:30–17:45）
  - `paid_leave` 行は加算しない。
- 従業員ごとの合計が、同じ従業員の複数行で加算される。
- 入力時刻は `HH:MM` を想定し、時刻差を分として計算する。
- 戻り値の値はPython `float` またはその集合演算で等価な値である。

## Evidence
### 確認できた事実
- 作業ディレクトリ内に `shifts.csv` がある。
- `shifts.csv` のヘッダーは `employee,date,type,start,end`。
- サンプルは2026-10月の10/1～10/3で、従業員E001～E003の行を含む。
- E001には `work` 2行と `paid_leave` 1行がある。
- E002には日跨ぎと考えられる `22:00` から `06:00` の行がある。
- 班時刻、休憩列、休憩時間の列は存在しない。
- 現時点で `solution.py` は存在しない。

### 仮定
- 対象CSV全体を1つの集計期間として扱い、従業員ごとに合算する。
- 日付は集計期間判定には使わず、各行の時刻差だけを集計する。
- `paid_leave` など `work` 以外の行を無視する。
- 休憩時間は差し引かない。
- 時刻は `HH:MM` の24時間表記とする。
- 月内集計は、入力内のすべての行を対象とする。月フィルター引数はない。
- 結果は丸めず、分数を60で割ったfloatとして累積する。

### 不足情報
- CSVが複数月をまたぐ場合の期間分割方法は、戻り値形式に月キーを入れられないため現時点では未定義。
- `employee`, `type`, `start`, `end` 列が欠けている場合の共通仕様は未定義。
- 不正な時刻や空の `work` 行を除外するか、エラーにするかの仕様は未定義。

### Open questions（最大3問。推奨既定案で進めるか選択してください）
1. 複数行・複数日をどう集計するか
   - 選択肢A（推奨）：CSV内の全行を対象に従業員ごとに合算し、`{"E001": 14.833333333333334}` のような単一dictを返す。
   - 選択肢B：日付の年月ごとに分割するが、戻り値を `{"E001": 14.8333}` のように従業員単位にする（年月を区別しない）。これは選択肢として、月跨ぎ時の合算方法を指定しないため推奨しない。
   - 選択肢C：CSV内の各従業員について最新の年月だけを集計し、他の年月を無視する。
   - どれでもない場合は「対象年月の開始日と終了日」または「年月ごとのdict構造」を具体的に指定してください。

2. 日跨ぎ時刻の扱い
   - 選択肢A（推奨）：`end < start` の場合だけ翌日跨ぎとみなし、`(end + 24h) - start` として計算する。`end == start` は0時間。
   - 選択肢B：常に `end - start` を計算し、負数を許可しない（負数は0時間）。
   - 選択肢C：すべての時刻を同日内とみなし、`end < start` は24時間以上跨ぎ扱いせずエラーまたは負数とする具体的ルールを指定する。
   - どれでもない場合は、`開始時刻と終了時刻の境界関係` を具体的な数式で指定してください。

3. 不正な `work` 行または欠損時刻の扱い
   - 選択肢A（推奨）：不正な時刻・欠けた時刻・必須列欠落がある場合は、行番号を含む `ValueError` を発生させる。
   - 選択肢B：不正な行を集計から無視し、有効な行だけを合算する。
   - 選択肢C：不正な行は0時間として集計し、関数は例外を出さない。
   - どれでもない場合は、不正行の判定条件と具体的な処理（例外名、欠損時の値）を指定してください。

注記: 質問にしなかった重要な仮定として、丸めは行わず、浮動小数点の誤差も明示的には補正しないことで進めます。また、`start == end` は0時間、休憩控除なし、日付は集計に使わないことで進めます。
