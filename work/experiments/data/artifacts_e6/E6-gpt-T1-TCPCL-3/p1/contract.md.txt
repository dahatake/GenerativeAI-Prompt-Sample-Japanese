# Task Contract 案：月次売上集計（Spec Mode）

## Outcome

`solution.py` の `monthly_sales(path)` が、指定された CSV の売上を暦月ごとに集計し、`{"YYYY-MM": 金額(int)}` の Python `dict` を返す。以下の既定案は契約案のためのもので、今回は実装しない。

## Scope・Out of scope

- 対象：CSV の読み込み、必須値の検証、対象行の選別、集計タイムゾーンへの換算、月次合計、必要に応じた欠け月の補完。
- 対象外：税額の再計算、通貨換算、数量による乗除、時間・数量の控除、注文 ID による重複排除、期間指定の追加、CSV の書き換え、外部データ参照、ファイルへの集計結果の出力。

## Data sources

### 確認できた事実

- `sales.csv` はカンマ区切り、ヘッダーは `order_id,ordered_at,amount_incl_tax,status`。ヘッダーを除き 10 行あり、`completed` が 8 行、`cancelled` が 2 行。
- すべての日時は `Z`（UTC）付きで、金額は整数表記。`A-1006` は `completed` で `-1100`。通貨・税率・数量・控除・種別の独立列はない。
- `A-1004` と `A-1010` は UTC と日本時間で属する月が異なる。3 月の行はない。
- 調査時点では `solution.py` や既存のテスト・仕様書はなかった。

## Constraints

- 承認後の実装は Python 標準ライブラリで完結し、引数で渡したファイルを読み込む。入力ファイルや外部状態を変更しない。
- 今回は作業ディレクトリ内の `contract.md` と `timing.txt` のみを書き、集計関数・テストは作成しない。

## Definition of Done

承認後、以下を自動テストで確認できること。選択が既定案と異なる場合は、その選択に合わせて期待値を更新する。

- 既定案（Q1〜Q3 の A）で `monthly_sales('sales.csv')` は `{'2026-01': 16500, '2026-02': 11000, '2026-03': 0, '2026-04': 18700, '2026-05': 7700}`。`dict` のキーは記載の順で、値の型はすべて `int`。
- 既定案で `2026-01-31T14:59:59Z` は 1 月、`2026-01-31T15:00:00Z` は 2 月に入る。同じ瞬間を `2026-02-01T00:00:00+09:00` と記した場合も 2 月に入る。
- 既定案で `cancelled` やその他のステータスを除外し、`completed` の負額とゼロは符号付きのまま集計する。別の月に 0 の対象行しかない場合でもその月を返す。加減算で合計が 0 になった月も返す。
- ヘッダーのみ、または有効な対象行がゼロ件の場合は `{}`。必須列の欠落や、対象外ステータスの行も含めた必須値の欠損・不正値は `ValueError`。不正値の例は小数金額とタイムゾーンなしの日時。

## Evidence

- `A-1004`：`2026-01-31T16:20:00Z` → JST `2026-02-01 01:20:00`、税込 3300。`A-1010`：`2026-04-30T15:30:00Z` → JST `2026-05-01 00:30:00`、税込 7700。
- `completed` の 8 行を独立計算した結果（欠け月補完前）：JST は `{'2026-01': 16500, '2026-02': 11000, '2026-04': 18700, '2026-05': 7700}`、UTC は `{'2026-01': 19800, '2026-02': 7700, '2026-04': 26400}`。
- 既定案の 2 月は `3300 + 8800 - 1100 = 11000`。`cancelled` の `A-1003`（22000）と `A-1007`（4400）は含めない。

## Open questions

### 不足情報（要確認・3 問）

各問、選択肢のどれでもない場合は、実装できる具体的な値・条件で回答してください。

1. **Q1：どのタイムゾーンで月を区切りますか？** `Z` はデータの記録時刻を示すため、集計月のタイムゾーンまでは確定しません。
   - **A（推奨）**：日本時間（固定 UTC+09:00、夏時間なし）。月初 `00:00:00` を含み、翌月初 `00:00:00` を含まない。
   - **B**：UTC（UTC+00:00）。月初 `00:00:00Z` を含み、翌月初 `00:00:00Z` を含まない。
2. **Q2：`status` と負額で、どの行を集計しますか？** `cancelled` かつ正額の行と `completed` かつ負額の行があります。
   - **A（推奨）**：`completed` のみ。負額は差し引き、ゼロも対象行として含める。
   - **B**：`completed` かつ金額 `>= 0` のみ。負額は除き、ゼロは含める。
   - **C**：`completed` と `cancelled` の両方。負額は差し引き、ゼロは含める。ほかのステータスは除く。
3. **Q3：対象行のない月を出力しますか？** `sales.csv` には 3 月の行がありません。
   - **A（推奨）**：最初と最後の対象行が属する月を両端に含め、その間に対象行がない月は整数 `0` で埋める。両端の外は補完せず、対象行がなければ `{}`。
   - **B**：対象行が 1 行以上ある月だけを返す。対象行があって合計が `0` の月は残し、対象行がなければ `{}`。

### 仮定（質問しない点）

以下は**この仮定で進めます**。いずれも Q1〜Q3 の回答と合わせ、実装時に適用します。

- **金額・範囲**：`amount_incl_tax` の税込額をそのまま足す。単位は CSV と同じ（`1` は入力通貨の 1 単位、通貨名は未確認）。任意の先頭符号 `+` / `-` に続く ASCII 十進数字を整数として受け付け、小数は `ValueError` とし丸めない。業務上の金額上限・下限は設けず、負額の採否のみ Q2 に従う。
- **日時・期間**：`ordered_at` は `YYYY-MM-DDTHH:MM:SS` に `Z` または `±HH:MM` が付いた形式（秒の小数部は 1～6 桁まで任意）。タイムゾーンなしや実在しない日時は `ValueError`。入力・換算後とも暦年 `0001`～`9999` を有効範囲とし、任意の期間フィルターは設けない。月の所属は入力日時を Q1 のタイムゾーンに換算した後に決める。
- **種別・換算・控除**：取引種別での追加除外はせず、数量・時間による控除や換算も行わない。`order_id` は集計には使わず、同じ ID の行でもそれぞれ独立に集計する。
- **CSV・欠損**：UTF-8（BOM は任意）のヘッダー付き CSV とし、`ordered_at`・`amount_incl_tax`・`status` を必須列とする。余分な列は集計に使わない。完全な空行は無視し、それ以外では必須値の前後空白を除いて検証する。必須列の欠落や必須値の空欄・不正値は、行を除外する前に `ValueError` とする。`status` は大文字・小文字を区別して Q2 の値と照合し、一致しない非空値の行は除外する。
- **出力と順序**：`YYYY-MM` は年 4 桁・月 2 桁とし、月の昇順で `dict` に挿入する。値は `int`。対象行が存在する月の合計 `0` は省略しない。
