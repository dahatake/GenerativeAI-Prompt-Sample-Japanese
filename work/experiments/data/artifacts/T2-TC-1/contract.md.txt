# Task Contract: `dedupe(records)` — **承認済み（2026-11-25）／ Execution Mode**

## 0. 決定事項
- Q1 = (a): 判定キーは email を strip + lower した値とする。email が空や `null` のレコードは判定の対象にせず、すべて残す。
- Q2 = (a): グループ内で `updated_at` が最も新しいレコードを、元の値のまま残す。
- Q3 = (a): グループが入力で最初に出てくる位置の順に並べ、値は元のまま返す。
- 回答がない点（A1〜A5 と Open questions）は推奨の既定案を採用する。

## 1. 確認できた事実
- 作業ディレクトリには `members.json`（7件）だけがある。`solution.py`、テスト、README、依存定義はない。
- 各レコードのキーは `id`, `name`, `email`, `updated_at` の4つ。
- `id` は 1〜7 で重複していない。そのため、`id` だけでは重複を判定できない。
- `email` の値には表記ゆれがある。
  - id1 `taro.yamada@...` と id3 `" Taro.Yamada@..."` は、前の空白と大文字小文字だけが違う。`name` も同じ。
  - id2 `hanako.sato@...` と id6 `HANAKO.SATO@...` は、大文字小文字だけが違う。`name` も同じ。
- `email` が空文字のレコード（id4）と `null` のレコード（id5）がある。
- `name` には全角文字と半角スペースが入っている。今回のデータでは、同じ名前のレコードは email でも同じグループになる。
- `updated_at` はすべて ISO 8601 形式で、タイムゾーンは `+09:00`。重複している2組では、どちらも id の小さいほうが古い（id1 < id3、id6 < id2）。
- 実行環境は Python 3.12.10。

## 2. 仮定（質問の回答で上書きします）
- A1: `dedupe` は引数のリストだけを処理する。ファイルの読み書きはしない。
- A2: 標準ライブラリだけを使う。
- A3: 入力のリストと dict は変更しない（非破壊）。
- A4: 同じグループで `updated_at` が同じ場合は、入力で先に出てくるレコードを残す。
- A5: `updated_at` は `datetime.fromisoformat` で読み取って比較する。文字列の比較では行わない。

## 3. 不足情報

- 重複している中から、どのレコードを残すのか。
- 出力の順序と、出力する値を正規化するかどうか。
- 想定するデータ量。今回は O(n) を前提とし、質問はしません。

## 4. 質問（最大3問）
**Q1. 重複の判定キーは何ですか？**
- (a) **推奨（既定）**: `email` の前後の空白を除き、小文字にした値で判定する。email が空文字や `null` のレコードは、重複判定の対象にしない（すべて残す）。
- (b) 正規化した `email` と `name` の両方が一致したら重複とする。
- (c) `name` だけで判定する（同じ名前の別人も1件にまとめてしまう危険があります）。
- (d) その他（判定ルールを指定してください）。

**Q2. 重複の中から、どのレコードを残しますか？**
- (a) **推奨（既定）**: `updated_at` が最も新しいレコードを、元の値のまま残す。
- (b) 入力で最初に出てくるレコードを残す。
- (c) 項目ごとにマージする（例: 新しいほうの値を優先し、空の項目は古いほうの値で補う）。

**Q3. 出力の順序と値はどうしますか？**
- (a) **推奨（既定）**: そのグループが入力で最初に出てくる位置の順に並べる。値は元のまま返す（email の正規化結果は出力に反映しない）。
- (b) 残したレコードが入力で出てくる位置の順に並べる。値は元のまま返す。
- (c) 順序は (a) と同じだが、`email` を正規化した値に書き換えて返す。

### Definition of Done（検証できる条件）
1. `members.json` を読み込んで `dedupe` に渡したとき、返るレコードの `id` が順に **`[3, 2, 4, 5, 7]`** になる。

6. 空のリストを渡すと `[]` が返る。
