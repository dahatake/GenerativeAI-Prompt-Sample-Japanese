# report

## 実装内容
- `solution.py` に `monthly_sales(path, tz=JST, statuses=("completed",))` を実装（標準ライブラリのみ）。
- `sales.csv` を `csv.DictReader` で読み、`ordered_at`（UTC）をタイムゾーン変換して `YYYY-MM` 単位で `amount_incl_tax` を int で合計。キー昇順の dict を返す。

実行結果（同梱 sales.csv）:
- 既定（JST）: `{'2026-01': 16500, '2026-02': 11000, '2026-04': 18700, '2026-05': 7700}`
- `tz=timezone.utc` 指定時: `{'2026-01': 19800, '2026-02': 7700, '2026-04': 26400}`

## 前提にしたこと（要確認）
1. **月の判定は JST**: `ordered_at` は UTC (`Z`) だが、日本の業務の月次として JST に変換して判定。A-1004（1/31 16:20Z → 2/1 JST）、A-1010（4/30 15:30Z → 5/1 JST）は月が変わる。UTC 基準にしたい場合は `tz=timezone.utc` を渡す。
2. **金額は税込** (`amount_incl_tax`) をそのまま使用（税抜換算はしない）。
3. **status が `completed` の行のみ集計**し、`cancelled` は除外。
4. **負の金額（A-1006: -1100）は返金・値引きとみなし合算**（売上から差し引く）。
5. **売上の無い月（例: 2026-03）はキーに含めない**（0 埋めしない）。

上記のうち特に 1（タイムゾーン）と 3・4（キャンセル/負値の扱い）は集計結果に直接影響するため、仕様の確認をお願いします。
