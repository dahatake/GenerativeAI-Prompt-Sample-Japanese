# monthly_sales 実装レポート

## 実装内容
- `solution.py` に `monthly_sales(path, tz=JST, exclude_statuses=("cancelled",))` を実装。
- `csv.DictReader` で読み込み（UTF-8 / BOM 対応）、`ordered_at` を指定タイムゾーンに変換して `YYYY-MM` を求め、`amount_incl_tax` を int で合計。
- 戻り値は月の昇順に並べた `{"YYYY-MM": int}` の dict。

## 前提にしたこと（データからは判断できなかったため仮定）
1. **月の区切りは JST（日本時間）**: `ordered_at` は UTC (`Z`) ですが、日本の業務の月次集計を想定して JST に変換しています。
   - 影響あり: `A-1004`（2026-01-31T16:20Z → JST 2/1）、`A-1010`（2026-04-30T15:30Z → JST 5/1）。
   - UTC で集計したい場合は `monthly_sales(path, tz=datetime.timezone.utc)`。
2. **`cancelled` は除外**: キャンセル注文は売上に含めません。`exclude_statuses=()` で全件集計も可能です。
3. **マイナス金額は含める**: `A-1006`（-1100, completed）は返金・値引きとみなし、そのまま差し引きます。
4. **金額は税込**: 列が `amount_incl_tax` のみのため税込金額をそのまま合計（税抜換算はしていません）。
5. **データのない月は出力しない**: 例えば 2026-03 は 0 として補完せず、キーを含めません。

## 実行結果（sales.csv）
| 条件 | 結果 |
|---|---|
| 既定（JST・cancelled 除外） | `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}` |
| UTC・cancelled 除外 | `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}` |

## 確認したい点
- 月の区切りは JST と UTC のどちらが正しいか。
- キャンセル・マイナス金額の扱い、税込/税抜、データなし月の 0 補完の要否。
