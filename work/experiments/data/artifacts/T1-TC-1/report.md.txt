## 採用した仮定

| ID | 内容 | 根拠 |
|---|---|---|
| A1 | 標準ライブラリのみを使う（`csv`、`datetime`） | 推奨既定案 |
| A2 | 売上には `amount_incl_tax` 列を使う | 列名から判断 |
| A3' | 補完する月の範囲は、cancelled を含む全注文の最初の月〜最後の月。データ行が 0 件なら `{}` | 回答「注文がない月も 0」に基づく解釈 |
| A4 | キーは `YYYY-MM` で昇順、値は `int` | 依頼の仕様 |
| A5 | `utf-8-sig` で読み込む（BOM があっても可） | 推奨既定案 |
| A6 | 重複した `order_id` を除外せず、そのまま合算する | 指定なしのため推奨既定案 |
| A7 | JST は固定オフセット UTC+9 として扱う | JST に夏時間はない。`tzdata` に依存しない |
| A8 | 想定外のデータは `ValueError` にする | 指定なしのため推奨既定案 |
| A9 | 集計するのは `completed` のみ。負の金額は差し引く | 指定なしのため推奨既定案 |
| A10 | 税抜換算は注文ごとに行う。内税額（税込 × 10/110）を 1 円未満切り捨てし、税込から引く。負の金額は絶対値に同じ規則を適用する。整数演算のみ | Q3 で丸め方法が未指定だったため |

## 人間の確認が必要な点
1. **A10 の丸め方法**: 注文ごとか月の合計ごとか、切り捨て・四捨五入・切り上げのどれにするか。
2. **A3' の月の範囲**: cancelled の注文しかない月を範囲に含めてよいか。決算期などの固定期間で範囲を決める必要はないか。
