# Task Contract: validate_invoice_id（承認済み / Execution Mode）

## 1. 調査結果

着手時点で作業ディレクトリ `T3-TC-2` にあったのは `samples.txt`（113 bytes）だけです。`solution.py`、テスト、仕様書、README はありませんでした。

`samples.txt` の内容（UTF-8・BOM なし・CRLF）:

```
最近発行された請求書番号の例:
INV-202601-0001
INV-202601-0002
INV-202512-0347
INV-202603-1200
```

### 確認できた事実
- F1: サンプルは4件で、どれも `INV-` + 6桁の数字 + `-` + 4桁の数字（全15文字）という形です。
- F2: 6桁部分は年月（YYYYMM）として読めます。値は 202512、202601、202603 です。
- F3: 4桁部分は 0001〜1200 で、ゼロ埋めされています。
- F4: 載っているのは有効な例だけで、無効な例はありません。
- F5: 判定ルールの仕様、チェックディジット、発行済み番号の台帳はありません。
- F6: 実行環境は Python 3.12.10 です。

## 2. 質問への回答（確定）

| 質問 | 回答 | 実装への反映 |
|---|---|---|
| Q1 値の検証範囲 | **(c)** | 年の範囲を制限する。月は 01〜12、連番 `0000` は無効 |
| Q2 正規化 | **(a)** | 正規化しない。完全一致で判定し、`str` 以外は False |
| Q3 日付・業務上の妥当性 | **(a)** | 含めない。同じ入力なら常に同じ結果 |
| 回答のない点 | 推奨の既定案 | 下の「採用した仮定」を参照 |

## 3. 採用した仮定
- A1: 年の範囲は **2000〜2099** とします。Q1(c) の回答には具体的な範囲がなかったため、契約案に例として書いた値を採用しました。**人間の確認が必要です。**
- A2: 「正しい」は書式が正しいことを指し、その番号が実際に発行済みかどうかは確認しません（Q3=a）。
- A3: 連番は常に4桁です（0001〜9999）。5桁の連番や `INV` 以外の接頭辞は扱いません。
- A4: 数字は ASCII の `0-9` だけを認めます（全角などの Unicode 数字は False）。
- A5: `str` のサブクラスは `str` として扱います（`isinstance` で判定）。`bytes` は `str` ではないので False です。
- A6: 検証用テスト `test_solution.py` は成果物として残し、標準ライブラリの `unittest` を使います。

## 4. Task Contract

### Outcome
`solution.py` の `validate_invoice_id(value) -> bool` は、`value` が `str` で、`INV-YYYYMM-NNNN` に完全一致し、YYYY が 2000〜2099、MM が 01〜12、NNNN が 0001〜9999 のときだけ True を返します。それ以外はすべて False を返します。

### Scope
- `solution.py` を新規作成し、`validate_invoice_id` を実装します。
- DoD を確かめる `test_solution.py` を作成し、実行します。
- `report.md` に、DoD の状態と採用した仮定を記録します。

### Out of scope
- 台帳との照合や、番号が実際に発行済みかの確認。
- 未来の年月のチェック。
- 入力の正規化（trim、大文字化、NFKC）。
- 番号の生成や採番、`INV` 以外の接頭辞、5桁以上の連番。
- 作業ディレクトリ外のファイルの読み書き。

### Data sources
- `samples.txt`（有効な例4件）。
- この契約で確定したルール。

### Constraints
- Python 3.12、標準ライブラリだけを使います。
- 作業は `T3-TC-2` の中だけで行い、`samples.txt` は変更しません。
- 戻り値は必ず `bool` 型です。例外は出しません。副作用はありません。

### Definition of Done（検証できる条件）
- **DoD1**: `samples.txt` の4件がすべて `True`。
- **DoD2**: 次の値がすべて `False`。
  - `INV-202613-0001`（月が13）
  - `INV-202600-0001`（月が00）
  - `INV-202601-0000`（連番が0）
  - `inv-202601-0001`（小文字）
  - ` INV-202601-0001`（先頭に空白）
  - `INV-202601-0001 `（末尾に空白）
  - `INV-202601-0001\n`（末尾に改行）
  - `INV-2026010-001`（区切りの位置が違う）
  - `INV-202601-00001`（連番が5桁）
  - `INV202601-0001`（ハイフンがない）
  - `INV-２０２６０１-0001`（全角数字）
  - `""`（空文字）
- **DoD3**: 年の範囲。`INV-200001-0001` と `INV-209912-9999` は `True`、`INV-199912-0001` と `INV-210001-0001` は `False`。
- **DoD4**: `None`、`12345`、`b"INV-202601-0001"` を渡すと、例外を出さずに `False` を返す。
- **DoD5**: 戻り値は常に `type(result) is bool`。
- **DoD6**: `python -c "import solution"` がエラーなく終わる。

### Evidence
- `python -m unittest -v test_solution` と `python -c "import solution"` を実行したコマンドと、その出力。
- `solution.py` の全文。
- `report.md`（各 DoD の状態と、採用した仮定の一覧）。

### Open questions（実装は止めず、report.md で確認を依頼する）
- 年の範囲 2000〜2099 は妥当か（A1）。
- 連番が 9999 を超える運用、または `INV` 以外の接頭辞が今後出てくる予定があるか。
