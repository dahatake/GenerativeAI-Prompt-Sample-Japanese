# monthly_sales 実装レポート

## 実装内容
- `solution.py` の `monthly_sales(path, tz=JST, include_statuses=("completed",))` が `{"YYYY-MM": int}` を返す（キーは昇順）。
- `csv.DictReader` で読み込み、`ordered_at` の時刻（UTC の `Z` 表記）をタイムゾーン変換して月を決め、`amount_incl_tax` を合計する。

## 前提にしたこと（仕様が不明だった点）
1. **月の判定は JST（UTC+9）**: 日本の業務を想定。UTC で判定すると月をまたぐ行があり、結果が変わる（A-1004 は 1月→2月、A-1010 は 4月→5月）。UTC で集計したい場合は `tz=timezone.utc` を渡す。
2. **`status == "completed"` の行だけ集計**: `cancelled` は売上に含めない。それ以外の未知のステータスも含めない。
3. **金額は税込（`amount_incl_tax`）をそのまま使用**: 税抜への換算はしない。
4. **負の金額（A-1006: -1100）は返金・値引きとみなして差し引く**。
5. **売上がない月（例: 2026-03）はキーに含めない**（0 で埋めない）。

## 結果（sales.csv）
- 既定（JST）: `{"2026-01": 16500, "2026-02": 11000, "2026-04": 18700, "2026-05": 7700}`
- UTC の場合: `{"2026-01": 19800, "2026-02": 7700, "2026-04": 26400}`

## 確認したい点
- 月の判定は JST と UTC のどちらにするか。税込と税抜のどちらで集計するか。売上がない月を 0 として含めるか。
