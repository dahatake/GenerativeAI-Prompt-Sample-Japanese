## 1. 調査結果

### 確認できた事実
- 作業ディレクトリにあるのは `members.json`（7 件）だけ。`solution.py`、テスト、README、Python のバージョン指定、依存関係ファイルはない。
- 各レコードのキーは `id`(int) / `name`(str) / `email`(str|null) / `updated_at`(ISO 8601、+09:00)。
- `id` は 1〜7 で全件異なる。そのため、完全一致の重複は 0 件。
- 同一人物と思われる組:
  - id 1 と 3: `name` が同じ「山田 太郎」。`email` は大文字小文字と先頭の空白だけが違う（`" Taro.Yamada@..."`）。新しいのは id 3（2026-03-15）。
  - id 2 と 6: `name` が同じ「佐藤 花子」。`email` は大文字小文字だけが違う。新しいのは id 2（2026-02-01）。どちらの組も、新しいほうがリストの先頭にあるとは限らない。
- `email` が空文字のレコード（id 4）と `null` のレコード（id 5）がある。
- `updated_at` のタイムゾーンはすべて +09:00。

### 仮定（質問で覆らなければ採用）
- A1: 入力は `list[dict]`。関数は入力を変更しない（mutate しない）。外部ライブラリは使わず、Python 3 の標準ライブラリだけを使う。
- A2: 残すレコードの値は元のまま返す。`email` の正規化は比較のためだけに行う。
- A3: 出力の順序は、各グループが入力で最初に現れた位置の順にする（安定）。
- A4: `dedupe` はファイル入出力をしない。JSON の読み込みは呼び出し側が行う。
- A5: 期待値（Q1〜Q3 が (a) の場合）: id 1 と 3 からは 3 を残し、id 2 と 6 からは 2 を残す。出力は 5 件で、順序は [3, 2, 4, 5, 7]。
- A6（実行時に追加）: 空白だけの email（例: `"  "`）は正規化すると空になるので、`email` キーがないレコードとともに、空文字と同じく判定対象外として残す。
- A7（実行時に追加）: `updated_at` は `datetime.fromisoformat` で解釈し、時刻として比較する（タイムゾーンが違っても正しく比べる）。値がない、または解釈できない場合は例外を送出する。
- A8（実行時に追加）: 戻り値の各 dict は入力の浅いコピー。値は元のまま。

## 2. 質問（最大 3 問）

**Q1. 重複キーは何にしますか？**
- (a) 正規化した email（前後の空白を除いて小文字化）【推奨・既定】
- (b) name（同姓同名の別人もまとめてしまう危険がある）
- (c) 正規化した email と name の両方が一致するもの
- (d) dict 全体の完全一致（このデータでは 1 件も除かれない）

**Q2. 重複のうち、どれを残しますか？**
- (a) `updated_at` が最も新しいレコード。同時刻なら入力で先に出たもの【推奨・既定】
- (b) 入力で最初に出現したもの
- (c) 項目単位でマージする（新しい非空の値を優先する。仕様が膨らむ）

**Q3. email が空文字または null のレコードはどう扱いますか？**
- (a) 重複判定の対象外にして、すべてそのまま残す【推奨・既定】
- (b) name を代わりのキーにして判定する
- (c) 出力から除外する
