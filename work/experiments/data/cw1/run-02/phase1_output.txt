Q1. 月の区切りに使うタイムゾーン

A. 日本時間(UTC+9)で区切る ← 推奨。A-1004 は 2026-02、A-1010 は 2026-05 に入ります。
B. UTC のまま区切る。A-1004 は 2026-01、A-1010 は 2026-04 に入ります。
理由: 2件の計上月が変わり、2026-05 という月ができるかどうかも決まります。

Q2. 集計する金額

A. 税込額をそのまま足す ← 推奨。列の値を変えずに使えます。
B. 税抜額を足す。1行ごとに 
11
(10%で割り戻し、端数は切り捨て)を計算してから合計します。
C. 税抜額を足す。月の税込合計を出してから 
11
 で割り戻します。
理由: 合計額が全体で約9%変わります。B と C は端数が出たときに結果が変わることがあります。

Q3. マイナス金額の行(A-1006 の -1100)の扱い

A. completed ならマイナスもそのまま足し、注文日時の月から差し引く ← 推奨。2026-02 は税込・日本時間で 11000 になります。
B. マイナスの行は除く。同じ条件で 2026-02 は 12100 になります。
C. マイナスの行が見つかったらエラーを出して止める。
理由: 純売上と総売上のどちらを出すかが変わり、月の金額も変わります。
4. Task Contract 案

Outcome

Python 関数 monthly_sales(path: str) -> dict[str, int] を作ります。sales.csv を読み、{"YYYY-MM": 金額(int)} を返します。

Scope

CSV の読み込み、行の絞り込み、Q1 で決めたタイムゾーンでの月の決定、Q2・Q3 に従った金額の合計を行います。

返金を元の注文の月に付け替えること
ファイルへの出力、グラフ、コマンドとして実行する機能
標準ライブラリ以外を使うこと

Python 3.9 以上で、標準ライブラリ(csv、datetime、zoneinfo)だけを使います。
