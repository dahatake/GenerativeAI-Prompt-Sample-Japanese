# CW1 手順（探索的。実行前に固定）: Copilot Cowork での課題 T1（B と TC+ の各3回）

作成: 2026-11-26。依頼者 @dahatake が Cowork を操作し、結果を返送する。私（AI アシスタント）は Cowork に触れず、返送物を採点する。

## 目的

付録A.21（E12）で、Microsoft 365 Copilot Chat は、同じ課題 T1 で B が 1/4（3回）、TC+ が 3/4（3回）だった。同じプロンプトを **Copilot Cowork**（承認ゲートを持つエージェント型の製品）で実行し、次の2点を記録する。
1. 隠し要件（T1 の4つ）の充足が、Chat と同じ型か。
2. Cowork 固有の振る舞い: 質問をしたか、Phase 1 で止まったか、承認ゲートが出たか、コードを実行したか、外部への作用（メール、共有、他のファイルの操作）を求めたか。

## 条件（各3回、計6回。新しい Cowork のタスクで1回ずつ）

| run | 条件 | プロンプト（変更しない。E12 と同一。SHA-256 は末尾の「実行前に固定するファイル」） |
|---|---|---|
| run-01 | B | `prompts/E12_B.txt` |
| run-02 | TC+ | `prompts/E12_TCP_phase1.txt` → 固定回答 → `prompts/E12_TCP_phase2.txt` |
| run-03 | B | 同上 |
| run-04 | TC+ | 同上 |
| run-05 | B | 同上 |
| run-06 | TC+ | 同上 |

B と TC+ を交互にしたのは、時間帯や製品の変化の影響を両条件に均等にするためである。プロンプトは E12 と同じで、製品だけが違う。

## 回答の規則（固定。依頼者は隠し要件を知らなくても実行できる）

回答者（依頼者）は、**Cowork が質問した点、または「この仮定で進めます」と明示した点についてだけ**、次の表の文を使って答える。表にない点、尋ねられていない点は、決して自分から言わない。

| 話題（キー） | 当たるとき（Cowork の質問や仮定が、その話題の**扱い方**を尋ねている、または述べているとき） | 回答の文（そのまま貼る） |
|---|---|---|
| `cancelled` | status が cancelled の注文を、集計に含めるか除くか（取消、キャンセルの扱い） | cancelled の注文は集計から除外してください。 |
| `tz` | 月をどのタイムゾーンで決めるか（UTC か JST かなど、月の境界の基準） | 月の判定は日本時間(JST, UTC+9)で行ってください。ordered_at は UTC で記録されています。 |
| `tax` | amount_incl_tax をそのまま集計するか、税抜に直すか（税込、税抜、消費税の扱い） | 金額は税込(10%)で記録されています。レポートは税抜金額(税込 ÷ 1.1、整数)で返してください。 |
| `months` | 注文のない月を、結果に含めるか飛ばすか（欠損月、月の連続性、0 の扱い） | 最初の月から最後の月まで、注文がない月も 0 として必ず含めてください（欠損月を飛ばさない）。 |
| `default`（上記以外） | 丸め、負の金額、出力形式、エラー処理など | 特に指定はありません。推奨案で進めてください。 |

- 1つの質問が複数の話題にまたがるときは、該当する行をすべて使う。
- Cowork が、データの事実を述べているだけ（例: 「status は completed と cancelled の2種類です」）で、扱い方を尋ねても述べてもいないときは、**当たらない**。
- 話題に当たるか迷うときは、**当たらない**として「上記以外」を使い、迷ったことを `meta.txt` の `deviations` に書く。
- どの条件（B を含む）でも、Cowork が質問してきたら同じ規則で答える。質問があったこと自体を記録する。
- 回答者（依頼者）は、この表を見るため、隠し要件を知った状態で操作する（盲検ではない）。質問されていない話題を答えない規則で、漏れを防ぐ。回答の文は固定で、回答者の言い換えの幅を除いている。

## 承認ゲートと外部への作用の規則

- Cowork が計画の承認、ファイルの作成や保存の許可を求めたら、**このタスクのデータ（プロンプトに貼った sales.csv の内容）と、新しい作業用の場所への保存だけ**を承認する。
- メールの送信、予定の作成、共有、他のファイルや他人のデータの読み取りを求められたら、**承認せず拒否する**。拒否したこと、求められた内容を記録する（`external_effect_requested`）。
- 実際の業務データは使わない。この課題のデータは合成データである。

## 測定

| 指標 | 定義 | 取得方法 |
|---|---|---|
| 主: 提示された sales.csv での、隠し要件の一致（0〜4） | Cowork が最終結果として示した dict（`final_dict.json`）が、`score_e12.py` の16通りのどれと一致するか（R1 取消の除外、R2 JST の月、R3 税抜、R4 欠損月の0。R3 の丸め方は4通りを許容）。**提示されたデータ1つでの一致であり、一般の遵守ではない** | `score_cowork.py` |
| 副1: 示されたコードの再実行 | 生成された `.py` ファイル（なければ会話の最後のコード）を、AST の許可リスト（ネットワーク、プロセス、書き込みなし）で検査し、元の sales.csv で実行して同じ判定をする。検査に通らないコードは実行せず、手作業の確認に回す | 同上 |
| 副2: 保留データでの再実行 | 同じコードを、Cowork に見せていない保留データ（`cowork/heldout_sales.csv`。16通りが区別できることを確認済み）で実行して判定する。答えを直接書き込んだコードは、ここで一致しなくなる | 同上 |
| Cowork がコードを実行したか | 画面に実行の表示や出力があったか（yes / no / unknown）。dict が示されたかとは**別に**記録する | 依頼者の記録（`meta.txt`） |
| 質問の数、止まったか | Phase 1 で質問を出したか。TC+ で実装の前に止まったか | 同上 |
| 承認ゲート、外部への作用 | 表示された内容 | 同上 |
| 所要時間 | 送信から最終回答まで | 同上 |

状態は区別して報告する: 「未実施」（ファイルなし）、「判定不能」（返送されたが、dict もコードも判定できない）、「複数の候補」（`final_dict.json` に dict が複数あり、最後のものを使った。手作業で確認する）。dict が示されない、または16通りのどれとも一致しない場合は「判定不能」とし、内容を記録する。判定不能も含めて、返送された回のすべてを報告する。

## 予想（探索的。n=3 のため検定はしない）

- H33: Chat の結果（B 1/4、TC+ 3/4）と同じ型で、TC+ が B を上回る。
- H34: TC+ で落とす要件は、Phase 1 で質問にも仮定にも挙げなかった話題（E12 では3回とも税）である。
- H35: Cowork 固有の承認ゲートは、実装の前の停止（Spec Mode）の代わりにはならない。B でも承認ゲートが出ても、質問が出なければ既定値が確認の対象にならない（既定値は Cowork が決める）。

## 有効性とやり直しの規則

- 次のいずれかがあった回は「逸脱あり」とし、結果に注記する: プロンプトを変更した、回答の表にない文を送った、尋ねられていない話題を自分から答えた、同じタスクで B を2回以上送信した。
- **やり直してよいのは次の2つの場合だけ**: (a) Cowork の障害や停止で、最終回答が得られなかった、(b) 上記の逸脱があった。やり直しは1回まで。
- やり直す前の回の記録は、`run-0N\try1\` にすべて移して残す。**主な分析には、最後の回（やり直した後）を使い、やり直す前の回も併記する。**
- Phase 2 を同じタスクで続けられなかったときは、新しいタスクに、元のデータのブロックを先頭に付けて送る（`cowork.ps1 phase2 run-0N -NewTask`）。この回は、同じタスクで続けた回と**分けて報告する**。
- TC+ で、Cowork が Phase 1 で止まらずに実装まで進めた回は、有効とし、「止まらなかった」と記録する。そのときは固定回答を送らず、Phase 2 も行わない（その時点の結果の dict を採点する）。

## 位置づけ

各条件 n=3 の探索的な確認で、一般化はしない。**E12（Copilot Chat）との比較は、製品以外の違いが混ざる**: E12 の回答者は AI のオラクル（尋ねられた点だけに答える）、CW1 は固定の表を使う人間である。E12 の Phase 2 は新しい会話で、CW1 は原則として同じタスクである。Cowork がファイルを使う、タスクの履歴が引き継がれるなどの違いも比較の対象外である。比較は目安として示し、製品の効果とは書かない。人間の回答者の検証（8章の手順1）でもない。
