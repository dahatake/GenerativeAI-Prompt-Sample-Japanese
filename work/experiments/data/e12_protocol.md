# E12 手順（探索的。事前登録 v4 への追補、実行前に固定）

作成: 2026-11-26

## 目的

7章の「製品間（GitHub Copilot と Microsoft 365 Copilot）の、同じ課題での比較は未実施」を、最小の形で確かめる。T1（月次売上、隠し要件4つ）を、Work IQ 経由の Microsoft 365 Copilot Chat（既定のエージェント）で、B と TC+ の各3回実行する。

## 条件

- **B**: `prompts/E12_B.txt`（依頼文、sales.csv の内容、コードの実行と前提の記述の指示）。新しい会話で1回ずつ。
- **TC+**: `prompts/E12_TCP_phase1.txt`（6.1節の Spec Mode。ファイルの探索の代わりに、貼り付けたデータを調べる）→ オラクル → `prompts/E12_TCP_phase2.txt`。
  - オラクル: v2〜v4 と同じ汎用サブエージェント（既定モデル）。Copilot の Phase 1 の出力を、そのまま `contract.md` としてサンドボックスに保存し、`ORACLE_FILE.txt` と同じ規則（質問と「この仮定で進めます」と明示された点だけに答える）で `answers.md` を書かせる。
  - Phase 2: Work IQ 経由では同じ会話の継続が失敗することがあるため（v1.3 の観察）、**新しい会話**で、Phase 1 の出力の全文とオラクルの回答の全文を貼り付けて送る（E7b と同じ「新しいセッションでの再開」）。値の聞き返しは行わない（`E12_TCP_phase2.txt` で「これ以上の確認はできません」と伝える）。

## 採点

- Copilot が示した結果の dict を、`score_e12.py` で、16通りの要件の組み合わせ（R1 取消の除外、R2 JST の月、R3 税抜、R4 欠損月の0）を sales.csv に適用した結果と照合する。16通りの結果はすべて異なる（`python score_e12.py` で確認）。R3 の丸め方は、切り捨て、四捨五入、偶数丸め、行ごとの換算のどれでも可とする。
- dict が示されない、または16通りのどれとも一致しない場合は「判定不能」とし、内容を記録する。
- 結果の dict は Copilot の自己申告である。Copilot が示したコードを手元で実行して、同じ dict になるかも確かめる（コードが示された場合）。

## 位置づけ

各条件 n=3 の探索的な確認で、仮説検定はしない。入力はファイルではなく貼り付けたデータであり、ファイルの探索、テストの実行の繰り返し、作業範囲の隔離は比較の対象外である。
