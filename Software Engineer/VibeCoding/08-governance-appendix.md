# 第 8 章 ガバナンスと付録

## 8.1 企業利用の注意点

| 領域 | 確認・対策 |
|---|---|
| 情報漏えい | 社外送信可否の分類、機密/個人情報をプロンプト・ログ・コンテキストに入れない、企業向けプラン（学習利用なし）を使用 |
| 知財・ライセンス | 生成コードの類似コード検出設定、依存ライセンスチェック、SBOM 生成 |
| セキュリティ | 最小権限、本番資格情報を Agent に渡さない、破壊的操作は承認制、プロンプトインジェクション（外部文書/Issue/Web 内容に紛れた指示）に注意 |
| MCP / ツール連携 | 許可リスト方式。接続先と権限を棚卸し。信頼できない MCP サーバを使わない |
| 監査 | PR・コミットに Agent 利用を記録（Co-authored-by 等）、変更理由を残す |
| 品質責任 | 最終責任は人間。レビューなしのマージ禁止。ブランチ保護を必須化 |
| コスト | モデル/トークン/同時実行の予算管理、利用状況の可視化 |
| 規制・内部統制 | 変更管理、職務分離（実装者≠承認者）、システム分類に応じた利用範囲 |

## 8.2 Agent 利用ポリシー例（チーム合意用）

1. 本番環境・本番データへの直接アクセスを Agent に許可しない
2. `git push` / デプロイ / リソース削除は人間が実行または明示承認する
3. 新規依存追加は理由を提示し承認を得る
4. すべての変更は PR 経由、CI 緑 + 人間のレビュー必須
5. 機密情報をプロンプトに含めない。含めてしまった場合は報告手順に従う

## 8.3 習熟度レベル

| Lv | 状態 | 目安 |
|---|---|---|
| 1 | 単発で依頼し、動かして直せる | 第 1〜2 章 |
| 2 | Spec/Plan 先行で、テストと共に進められる | 第 3〜4 章 |
| 3 | クラウドまで通しで再現可能に構築できる | 第 5 章 |
| 4 | 既存システムへ安全に機能追加を反復できる | 第 6 章 |
| 5 | 複数 Agent を設計・統制し、チームに展開できる | 第 7〜8 章 |

## 8.4 付録 A: プロンプト集

**仕様の曖昧さ洗い出し**
```text
この Spec を読み、実装前に確認すべき曖昧点・矛盾・抜け(エラー系、境界値、権限、性能)を質問形式で列挙して。
```

**Plan 作成**
```text
実装計画のみ出力(コード不可): 変更ファイル、手順(小さなコミット単位)、テスト方針、リスク、質問。
```

**テスト先行**
```text
受け入れ基準をテストに変換し、失敗を確認してから実装して。テストを仕様に反して変更しないこと。
```

**コード理解**
```text
このリポジトリの全体構造・データフロー・主要な設計判断を、新メンバー向けに説明して。根拠のファイルパスを添えて。
```

**リファクタ**
```text
挙動を変えずに <対象> を整理して。先に既存テストで挙動を固定し、リファクタ後に同じテストが通ることを示して。
```

**デバッグ**
```text
症状・再現手順・ログは以下。仮説を可能性順に挙げ、各仮説の検証方法を提示して。確認後に修正する。
```

**ドキュメント**
```text
現在のコードに基づき README と docs を更新して。コードにない内容は書かないこと。
```

**セッション引き継ぎ（コンテキストが長くなったとき）**
```text
ここまでの決定事項・変更点・未完了作業・次の一手を 20 行以内で要約して。新セッションの冒頭に貼る。
```

## 8.5 付録 B: トラブルシュート

| 症状 | 原因 | 対処 |
|---|---|---|
| 同じ誤りを繰り返す | 文脈不足/会話が長い | AGENTS.md に追記し新セッションで再開 |
| 勝手に大量変更する | 依頼が大きい/制約が無い | 対象ファイルを限定、Plan 承認制 |
| 存在しない API を使う | 幻覚 | 公式ドキュメント参照を指示、型/実行で検証 |
| 「完了」と言うが動かない | 検証未実施 | 実行コマンドと出力の提示を必須化 |
| 差分が大きすぎてレビュー不能 | 1 依頼の粒度 | 分割。コミット単位を細かく |

## 8.6 付録 C: 総合チェックリスト

- [ ] AGENTS.md / Spec / openapi / ADR が最新
- [ ] すべての変更が PR・CI 経由
- [ ] 秘密情報なし、依存・脆弱性スキャン実施
- [ ] 本番資格情報を Agent に渡していない
- [ ] 検証用クラウド資源を削除済み（コスト）
- [ ] 振り返りを記録し、AGENTS.md に反映した

## 8.7 次のステップ（発展）

- Agent を CI に組み込む（PR 自動レビュー、失敗ログからの修正提案）
- MCP でチーム固有のツール（社内 API、チケット、ナレッジ）を Agent に接続
- カスタムエージェント/スキル（再利用可能な手順書）の整備
- 評価の自動化（Agent の成果物品質を測るテスト/ベンチ）と継続的改善
