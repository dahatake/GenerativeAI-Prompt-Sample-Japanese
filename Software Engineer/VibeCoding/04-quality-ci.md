# 第 4 章 品質ゲート（テスト・レビュー・CI・セキュリティ）

**ゴール**: 「Agent が書いたコード」を信頼できる状態に保つ仕組み（自動検証 + 人間レビュー）を作る。

## 4.1 講義: Vibe Coding の品質リスク

| リスク | 例 | 対策 |
|---|---|---|
| 幻覚 | 存在しない API/パッケージを使う | 実行・型チェック、依存追加の承認制 |
| 見せかけのテスト | アサーションが空、実装をコピーしたテスト | ミューテーション/レビュー、仕様由来のテスト |
| セキュリティ | 入力検証漏れ、秘密情報の混入 | SAST、シークレットスキャン、依存脆弱性スキャン |
| 保守性 | 重複、巨大関数 | lint ルール、複雑度制限、レビュー |
| ライセンス | 由来不明コード | 依存ライセンスチェック、社内ポリシー |

## 4.2 ハンズオン A: テスト強化（50 分）

```text
@docs/spec/S-001..S-003 の受け入れ基準と現在のテストを突き合わせ、カバーされていない基準の一覧を出して。
その後、不足テストを追加。実装コードは変更しないこと。テストが失敗した場合は、
実装を直さず、失敗内容と原因の仮説を報告して。
```

**意図的な破壊テスト**: 実装を 1 行壊し（例: 404 → 200）、テストが落ちるか確認。落ちなければ「見せかけのテスト」。

```text
テストの品質を検証したい。実装に小さなバグを 5 種類(境界値, 条件反転, 例外握りつぶし等)を
1 つずつ仕込み、テストが検出できるか確認し、検出できなかったものにテストを追加。仕込みは最後に元へ戻すこと。
```

## 4.3 ハンズオン B: CI（GitHub Actions）（40 分）

```text
.github/workflows/ci.yml を作成: push/PR で、Node LTS、npm ci、lint、typecheck、test、build を実行。
PostgreSQL は service container を使う。依存キャッシュを有効化。権限は contents: read の最小に。
```

追加（任意）:
- 依存関係レビュー（Dependabot / dependency-review）
- シークレットスキャン（GitHub Secret Protection 等）
- コードスキャン（CodeQL）

ブランチ保護: `main` への直接 push 禁止、CI 成功と 1 名以上のレビューを必須にする。

## 4.4 ハンズオン C: Agent にレビューさせ、人間が判断（40 分）

```text
git diff main...HEAD をレビューして。観点: (1)仕様逸脱 (2)セキュリティ(入力検証, 認可, 秘密情報)
(3)エラー処理 (4)テスト不足 (5)不要な変更。重大度順に、ファイル:行 と修正案を提示。
修正はまだしないで。
```

- 指摘を**鵜呑みにせず**、妥当/不要を仕分けして採否を記録
- 別の Agent/モデルでレビューさせ、指摘の差を比べる（クロスレビュー）

## 4.5 ハンズオン D: セキュリティ基礎（30 分）

```text
OWASP Top 10 の観点で API を点検し、実在する問題のみ指摘して(推測は「要確認」と明記)。
特に: 入力検証、エラーメッセージの情報漏えい、CORS、レート制限、ヘッダ(helmet 相当)、依存脆弱性。
```

## 4.6 Definition of Done（チームで合意し AGENTS.md に反映）

- lint / typecheck / test / build がローカルと CI で緑
- 仕様の受け入れ基準 ⇔ テストの対応が取れている
- openapi.yaml 更新済み、新規依存は理由付きで承認済み
- シークレット無し、脆弱性スキャン重大指摘なし
- 変更の要約と動作確認結果が PR に記載

## 4.7 完了チェック

- [ ] 破壊テストで全バグを検出できた
- [ ] CI が PR で動き、ブランチ保護が有効
- [ ] Agent レビュー結果の採否を記録した
- [ ] DoD を AGENTS.md に追記した

## 動作確認で判明した注意点(実機検証済み)

- `ci.yml` の各ステップ(`npm ci` → lint → typecheck → test → build → `npm audit`)はローカルで同じ順に実行して成功を確認した。ただし GitHub Actions 上での実行は未検証。
- ミューテーションテスト(DELETE の 404 を 204 に変える)がテストで検出されることを確認した。
- npm 11 は esbuild などで `allow-scripts` 警告を出すが無害。
