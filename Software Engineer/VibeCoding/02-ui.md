# 第 2 章 画面の追加（UI ⇄ API 連携）

**ゴール**: React UI を追加し、ブラウザからローカル API を操作できるようにする。UI と API は **OpenAPI 契約**で結ぶ。

## 2.1 講義: UI の Vibe Coding のコツ

- UI は「見た目の好み」が入りやすい。**画面仕様（ワイヤー/状態）**を言葉で書き、スクリーンショットや手書きスケッチを添付すると精度が上がる。
- **契約駆動**: Web は `docs/openapi.yaml` から型/クライアントを生成し、API の独自解釈を禁止する。
- **状態を明示**: loading / empty / error / success の 4 状態を必ず仕様に含める。

## 2.2 ハンズオン A: 画面仕様（20 分）

`docs/spec/S-002-task-ui.md`:

```markdown
# S-002 タスク画面
## 画面
- 一覧: 列(To do / Doing / Done)のボード表示。カードに title と更新日
- 追加: 上部フォーム(title 必須, description 任意)
- 編集: カードクリックでダイアログ。status 変更、削除
## 受け入れ基準
- 初回表示で GET /tasks の結果が列ごとに表示される
- 追加後、再読込なしで一覧に反映される
- API エラー時はトースト表示し、画面は壊れない
- 0 件のとき「タスクがありません」を表示
- キーボードだけで追加・編集できる(a11y)
## スコープ外
ドラッグ&ドロップ、認証
```

## 2.6 つまずきポイント

| 症状 | 対処 |
|---|---|
| UI が API 仕様とズレる | 生成型を使用し、型エラーで検出。ズレたら API 側が正 |
| CORS エラー | 開発は proxy、クラウドは API 側で許可 Origin を明示（`*` は禁止） |
| 巨大な 1 コンポーネント | 「300 行超のコンポーネントは分割」を AGENTS.md に追記 |

## 動作確認で判明した注意点(実機検証済み)

- 2026 年時点の Vite テンプレートは TypeScript 6 系と oxlint を同梱し、`typecheck` スクリプトがない。`openapi-typescript` は TypeScript 5 が必要なため `npm i -D typescript@^5` で固定し、`"typecheck": "tsc -b --noEmit"` などを自分で追加する。
- Vitest は Vite 8 と型が合う `vitest@^5` を使い、`vitest/config` の `defineConfig` で `test.environment: 'jsdom'` を指定する。
- `openapi-fetch`:
  - 相対 `baseUrl`(`/api`)は jsdom/Node で失敗するため `window.location.origin + '/api'` とする。
  - `createClient` 時点で `fetch` を捕捉するため、テストのモックが効かない。`fetch: (r) => globalThis.fetch(r)` を渡す。
- Testing Library は vitest の globals を使わない場合、`setup.ts` に `afterEach(cleanup)` が必要。
- `useEffect` 内で読み込みを行うパターンは lint の `react(set-state-in-effect)` 警告が出る(動作には影響なし)。
- E2E は Playwright の `channel: 'msedge'` で Edge を使うとブラウザの追加ダウンロードが不要。
