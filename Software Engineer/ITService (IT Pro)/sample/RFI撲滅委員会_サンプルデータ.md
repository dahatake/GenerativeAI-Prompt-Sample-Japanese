# 共通シナリオ
- 顧客企業: 東北ライフスタイルモール株式会社
- プロジェクト名: 商品探索チャット基盤 `MallConcierge`
- 目的: ECサイトと LINE で、膨大な商品情報から利用者の意図に合う商品候補と要約を返す
- 自社技術: Azure / AWS 利用経験あり、C# と Java が主力、Web開発可能
- 対象市場: 日本国内、日本語のみ
- 除外範囲: 既存EC本体の置換、既存ERP改修、大規模DWH再構築
- 重要制約:
  - 個人情報は氏名・配送先・購買履歴を含むため、最小権限と暗号化が必須
  - MVPは6か月で公開
  - 24/7運用ではなく、営業時間外はオンコール1名体制
  - 回答品質よりも初期導入速度を優先するが、説明可能性は必要

## 1. Deep Research 用: 添付なし版に入れる値
```text
# 業務背景
- ユーザーが迷わないように、約85万件の商品情報から、その時の相談内容に合う候補を提示したい
- コールセンターの有人問い合わせを初年度で15%削減したい
- MVP の最初のフェーズは外部ベンダーへ丸投げせず、社内主導で構築したい
- 開発/運用の知見を社内に残したい

# 要求定義
- チャットでユーザーの要望を整理する
- 商品マスタ、レビュー、FAQ から回答文を要約生成する
- ECサイト埋め込みチャットと LINE 公式アカウントに対応する
- 管理者向けに最低限の分析機能を持たせる
  - 利用件数
  - 応答速度
  - 不適切入力件数
  - 回答根拠の表示率
- 商品在庫は10分以内の遅延で反映されればよい

# RFI項目へ追加してほしい評価観点
- LLM 利用時の監査ログ粒度
- ナレッジ更新の運用負荷
- 日本語検索精度の根拠
- LINE 連携実績
- PoC から本番までの責任分界点
```
